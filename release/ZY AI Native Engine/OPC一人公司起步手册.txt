# OPC 一人公司起步手册
## —— 从一人公司到巨头，ZY AI Engine 全程陪跑

> 适用对象：一个人创业，没有团队、没有办公室、预算有限，但想拥有一个"像真公司一样会成长"的 AI 经营班子。
> 平台：ZY AI 企业智能引擎（AI Native Engine）— 三端架构（智能控制中心 / AI 执行引擎 / 边缘智能节点）。
> 说明：本手册按产品实际能力撰写。标注：【可用】= 已实现（对应 PRD-v2，V2.3.4）；【开发中】= 组织进化引擎分阶段落地中（PRD-v2.5）；【规划】= 产品设计在案但未开发。

---

## 第一章 一人公司经营观：你不再是一个人

传统的单人创业死于三件事：**分身乏术、决策孤单、成长没头绪**。ZY AI Engine 用三件事回应：

1. **AI 合伙人，不是工具** —— 起步期给你"一人全能 Agent"，包揽开发、内容、客服、财务，7×24 自主运营（【可用】auto-ops 自动运营模式，见 4.6 节）。
2. **按需进化，不是一步到位** —— 业务分化时 AI 建议增员、装配新技能，像真公司一样"招聘—培训—扩展"（【开发中】组织进化引擎：四阶段模型 + 阶段感知 + 增员建议，分阶段落地中；当前需在智能体中心手动建角色）。
3. **人在回路，不是黑箱** —— 涉及花钱、发邮件、对外发布的关键动作，AI 只做草稿，等您拍板（【可用】人工处理节点 + 三通道决策）。

**您的角色**：创始人（定方向、批预算、拍板）、CEO（看经营日报）、投资人（审账本）。其余交给 AI 团队。

**长期视角**：本手册不是只教您"从 0 到 1"。ZY AI Engine 陪您走的是一整条路——从一人公司起步，到小组分工、部门建制、事业部自治，再到上市治理与生态巨头。后面每一章，都会同时告诉你"现在该做什么"和"长大以后会变成什么样"。

## 第二章 起步 30 天路线图：从想法到第一笔业务

### 第 1 周：立项目（Day 1-7）
| 动作 | 操作入口 | 说明 |
| :--- | :--- | :--- |
| 注册并创建公司 | 控制中心 → 账号与组织管理 | 建立组织架构，定义您的最高权限角色 |
| 新建项目 | 控制中心 → 新建项目 | 用"小白式"引导对话描述业务构想；AI 先做网络研究，再引导您补充要求与限制（【可用】3.1） |
| 确认执行策略 | 引导流程内 | AI 生成目标拆解、关键路径、所需岗位、预算建议、里程碑 —— 可修改、可重新生成（【可用】4.2.1） |
| 选择运行模式 | 项目设置 → 运行模式 | 全自动 / 半自动 / 人工审核。第一周建议**半自动**：先看懂 AI 怎么做，再放手 |
| 设定预算 | 项目设置 → 预算 | 总预算 + AI 运行预算（token/算力额度），预算到 80% 预警、超限熔断（【可用】4.6.9） |
| 安装边缘客户端 | 下载本地软件 | 扫描本地 Word/PDF/Excel 自动清洗上传，构建专属知识库，消除 AI"幻觉"（【可用】4.3.1） |

### 第 2 周：首个交付（Day 8-14）
- **给 AI 团队下第一个任务**：任务面板 / 自动运营 → 新建任务，或用 AI 对话自然语言提需求（"帮我做一个落地页并部署上线"）。
- **看执行过程**：项目 → 任务 → 轮次，实时日志可视化浏览 AI 的每一步（【可用】4.6.7）。
- **验收别跳过**：任务达成 done_when 后由**独立验收 Agent** 对照验收（通过/返工/驳回），不是 AI 自说自话（【可用】4.2.2 三权分立）。
- **本周目标**：跑通一个"想法 → 成品 → 上线链接"的完整闭环。

### 第 3 周：让人知道（Day 15-21）
- **打开增长能力**：技能中心按需装配 —— 营销文案、邮件、SEO（【可用】4.4.2 技能库）。
- **真实获客**：营销线索搜索已是**真实网络搜索 + LLM 提炼**（metaso/serper，【可用】4.5.3），不再是模拟数据。
- **客户跟进**：线索进入销售漏斗/客户管道（线索→商机→方案→成交），归因到营销角色（【规划】4.2.4 CRM 管道）。
- **发文前注意**：对外发布默认生成草稿等您审批 —— 这是安全底线，不是麻烦。

### 第 4 周：复盘与进化（Day 22-30）
- **读经营日报**：每天 AI 自动生成昨日进展、风险预警、预算消耗、待审批节点（【可用】4.6.11）。
- **触发一次 review**：让 AI 审视全局（进度/预算/收益），重排任务集与时间片（【可用】4.6.4）。
- **进化角色**：智能体中心 → 角色进化，手动触发生成新版本（提示词/技能/配置快照），可灰度试跑、择优生效（【可用】4.4.5）。
- **看账本**：公司账本（平台真实账本）与项目账本（项目虚拟核算）双入口（【可用】4.1.3 / 4.2.4）。

## 第三章 组织进化阶梯：从一人全能到巨头生态

> 对应产品"组织进化引擎"。四阶段模型、阶段感知、增员建议、一键扩编为【开发中】，按 MVP → 增强项分阶段落地。落地前，本表给出**您应该手动做的事**；落地后，AI 会感知业务信号、主动建议并带您走完"建议 → 确认 → 上岗"。

### 阶段一 · 起步期（一人全能，0→1）  — 约 $15-30/月
- **形象**：2 人创业公司，一位"全栈合伙人"包揽一切。
- **您要做**：创建 1 个全能 Agent 角色，绑定 3-5 项核心技能（开发/内容/客服）。
- **AI 做**：自主拆解目标、编码构建、自动部署上线、知识库沉淀、账本追踪。
- **检查清单**：□ 有公网可访问的成果 □ 有专属知识库 □ 账本有真实数字

### 阶段二 · 成长期（小组分工，1→10）  — 约 $50-150/月
- **形象**：业务分化，全能手不够用了。
- **您要做**：按业务线手动增员 —— 研发 Agent（产品迭代）、营销 Agent（内容推广）、客服 Agent（客户咨询）；用 Skill 集市按需装配，用到什么学什么。
- **AI 做**：感知业务信号、给出增员建议（【开发中】自动建议机制）；执行双引擎调度，复杂编码走 loop、信息整合走 Agent。
- **检查清单**：□ 岗位职责边界清晰 □ 每个角色有负责人 □ 营销开始带来线索

### 阶段三 · 规模化期（部门建制，10→100）  — 约 $200-800/月
- **形象**：50-200 人公司的组织模式，部门内细分专业岗位。
- **您要做**：研发部门（架构师+前端+后端+测试）、营销部门（内容+SEO+广告投放）；设定优化频率、预算弹性、信任等级。
- **AI 做**：角色绩效评估（任务成功率/单位 token 附加值/返工率），预算向高绩效倾斜（【可用】4.4.5）；版本灰度 A/B 择优。
- **检查清单**：□ 各岗位有绩效数字 □ 预算科目化（token/API/算力/人工）□ 高风险操作双签复核

### 阶段四 · 成熟期（事业部自治，100+）  — 按需弹性
- **形象**：按市场/产品线划分事业部的完整 Agent 团队。
- **您要做**：建中台 Agent（知识/技术/数据跨部门共享），多预算池分配，设置红队演练与风险登记册（【规划】4.6.14）。
- **AI 做**：全局 ROI 调度、实时自适应、混沌自愈（【规划】能力扩展自动化 4.6.5）。
- **检查清单**：□ 有独立审计 □ 有结项报告 □ 组织知识活文档（《项目运营手册》）自动再生成

### 阶段五 · 上市期（治理升级，IPO 准备）  — 按需弹性
- **形象**：对标上市前准上市公司。组织不再是增长瓶颈，**资本化成为主线**——财务、合规、治理都要达到可审计、可辩护的标准。
- **您要做**：财务合规（审计级账本）、多国法规合规防火墙（GDPR / SOX / CAN-SPAM，发布前检查，【规划】增长配套）、公司治理（董事会/ESG/股权架构）、投资者关系（路演 Q&A 草稿、招股素材）。
- **AI 做**：管理转录 + 不可变审计日志沉淀为**合规证据链**（【可用】4.6.14）；法规命中自动熔断转人工复核；投资者问答草稿与招股数据自动汇总。
- **检查清单**：□ 审计级财务三表可一键导出 □ 法规合规防火墙全开 □ 治理文档/ESG 报告自动生成 □ 股权与融资记录清晰可审计

### 阶段六 · 巨头期（生态平台，500+）  — 按需弹性
- **形象**：对标平台型巨头。多事业部 + 多公司 + 开放平台，靠生态与复利扩张，而非单线增长。
- **您要做**：多项目/多公司组合管理、并购整合、开放平台（对外 AI 客户页面、开放 API，【规划】8.3）、第二曲线孵化。
- **AI 做**：跨项目资源调度与合并报表；被并购公司的知识迁移与组织整合；对外客户自助 AI 服务（公开知识库白名单问答）。
- **检查清单**：□ 多公司合并报表可用 □ 被并购组织知识成功迁移 □ 对外客户自助 AI 页面在线 □ 第二曲线项目独立运转

> **升级规则**：不要急。阶段切换的唯一依据是**运营数据**（任务积压、客户咨询量、内容需求分化），不是"想变大"。所有扩编动作默认需您一键确认，成本透明标注。

### 升级毕业标准（阶段感知引擎【开发中】落地后自动判定）

| 升入阶段 | 达标信号（数据证据） | 最小动作 |
| :--- | :--- | :--- |
| 起步 → 成长 | 首个公网成果上线 + 出现真实获客需求（首批线索/咨询） | 增员研发 + 营销 |
| 成长 → 规模化 | 线索月增速连续 2 月 >30% + 客户 50+ 或日访问 500+ | 建部门，开 A/B、多语言 |
| 规模化 → 成熟 | 多市场/多产品线并行 + 事业部 ROI 可独立核算 | 事业部制 + 中台 Agent |
| 成熟 → 上市 | 营收结构稳定 + 审计级账本就绪 + 法规防火墙全开 | 合规治理升级 |
| 上市 → 巨头 | 多公司/多项目并行 + 有生态诉求（API/客户自助） | 平台化 + 并购整合 |

## 第四章 里程碑时刻：产品会主动提醒你"该长大了"

组织进化引擎【开发中】落地后，AI 会基于运营数据感知信号并主动建议。当前阶段，请在看到这些信号时**主动**做对应动作：

| 里程碑 | 信号 | AI 建议/自动动作 | 您要确认 |
| :--- | :--- | :--- | :--- |
| 首个成果上线 | 项目有公网可访问链接 | 建议开启营销能力（【开发中】） | 是否开始推广 |
| 首笔收入 / 首个付费客户 | 项目账本收入 > 0 | 建议新增营销/客服岗（【开发中】） | 扩编与预算 |
| 客户咨询超阈值 | 周咨询量明显上升 | 建议创建客服 Agent（【开发中】） | 岗位与知识库 |
| PMF 初步验证 | 出现重复购买 / 自然流量 | 建议进入成长期，开 SEO/邮件 | 阶段升级 |
| 任务积压超阈值 | 队列长度 / 等待时间过高 | 建议扩编对应职能（【开发中】） | 增员 |
| 角色绩效不佳 | 成功率低 / 返工率高 | 建议试用期评估或重构岗位 | 汰换或培训 |
| 预算接近预警线 | 消耗达 80% | 自动降级运行 + 通知（【可用】4.6.9） | 补预算或收缩 |

## 第六章 业务闭环六步实操（对应产品工作流）

1. **输入想法** → 在新建项目引导里说人话，AI 先研究再提问，全程可反问。
2. **极简启动** → 不装复杂流程，用最简模式跑通第一个交付，拿到公网链接。
3. **随需生长** → 看到增长信号（流量/咨询/内容分化）就主动加岗位、开渠道，确认即可。
4. **人在回路** → 花钱、发邮件、对外发布默认等您批；您的注意力只在关键处消耗。
5. **数据飞轮** → 每次采纳/修改都会被记录，AI 越用越准，好案例自动沉淀。
6. **自主进化** → 定期经营报告推送到飞书；AI 动态调策略、优化预算、发现问题自愈。

## 第七章 您的权力清单：哪些必须您拍板

- **批准**：对外发布、付费调用、删除操作、预算调整（黄通道临时授权可带过期时间自动回收）。
- **决定**：项目方向定义、运行模式、终止目标、结项。
- **知会**：例行事项 AI 自主执行，只在完成后通知您。
- **红线（红通道）**：协议级禁止动作，AI 不得代行，直接拦截转人工。
- **急停（Kill-Switch）**：【规划】全局硬停 / 按动作类别停 / 吊销凭据。

## 第八章 预算与账本速查

- **两条账**：平台真实账本（AI 算力/token、云服务器、媒体生成费）+ 项目虚拟账本（第三方支出、采购、收入）。
- **三个数字**：预警线（默认 80% 通知并自动降级运行）→ 超预算（暂停循环）→ 补预算（继续）。
- **降级运行**【规划】：预警后自动切低成本模型、降任务频率、保关键路径，恢复后自动回升。
- **成本构成**：token 费（输入 1 元/M、输出 2 元/M、缓存读 0.02 元/M）+ API 费 + 算力费 + 人工介入成本。
- **长大后的账本**：上市期需要审计级账本（可一键导出财务三表、满足审计追溯）；巨头期支持多公司/多项目合并报表（【规划】8.3）。

## 第九章 关键经营指标仪表盘：每个阶段盯什么数字

结合经营驾驶舱与经营日报，每个阶段关注的核心指标不同：

| 阶段 | 核心指标 | 对应页面/机制 |
| :--- | :--- | :--- |
| 起步期 | 任务完成率、首版上线时长、预算消耗速率 | 经营驾驶舱 |
| 成长期 | 线索量、线索→商机转化率、客户咨询量、内容产出量 | 营销漏斗（【规划】）/ 经营日报 |
| 规模化期 | 客户数、单位经济学（CAC/LTV）、分部门 ROI、返工率 | 驾驶舱 + 岗位级阿米巴核算 |
| 成熟期 | 事业部 ROI、现金流、NPS、知识库增长量 | 合并报表（【规划】）+ 独立审计 |
| 上市期 | 财务三表、法规合规项、治理指标 | 审计级账本 + 合规防火墙 |
| 巨头期 | 平台指标（API 调用、客户自助服务量）、跨项目协同效率 | 多项目合并 + 开放平台（【规划】） |

> 建议每周在经营日报里扫一遍"当前阶段的核心指标"，数字异常时先查根因再决定是否扩编/收缩，而不是凭感觉。

## 第十章 红线与注意事项

1. **别当甩手掌柜**：第一周务必选"半自动"，看懂 AI 行为逻辑再放开。
2. **别忽视验收**：每个任务的 done_when 写清楚，独立验收 Agent 才能给出可靠结论。
3. **别迷信组织进化**：组织进化引擎按 MVP → 增强项分步落地——阶段感知与增员建议落地前，**增员请手动、且要有数据依据**；阶段切换只看运营数据，不凭感觉。
4. **别把密钥写进对话/代码**：API Key 加密存储，凭证走环境变量。
5. **别让 AI 替你决定方向**：AI 负责执行与建议，方向判断是创始人的责任。
6. **上市与合规不临时抱佛脚**：从成长期就养成审计留痕（管理转录/变更记录）习惯，上市期的合规证据链就是平时积累出来的。

## 第十一章 退出 · 传承 · 扩展

公司不只有"长大"一条路，也可能会出售、传承或扩展成组合：

- **并购 / 出售**：组织知识活文档（《项目运营手册》）、SOP 库、交接文档由 AI 自动生成并持续更新——这些就是买家眼中"这家公司值钱"的证据，也让新东家能快速接手（【可用/规划】4.4.5 / 4.6.11）。
- **传承 / 换帅**：项目所有权与最终控制权可一键转移（【可用】4.1.1）；岗位档案、角色经验库、知识库随项目完整移交，新人能站在前人肩膀上起步。
- **多项目组合**：一个公司可运营多个项目，项目间财务合并、战略协同、跨项目资源调度（【规划】8.3），一个创始人管理"公司组合"而非"一个项目"。
- **平台化**：对外提供公开 AI 客户页面（有限权限知识库问答）、开放 API，把"卖产品"升级为"做平台"（【规划】8.3 AI 客户页面）。
