# 使用手册 — auto-ops 日志 / 人工 / 预算 / 时限（分卷 05）

> 面向项目负责人 / 运维 / 实施。本手册覆盖已落地能力；「待接线」能力以说明形式标注，不做操作引导。

## 一、功能概述

本模块为 auto-ops 提供四项运营保障能力：

1. **日志实时可视化**：把 qianshou/Claude Code 产生的会话日志（`.jsonl`）自动绑定到任务与轮次，增量解析后经 WebSocket 实时推送到前端，支持历史回放与断线重连对账。
2. **人工处理节点**：把合规拦截、线下流转、敏感授权、失败升级统一为「人工处理节点」，按 L0-L3 自主级别、RACI 责任矩阵、绿/黄/红三通道决策流转，叠加权限租赁、SLA 升级链、双签复核、渐进信任与经验沉淀。
3. **预算控制与 token 计费熔断**：确立「总预算 + AI 运行预算」唯一口径，token 按角色归因计费，达预警线通知、超预算暂停循环。
4. **运行时限控制**：任务级时限 + 提示词级自检 + 引擎级强杀三保险，防止 AI 无感知无限运行。

核心原则：**默认无人值守全自动，限制须显式设置**；**防烧钱闭环**（增量读取不整读、预算熔断、单轮超时强杀、连续错误退出）。

## 二、日志可视化

### 2.1 工作原理

- 系统扫描 `~/.claude/projects/` 下最新的 `.jsonl` 会话文件，轮次开始时创建 `task_log_bindings` 绑定。
- 按 `tail_offset` 字节偏移增量读取，每次最多读 `MaxLinesPerRead`（默认 200）行，绝不整读大文件。
- 解析出的结构化事件按频道 `autoops:{projectId}:{roundId}` 经 WS 推送，前端按「项目 → 任务 → 轮次」浏览。

### 2.2 关键 API

```
GET /api/v1/projects/:id/autoops/logs                    # 日志绑定列表（status/tail_offset/进度；绑定详情取此处对应项）
GET /api/v1/projects/:id/autoops/logs/:round_id          # 历史日志分页（?offset=&limit=）
WS  /ws（发送 {"op":"subscribe","channel":"autoops:{pid}:{rid}"}）  # 订阅实时流
```

### 2.3 断线重连

- 客户端订阅频道后，服务端立即回推 `autoops_log_snapshot`（内存环形缓冲最近 200 条，本次已补齐）。
- 后续增量以 `autoops_log_append` 推送，前端按 `seq` 去重：`seq <= snapshot 末尾 seq` 的增量丢弃。

> 说明：订阅指令解析（`{"op":"subscribe"}`）与订阅回推（`subscribe_ack` / `autoops_log_snapshot`）的 WS handler 已接线；前端 `AutoOpsRoundsView` 已按频道订阅并消费该流。

### 2.4 容错

- `.jsonl` 被删除/轮转 → 自动标记 `rotated`，下轮重建绑定。
- 单行超 1MB → 扫描缓冲容忍，不拖死 tailer。
- 崩溃恢复 → `tail_offset` 每次读后持久化，重启后从上次偏移续读。
- 面板错误分开展示：`404`（该轮尚无日志的**正常空态**）与其它错误分别呈现，后者带 HTTP 状态码并提示「检查实例是否在线」。
- 自动刷新开启/暂停时会提示「**内容可能已过期**」。

## 三、人工处理节点

### 3.1 自主执行级别（L0-L3）

| 级别 | 行为 |
|:---|:---|
| L0 | 全自主执行，不创建节点、不通知 |
| L1 | 通知不等待：创建节点+通知，AI 继续推进 |
| L2（默认） | 一键确认：AI 暂停等待，面板一键确认后继续 |
| L3 | 强制人工审核：必须审核通过（可多人/审批流）才继续 |

### 3.2 三通道决策

| 通道 | 触发 | 处理 |
|:---|:---|:---|
| 绿（green） | 例行事项 | 按级别处理，L0 直接执行归档 |
| 黄（yellow） | 敏感写操作（发布/删除/付费/外发等）| 生成权限租赁，超权限上限需授权 |
| 红（red） | 命中红通道禁止清单 | 强制 L3 人工审核，AI 不得代行 |

### 3.3 关键 API

```
GET  /api/v1/projects/:id/autoops/human-tasks          # 集中视图（?status= 分页）
POST /api/v1/projects/:id/autoops/human-tasks          # 创建节点
GET  /api/v1/projects/:id/autoops/human-tasks/:hid     # 节点详情
POST /api/v1/projects/:id/autoops/human-tasks/:hid/complete  # 一键确认/双签确认（body approved=true；approved=false 即拒绝）
POST /api/v1/projects/:id/autoops/permission-leases     # 黄通道授权（action/duration/cost_ceiling）
GET  /api/v1/projects/:id/autoops/permission-leases     # 租赁列表
POST /api/v1/projects/:id/autoops/permission-leases/:lid/revoke  # 回收租赁
POST /api/v1/projects/:id/autoops/permission-leases/:lid/renew   # 续期租赁
```

### 3.4 双签复核（四眼原则）

- 高风险节点（合规/红通道）默认需双签，`Raci.A` 需两个独立角色。
- 首位复核人确认后节点保持 `pending` 并**通知第二位复核人**（本次已补齐）；两位不同人批准后才 `done`。
- 同一人不能双签；任一复核人拒绝即 `rejected`。

### 3.5 权限租赁

- 黄通道敏感动作申请临时授权，绑定 `action` + `expires_at` + `cost_ceiling`。
- 到期或成本超限自动回收；执行前 `CheckLease` 校验有效性。

### 3.6 SLA 升级链与超时降级

- 节点超时：若配 `DegradeOnTimeout` 则降级为 L1 通知不等待、循环继续；否则按升级链逐级升级（项目负责人 → 平台超管）。
- 升级链耗尽：节点保持挂起（不自动放行敏感动作），等待人工介入。

> 说明：升级链耗尽后「自动通知平台超管」的告警动作尚未接线。

### 3.7 渐进信任与经验沉淀

- 系统每 N 轮（默认 10）根据成功率/违规数评估信任分，映射自主级别（≥80 L0、≥50 L1、≥20 L2、<20 L3）。
- 节点处理意见沉淀到 `role_experiences`（source=human_reply），后续 AI 处理同类事项可检索参考。

## 四、预算控制与 token 计费

### 4.1 口径

- 项目预算 = 总预算（覆盖全项目支出）+ AI 运行预算（token/算力额度）。
- token 单价：input=1 元/M、output=2 元/M、cache_read=0.02 元/M；`input = input_tokens + cache_creation_input_tokens`。
- 计费按发生时单价快照落库，单价变更不追溯历史流水（已实现）。

### 4.2 预警与熔断

- 预警线统一由后端 `warn_line_pct` 驱动（默认 **80%**）：控制台「预警」标签与配色同源，与「计费明细」页口径一致（不再硬编码 90%）。
- 达到 AI 运行预算预警线 → 预算预警通知。
- 超 AI 运行预算 / 超总预算 → 暂停循环（熔断），补充预算后恢复。
- **单轮预算上限 `single_round_max_budget`（默认 100 元）已真正生效**：轮末结算超限即告警并暂停项目，补上了**金额维度**的熔断（时间维度另有单轮超时强杀）。
- 兜底/熔断暂停时：顶部状态标签**不再显示绿色「运行中」**；红色告警的下一步指向「**恢复**」（不再引导点击已禁用的「启动」）。
- 「预算运行态」的熔断 / 降级 / 终止标签补了说明与**优先级**。
- 降级策略声明支持 4 个取值，目前**只有 `model_low_cost`（换低价模型）已接线**；其余取值在触发降级时会**显式告警**（不代表已实现）。

> 说明：预警/熔断的完整决策（`PreRoundCheck`/`budget.go`）与恢复 API 已落地：`PreRoundCheck` 每轮执行前做「AI 运行预算 / 总预算」两级熔断判定（两条独立标记 + 独立首次通知），`RecoverAfterTopUp` 补充预算后复核两线并清熔断，`GateStatus` 供启动/恢复路径复核。`project.go` 的 `BudgetExceeded`/`BudgetWarned` 纯函数、`billing.go` 的 token 计费流水与角色归因亦已实现。

### 4.3 关键 API（已落地）

```
GET /api/v1/projects/:id/autoops/budget/state        # 预算状态（预算/已用/预警/熔断/降级/终止）
GET /api/v1/projects/:id/autoops/billing             # token 计费汇总（?group=role|day 等）
PUT /api/v1/projects/:id/autoops/config              # 调整预算（ai_budget/budget_total 等）→ 触发清熔断
```

## 六、常见问题（FAQ）

1. **日志页面看不到实时输出？** 确认订阅了正确频道 `autoops:{projectId}:{roundId}`；确认该轮已有 `task_log_bindings` 且 `status=active`。
2. **断线重连丢日志？** 重连后应收到 `autoops_log_snapshot` 回放，前端按 `seq` 去重对账（本次已补齐环形缓冲数据源）。
3. **历史日志翻页 has_more 一直为 true？** 本次已修复该缺陷，重新拉取即可。
4. **人工节点卡在 pending？** 检查 RACI 的 A（批准人）是否已确认；双签节点需两个不同复核人依次确认。
5. **敏感操作为什么被拦截？** 命中红通道禁止清单或属敏感写操作（发布/删除/付费/外发），需人工审核或黄通道授权。
6. **项目超预算后停了？** 属预算熔断，补充预算（`PUT /config`）后到自动运营控制台点「**恢复**」即可（`RecoverAfterTopUp` 自动复核两线并清熔断）；此时「启动」可能已被禁用，按告警指引走「恢复」。

## 七、安全提示

- 敏感写操作（对外发布、删除、付费调用、发邮件）默认转人工节点，L0/L1 需显式授权才放行。
- 双签复核、SLA 升级链、成本上限、预算熔断是防烧钱与防误操作关键路径，请勿在生产环境关闭相关阈值。
- 所有 LLM 调用统一经 `llm.Router`，token 计入项目 AI 运行预算并写入 `token_billing_records`。
