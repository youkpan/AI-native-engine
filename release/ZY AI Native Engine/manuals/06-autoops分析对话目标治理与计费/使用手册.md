# 使用手册 — auto-ops 分析 / 对话 / 目标治理 / 计费（分卷 06）

> 面向项目负责人 / 财务 / 运维 / 审计。本手册覆盖已落地能力；「待接线」能力（LLM 生成、建议自动应用、意图打分、保留期归档）以说明形式标注，不做操作引导。

## 一、功能概述

本分卷覆盖 auto-ops 的四大支撑能力：

1. **AI 分析与经营日报**（analyzer）：把 token 计费、项目账本、任务轮次、趋势汇总为指标，产出结构化分析报告与优化建议清单；经营日报按日汇总。
2. **AI 对话管理**（14 个 ToolCall 工具）：在项目对话窗口用自然语言驱动管理操作（调优先级、分析收益、触发 review、进化角色、管理目标等）。
3. **目标管理与意图工程**（objective）：愿景→目标（Objective）→关键结果（KR）→任务 的目标树，配权衡权重与升级阈值。
4. **治理与审计**（audit）：管理转录留痕 + 内审四检查 + 风险登记册 + 红队演练 + 变更记录。
5. **token 计费**（billing）：解析 `.jsonl` 用量计价，按角色归因，双通道入账（平台真实账本 + 项目 AI 预算熔断）。

> **当前实现边界**：以上能力的「纯函数 + 规则模板 + 落库」已落地；LLM 生成链路（router 接线）与若干增强项尚在推进中，相关 API/ToolCall 以当前代码为准。

## 二、计费口径与单价（重点）

### 2.1 单价表（可配置，默认值）

| 类型 | 单价 | 说明 |
|:---|:---|:---|
| 普通输入 | 1 元/M token | **含 cache_creation**，归入输入类 |
| 输出 | 2 元/M token | — |
| 缓存读（KV） | 0.02 元/M token | cache_read 缓存命中读 |

### 2.2 计价公式与累加口径

- 费用 = `input/1e6 × 输入单价 + output/1e6 × 输出单价 + cache_read/1e6 × 缓存读单价`。
- `input = input_tokens + cache_creation_input_tokens`（普通输入含缓存创建）。
- 示例：input=1M、output=0.5M、cache_read=10M → `1×1 + 0.5×2 + 10×0.02 = 2.2 元`。
- 单价变更对历史流水**不追溯重算**，以发生时单价快照（`unit_price_snapshot`）为准。

### 2.3 角色归因（岗位级核算）

计费流水带 `role_id`，可按角色聚合成本，支撑阿米巴核算与绩效评估；查不到角色时置空，岗位核算归「未归因」桶。

- 阿米巴表展示**岗位中文名**（原为英文 `role_id`）。
- 计费明细页补了「**按任务**」与**阿米巴岗位级核算**的直达入口。
- 计费页卡片标题区分三套「预算」口径（项目总预算 / AI 预算已用 / AI 运行预算消耗）并附说明。
- 兜底计费与「未计量」口径由 tooltip 改为**常显小字**，并给出精确账单入口（运行轮次 / 阿米巴核算 / 项目账本）。

## 三、分析报告与经营日报

- **触发分析**：`POST /api/v1/projects/:id/autoops/analyze`（body `{type:"analysis"|"daily", window_days?}`）。
- **获取报告**：`GET /api/v1/projects/:id/autoops/report`（缺省取最近一份）。
- **报告内容**：花费 / 收益 / ROI / 成本率 / 完成率 / 平均轮次 / 平均耗时 / 趋势 等指标，JSON 结构可前端渲染。
- **优化建议**：规则模板生成（prompt/schedule/setting/role_version/budget 类），当前为生成后落库待人工确认；**自动应用（ApplySuggestion）尚未接线**，建议应用需人工在配置页操作。

> 待接线：经营日报推送飞书/邮件、报告正文 LLM 生成（当前为规则生成）、建议一键应用。

## 四、AI 对话管理（14 个工具）

在项目对话窗口可直接用自然语言驱动，LLM 自动按需调用下列工具：

| # | 工具名 | 用途 |
|:---|:---|:---|
| T1 | autoops_update_project | 更新运行模式/自动运营开关/预算/并行/自主级别等 |
| T2 | autoops_start_stop_project | 启动/暂停/恢复/停止自动运营循环 |
| T3 | autoops_add_task | 添加任务（AI 评估优先级/权重/引擎） |
| T4 | autoops_update_task | 更新优先级/权重/引擎/状态/提示词覆盖 |
| T5 | autoops_list_tasks | 列任务清单（含状态/优先级/进度摘要） |
| T6 | autoops_trigger_review | 触发 review 轮 |
| T7 | autoops_analyze | 触发分析报告 |
| T8 | autoops_get_report | 获取分析/经营日报报告 |
| T9 | autoops_optimize_role | 角色自我进化（生成 candidate 版本） |
| T10 | autoops_select_role_version | 切换/回退角色版本 |
| T11 | autoops_list_human_tasks | 列待处理人工节点 |
| T12 | autoops_complete_human_task | 确认/批准/驳回/升级人工节点 |
| T13 | autoops_upsert_objective | 创建/更新目标与 KR |
| T14 | autoops_list_objectives | 列目标树与 KR 达成情况 |

**人在回路**：写操作（删除/预算/终止/对外发布）属重大变更，默认需人工确认；工具层删除任务会写 `change_logs` 留痕。工具参数解析失败返回 `[参数错误]` 前缀，不 panic。

**审批状态校验**：对**非目标状态**的任务执行审批 / 驳回会返回明确错误与原因（不再「点了没反应」）。

> 待接线：T1 的终止目标/预算科目/红通道/分级急停参数、T4 的注入新信息参数（跨模块）。

## 五、目标管理与意图工程

- **目标树**：Objective（目标）→ KR（关键结果）→ 任务。
- **权衡权重**：cost/quality/risk/speed 四项归一化为和 = 1（未提供时等权 0.25）。
- **升级阈值**：KR 加权达成率低于阈值时触发 review / 人工确认。
- **KR 达成率**：`加权达成率 = Σ(KR.weight × min(current/target, 1))`。

> 待接线：AI 自动拆解任务、意图打分排序（ScoreAndRankTasks）、review 注入 KR 达成（InjectKRStatus 已实现但未接线）、任务完成回填 KR 进度。注意：目标模型升级阈值默认值为 0.8，与设计「默认关闭（0）」存在差异，需主对话收口。

## 六、治理与审计

- **管理转录**：round/task 记录 AI 决策意图摘要（`reason` 字段），只增不改，形成可追溯审计链。
- **内审四检查**：权限漂移 / token 异常（单日激增超均值 N 倍）/ 越权调用 / 角色经验退化。
- **风险登记册**：概率/影响/缓释措施/责任人/状态。
- **红队演练**：AI 扮演攻击者，构造越权/注入/提示词劫持/预算耗尽用例。
- **变更记录**：change_logs 记录 who/what/when/why + 回滚点。

> 待接线：内审 Agent LLM、保留期归档（JSONL + SHA-256）、审计报告自动上报平台超管。

## 七、token 计费流水与对账

- 数据来源：qianshou/Claude Code 会话日志（`.jsonl`）usage 统计；agent 引擎可回退 `AgentRun`/`LLMCallLog`。
- 落库 `token_billing_records`（追加写、不可变），按「任务 + 轮次」粒度。
- 双通道：**平台真实账本（HMAC 上报已接通，AI 算力费会真实入平台账本）** + 项目 AI 预算（轮前熔断）。

**平台上报口径（本批接通）**：

- 按批上报，默认**每 5 分钟一批**；**上报成功才记账**，失败按指数退避重试、不丢单。
- 平台按 `report_id` **幂等去重**，重复上报不会重复扣费；余额不足返回 2008，项目侧保留本地流水，充值后换新 `report_id` 重报。
- **上报地址未配置时不启用上报**（此时平台账本不含 AI 算力费，平台账本页已加说明）。
- 上报水位落库于 `token_billing_records.platform_reported_at`，**进程重启不会重扫历史**。

> 待接线：区间/角色汇总接口（SummaryByRange/SummaryByRole 命名）、预算累计接口（DailyAccumulated/BudgetUsage）、`[Task finished]` 后截断的 billing 侧消费逻辑（ConsumeRound）。

## 八、常见问题（FAQ）

1. **报告里 token 费用和计费流水对不上？** 两者同源 `token_billing_records`；报告按 `billed_at` 窗口聚合，注意时间窗口差异。
2. **输入 token 怎么算？** `input = input_tokens + cache_creation_input_tokens`，缓存读单独 0.02 元/M token 计价。
3. **单价改了，历史流水会变吗？** 不会，历史以 `unit_price_snapshot` 快照定格。
4. **为什么报告正文看起来像模板？** LLM 生成链路尚未接线，当前为规则模板生成，指标数字仍来自真实聚合 SQL。
5. **目标升级阈值为什么是 0.8？** 属模型默认值与设计「默认 0」的差异，已记录待收口，不影响既有项目（需人工触发 review 接线后生效）。
6. **平台账本里为什么没有 AI 算力费？** 检查项目侧是否已配置上报地址：**未配置时上报不启用**，平台账本就不含 AI 算力费（平台账本页对此有说明）。

## 九、安全提示

- 所有 LLM 调用统一经 `llm.Router` 发出；调用 Agent 使用 opus 模型，token 计入项目 AI 运行预算。
- 计费流水只增不改（无软删除），保证核算不可篡改。
- 写操作工具遵循人在回路；重大变更写 change_logs 留痕，请勿在生产环境关闭相关阈值配置。
