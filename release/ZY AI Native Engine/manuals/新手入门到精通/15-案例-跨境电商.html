第15章 案例：跨境电商独立站

一个人、在国内、做面向欧美市场的家居小件独立站，预算有限、没有团队。从第 0 天到第 90 天，每一步「在哪个页面点什么」，照着走一遍。

阅读约 55 分钟 可照着操作 重点：每一步点哪里 附 5 个附录

前面 14 章，你学的都是「零件」：怎么建公司、怎么建项目、怎么设预算、怎么建智能体、怎么派任务、怎么开发软件功能。这一章把它们拼成一辆能开的车。我们会跟着一个具体的人，走完一段具体的路：从注册账号，到独立站上线，到第一个月复盘，到第一次扩编。

这一章的目标不是「讲清楚某个功能」，而是让你知道在什么时间、去哪个页面、按哪个按钮。所以它写得很啰嗦——每个动作都写了路径和按钮原文。你可以把它当成一份作战手册，第一次做的时候摊在旁边，做一步划一步。

先说清一件事：这一章不承诺结果

本章出现的所有金额、天数、数量、转化率，都是示例设定，用来把「操作顺序」和「判断逻辑」讲清楚。它们不是效果承诺，也不是业绩预测。真实的钱请以「计费明细」「公司账本」「项目账本」里显示的数字为准。能不能卖出去、卖多少，取决于你的产品、价格、市场和你自己的判断，AI 不替你做这个保证。

你将学会

  • 一个人做跨境电商独立站，从第 0 天到第 90 天的完整操作路线（每步都带页面路径和按钮）
  • 项目描述、项目目标、预算、运行模式这些字段，在一个真实案例里具体怎么写
  • 怎么用软件工程向导把「我要一个独立站」变成能跑的任务
  • 产品文案、SEO 内容、邮件营销这些日常活儿，怎么写成一张张可以直接照抄的任务卡
  • 第一个月该看哪些数字、三个典型问题怎么处置、什么时候该扩编（以及什么时候不该）

因为它把三端能力都用上了：公司/项目/预算在平台侧，AI 循环、知识库、任务、账本在项目服务器侧，本地资料扫描上传走边缘客户端。而且它天然需要「对外动作要审批」——发邮件、发布内容、上架商品，全都碰得到人在回路机制。你把这个案例走通了，换个行业（案例 17 章）只是换套素材。

一、第 0 天：把公司开起来

第一天不碰项目，只做一件事：建一个公司。别跳过这一步——项目必须挂在公司下面，公司的行业、描述、组织架构会一路影响到后面 AI 怎么理解你的生意。

1.1 注册账号

打开网站 › 登录页 › 还没有账号？立即注册

在登录页点 还没有账号？立即注册，填四项：用户名 / 邮箱 / 密码 / 确认密码。注册完用邮箱 + 密码登录。详细规则（用户名能不能重复、密码多长）见 第 02 章。

一个实际建议

用一个你长期不会丢的邮箱注册。这个邮箱以后是通知、审批、找回账号的入口，别用一次性邮箱。另外，把密码存进你自己的密码管理器——系统里不会明文显示它。

1.3 建组织架构：一人公司也要建部门

公司管理 › 组织架构（页签）

很多新手会想：「就我一个人，建什么部门？」——建。原因有两个。

第一，组织架构是给 AI 班子用的。项目服务器里的智能体组织（管理者 Agent → 员工 Agent）会参照你公司/项目的部门结构来分配职责。你现在建的是「框」，AI 后面往里填「人」。

第二，它省掉了你以后重排的工夫。一人公司的部门怎么建？按职能建，不要按人头建：

内容与品牌

产品文案、品牌调性、社媒内容、邮件文案都归这里。

站点与工程

独立站开发、页面改动、SEO 技术项、后续的小工具。

获客与客户

SEO、内容分发、邮件营销、客户咨询应答。

三个部门就够。现在这三个部门里一个真人也没有——这是正常的，我们后面会用 AI 员工把它们填上。

1.4 邀请谁：这一阶段其实没人可邀

说句实话：第 0 天你没有需要邀请的人。「成员邀请」页签是给有团队的情况准备的（合伙人、兼职运营、外包客服）。一人公司在这个阶段要认清一件事——

你的团队 = 你一个人 + N 个 AI Agent

这不是「退而求其次」。你真正缺的不是人手，是注意力。AI 班子帮你把「执行」这部分接走，你只保留「定方向、批预算、拍板」三件事。等你哪天确实需要真人（比如要找海外仓、要谈供应商），再去「成员邀请」页签发邀请。

1.5 权限：给自己开哪些，为什么有两个建议保留人工

系统里有 14 项权限（读 / 写 / 运行任务 / 花钱 / 外发邮件 / 装插件 / 装软件 / 加 MCP / 优化提示词 / 运行命令行 / 调权重 / 暂停项目 / 暂停任务 / 用户管理），完整解释见 第 14 章。作为创始人，你对自己的账号当然是全开。真正要你花心思的，是给 AI 班子开哪些。

建议放手给 AI 的

读、写、运行任务——这是干活的底线能力，不给就没法工作。
优化提示词、调权重——让角色能自己迭代、自己分配精力，这是「越用越准」的来源。

建议保留人工的

花钱（spend_money）——涉及投广告、买数据、付第三方接口费。金额一大就该有人签字。
外发邮件（send_email）——发出去就收不回来，触达的是真实客户，必须有一道人工关。

这两项不建议直接放开，还有个机制上的理由：半自动运行模式下，系统的设计本来就是「关键决策节点（目标变更、大额支出、对外动作）由人工确认后继续」。你把这两项手工开成全自动，等于绕过了产品给你的安全阀。

第 0 天收尾检查

□ 账号能登录 □ 公司建好了 □ 三个职能部门建好了 □ 顶栏公司切换器能选到 NestKeeper。这四项齐了，第 0 天就结束，不要急着建项目——项目要花钱的地方多，想清楚了再建。

二、第 1 天：把项目立起来

第 1 天做三件事：建项目 → 录服务器 → 启动。这是整个案例里信息密度最高的一天，因为你要一口气把「生意定义」写进系统。

2.3 为什么第一周选「半自动」

「半自动」不是「AI 少干活」，而是「关键决策要你点头」。官方在「调整运行模式与预算科目」窗口里给的解释原文是：

界面原文 · 半自动 半自动：AI 自动执行，但在关键决策节点（目标变更、大额支出、对外动作等）由人工确认后继续。

对跨境电商来说，这句话里有两个词特别关键：大额支出（选品、投广告、买工具）和对外动作（发邮件、发布内容、上架商品）。你第一周还不知道 AI 的判断准不准，让它把这些直接做出去，风险太大。

还有个机制细节要记住：只有全自动和半自动会启用自动运营循环；选「手动」时，任务要靠你自己一个个触发，AI 不会自己排班。所以「半自动」是起步期唯一合理的选择。

两个名字，同一件事

创建向导里第三个选项叫「手动」，等你进了项目、到「自动运营控制台 → 调整运行模式」时它叫「人工审核」——是同一个东西（内部值都是 manual）。别以为项目里冒出了新选项。

预算的三个数字怎么联动

80% 预警（通知你并降级运行）→ 超限熔断（暂停循环，不再烧钱）→ 补充预算后恢复（在自动运营控制台点「恢复」或「启动」）。起步期的正确心态是：先把额度调小，让它早点提醒你，而不是调大让自己安心。第一次被预警不是坏事，那说明机制在工作。

2.5 确认提交，然后从「草稿」到「运行中」

第三步是纯展示的核对页，把「基本信息 / 预算设定」两块并排给你看。确认无误点 提交创建，弹出「项目创建成功」。

注意：刚建好的项目状态是「草稿」，还不能跑。要让项目真的跑起来，必须做三件事：

  1. 录入 / 开通服务器

    进项目详情页 →「服务器实例」页签。三种来源任选其一（见下）。

  2. 确认部署完成

    服务器上部署脚本跑完、服务起来之后，回到页签点 确认部署完成。

  3. 启动

    点页面头部 启动，项目进入「运行中」，这时才能去自动运营里派任务。

2.6 服务器：三种来源选哪种

每个项目对应一台独立的项目服务器——这叫「单实例单项目物理隔离」。好处是项目之间数据隔离、互不影响；代价是每个项目都要一台机器（有成本）。你不用 SSH 上去操作，界面已经把它的能力透传了。

来源一：云厂商自动开通

平台对接了云厂商，你选规格和地域，平台自动下单开机、部署、健康检查，全程能看进度。本案例选这个，规格用最小的那一档。

来源二：手动录入已有服务器

点 录入服务器，填 IP、SSH 端口、项目服务器端口（默认 8090）、规格、地域。适合你手上已经有一台机器的情况。

来源三：部署脚本

点 查看部署脚本 拿一段一键脚本，到你自己的机器上跑，脚本负责装环境、生成配置、起服务。适合懂点运维的人。

「先用最小规格」不是抠门，是纪律

起步期你根本不知道这个项目会不会跑下去，也不知道真实的负载是多少。先开最小规格，跑起来看监控指标里的资源使用率，不够再升配。反过来（先开大机器再缩）通常缩不下去，因为你的项目数据在上面。

录入后建议点一下项目列表卡片上的 连接测试，验证平台和服务器「暗号对上了」。成功文案原文是：「连接成功：{ip}:{port}，HMAC 验证通过（{ms}ms）」。出现这行绿字，第 1 天就算收工了。

三、第 2 天：先喂资料，再让 AI 干活

第 2 天不做任何「产出型」的事，只做一件事：喂资料。这是全流程里最容易被跳过、也最影响后面所有结果的一步。

资料不喂够，AI 写出来的东西就像路人

你让 AI 写产品文案，它凭什么知道你卖的是「适合租房族的折叠收纳盒」还是「适合家庭主妇的大容量收纳箱」？没有资料，它只能写出通用电商套话——那种放在任何一家店都成立、也因此对谁都不成立的文字。你后面省下的每一个「不满意、重写」的来回，都是现在喂进去的资料换来的。

3.1 建两个知识库：公司级和项目级各放什么

左侧菜单「知识库」 › 新建知识库

知识库分两层（页面标题原文就是「分层知识库（公司级 → 项目级）」）。新建时的字段有五个：名称 / 描述 / 类型（公司级 / 项目级 / 共享）/ 所属项目 / 共享下级。本案例建两个：

公司级：品牌与口径库

类型选「公司级」。放不管哪个项目都该遵守的东西：

  • 品牌调性说明（一句话：理性、克制、不夸大）
  • 公司简介与对外统一口径
  • 客服话术底线（不承诺退款、不承诺时效）
  • 英文文案的用词偏好与禁用词

「共享下级」开关打开，这样项目级检索也能借到它。

项目级：NestKeeper 资料库

类型选「项目级」，「所属项目」选 NestKeeper 家居收纳独立站。放只对这一条业务线有用的东西：

  • 12 个 SKU 的产品资料（材质、尺寸、承重、卖点）
  • 供应商报价表（Excel）
  • 竞品拆解笔记（对方定价、页面结构、卖点）
  • 目标客群画像（25–35 岁租房城市年轻人）
一个专题一个库，别建一个「大杂烩」

你以后会需要「给客户页面的问答只开放某一个库」这种操作（第七节）。如果所有资料都塞进一个库，你就没法做筛选，客户页面要么全开放要么全关闭。现在多花两分钟分库，后面省很多事。

上传完注意看文档的状态：待处理 → 解析中 → 已解析 → 分块中 → 向量化中 → 就绪。只有到了「就绪」，它才真正参与检索。没到就绪的文档旁边会有 处理 按钮，点一下催它。

还有两种状态要认识：「失败」是压根没解析出来，点「处理」重试即可；「需人工确认」是解析走了降级路径（比如文档里乱码较多、结构特殊）——内容拿到了但不够干净，系统不会直接标成「就绪」，而是等你人工看过后才让它入库，具体原因会写在文档旁边。另外上传有格式白名单：.pdf / .txt / .md / .markdown / .docx / .xlsx，pptx 不能直接传（上传区已明示），要传就先把 PPT 另存成 PDF。不在名单里的格式、或伪装/损坏的文件会被当场拒收，不会悄悄进库。

3.3 自检：用 RAG 检索搜三个问题

知识库 › RAG 检索（页签）

检索框的提示原文是 输入检索关键词，如：产品定位、目标客户、营销策略。用你后面真的要问 AI 的那些问题的关键词来搜三个：

  1. 产品定位——应该能搜到你的品牌调性说明。
  2. 收纳盒尺寸 / 承重——应该能搜到对应的 SKU 资料，结果里会显示「相似度 N%」。
  3. 竞品定价——应该能搜到竞品笔记。

如果搜出来是空态「未检索到相关内容」，或者命中的是明显无关的内容，先别往下走。回头检查：文档是否「就绪」？内容是不是图片扫描件（纯图片 PDF 解析不出文字）？知识库的「类型 / 所属项目」是不是配对？

这个自检动作，以后每周做一次

知识库是活的——你会不断往里加东西，也可能不小心删掉关键文档。花两分钟搜三个关键词，是所有「AI 回答变笨了」问题里性价比最高的排查手段。

四、第 3–4 天：把 AI 班子搭起来

资料喂完了，接下来建人。这里有个新手最常见的错误：一上来就建五个专职 Agent（文案、设计、SEO、客服、开发）。在本案例里，我们只建一个。

4.1 建一个「全能操盘手」起步

进入项目 › 左侧菜单「组织与运营」 › 智能体 › 新建 Agent

「智能体中心」有四个页签：组织 / 任务 / 配置 / 运行。在「组织」页签点 新建 Agent。填岗位信息时可以先用「岗位模板库」里的现成岗位起步，也可以自己写。

关键在系统提示词。给一个可以直接复制进去的范例（把方括号换成你的）：

岗位提示词 · 独立站全能操盘手 你是【NestKeeper 家居收纳独立站】的运营操盘手，负责人是我（创始人）。当前阶段：起步期，一个人 + 你，预算有限。 你的职责范围：产品文案、页面内容、SEO 内容、营销素材、客户问答整理。你不负责最终对外发布——所有对外动作先产出草稿。 你的边界：单笔预算超过【200 元】的动作必须先上报；不自行承诺退款、赔偿、发货时效；不自行决定选品或改价。 你的输出格式：先给一句话结论，再列具体动作与依据，最后标出「需要人工确认的下一步」。 禁止事项：不要臆测缺失的信息，缺什么就明说缺什么；不要写夸大功效的文案（如「史上最好」）；不要用你不确定的产品参数。

4.2 装配技能

建完 Agent，在成员列表里点「技能」，从技能库勾选与这个业务相关的技能。本案例起步阶段勾这几类就够：内容写作、SEO、营销文案、数据整理。技能库里有个动作叫 提升为组织级——等你把某个技能调顺了，再提升，让以后的其它项目也能用。

4.3 为什么起步期一个全能 Agent 比五个专职 Agent 好

协调开销

五个 Agent 就要有分工、有交接、有管理者协调。你现在的业务量根本喂不饱五个岗位，它们会互相等活干。

成本

每个 Agent 都有自己的提示词和上下文。岗位越多，同样的活儿要烧的 token 越多（多出来的部分都花在「沟通」上）。

上下文

一个操盘手看得到全局（产品、价格、客群、内容），写出来的东西是一致的。五个专职 Agent 各看一角，写出来的东西容易互相打架。

什么时候该加人？当你确实在某一类活上排不过来的时候。这件事我们放到第九节（第 2 个月）再谈——那时候系统会主动给你建议。

五、第 1 周：第一个交付物——把独立站做出来

前面四天都是准备，第 5 天开始动真格。第一个大动作是建站，而这在系统里的正道是「软件工程向导」，不是随便发一条任务。

为什么必须走向导

独立站是一个「软件」。它有页面结构、有交互、有部署。你直接发一条「帮我做一个网站」，AI 会从零猜你要什么，猜错就是三天白干。软件工程向导的作用，是在动手前逼你把「要做什么」讲清楚，并且产出一份你可以逐字核对的需求文档。

5.2 第 1 步 · 需求对齐：一段完整对话范例

这一步是你和 AI 的对话，输入框提示原文是 描述你的软件工程需求（目标、功能、技术栈等）...。下面是一段完整的往返（约 10 轮），你可以照着这个节奏来——关键是：说清范围，而不是说清技术。

需求对齐 · 对话范例（跨境电商独立站） 我：我要做一个面向美国市场的家居收纳小件独立站，卖厨房收纳、桌面收纳、旅行收纳三类产品，先上 12 个 SKU。 AI：收到。我先确认三件事——① 目标客户是「租房年轻人」还是「有房家庭」？② 有没有已经定好的品牌名？③ 这个站只做展示，还是要能下单付款？ 我：主要面向 25–35 岁租房的城市年轻人。品牌名叫 NestKeeper。要有加购和结账入口，支付走 Stripe。 AI：明白，结账按 Stripe Checkout 处理。还要确认——④ 物流发货方式？⑤ 有没有现成的退货政策文本？⑥ 产品图片和文案你有素材吗，还是需要 AI 生成？ 我：物流用国内直发小包，美国 7–12 天到。退货政策没有，你按常见的 30 天退货写一版，我改。图片我有 40 张白底图，文案只有供应商给的参数表。 AI：好。⑦ 站点语言只要英文，还是英文 + 西班牙文？⑧ 主机和部署你有偏好吗，还是用平台默认？ 我：先只做英文。部署用平台默认。 AI：最后一个范围确认——⑨ 要不要包含博客栏目？⑩ 我建议把「做完」的标准写死为：首页、产品列表、产品详情、关于我们、联系我们、隐私政策、退换货政策 7 个页面公网可访问，并且 12 个 SKU 都能点开详情页。你同意吗？ 我：同意，博客先不做，留给下一轮。另外产品列表页要能有分类筛选。 AI：收到，加上分类筛选。我按这个范围生成 PRD 和 TAD，你看完把关。
这段对话里最值钱的是第 ⑩ 条

AI 主动把「什么算做完」写成了一个可以核对的标准（7 个页面 + 12 个可点开的详情页）。你以后每次需求对齐，都要往这个方向收口。因为界面暂时没有单独填「验收标准」的输入框，这个标准就写进任务描述里——这是让独立验收 Agent 判得准的唯一办法。

讲完点 下一步，进入「生成 PRD/TAD」这一步。

5.3 第 2–5 步：文档生成与评审

  1. 生成 PRD/TAD

    这一步是等待，界面显示「AI 正在撰写 PRD 和 TAD，请稍候...」。不要关窗口。

  2. PRD 确认

    文档名 PRD.md，右上角可切换 预览 / 编辑。这里必须真的读一遍——尤其核对：7 个页面写全了吗？12 个 SKU 的结构对吗？Stripe 结账写进去了吗？改完点 保存并下一步。

  3. TAD 确认

    文档名 TAD.md，技术方案。你读不懂代码没关系，重点看「用了哪些技术、部署在哪、数据存哪」这三句话能不能看懂。看不懂就问 AI，别硬点下一步。

  4. 评审对话

    输入框提示 输入评审意见，与 AI 多轮讨论 PRD/TAD...。这是给你「挑刺」的机会。挑完点 应用评审。

然后是「生成模块」（显示「正在生成模块文档与开发计划...」），最后到第 7 步 · 完成：界面显示「PRD / TAD / 模块文档已生成完毕」，并给出「最终任务提示词」。点 创建任务，任务才真正进入执行队列。

5.5 任务上线后看什么

任务创建完，回到「任务管理」列表，你会看到它。这个页面有几列值得你每天扫一眼：任务名称 / 状态 / 优先级 / 时间片 / 引擎 / 类型 / 模型 / 创建时间。其中「模型」列空着时显示「路由自动」——意思是系统替你选模型。

然后去「运行轮次」页看它跑到哪了。页面标题是「运行轮次与日志」，列有轮次 / 状态 / 模式 / 引擎 / 耗时（秒）/ 花费（元）/ 开始时间。状态是这六个之一：待执行 / 运行中 / 已通过 / 需重做 / 已驳回 / 失败。

「已通过」不是 AI 自己说的

任务干完会触发独立验收 Agent（这就是「三权分立验收」：干活的、验收的、批准的不是同一个 AI）。它会给出通过 / 返工 / 驳回三种结论，并且这些结论会记在「验收记录」页里。你要养成的习惯是——看验收记录，而不是看任务状态。任务显示「已完成」但验收记录写着「返工」，说明还有问题。

5.6 第一个交付物达成：公网可访问链接

当建站任务通过验收、部署也完成后，你会拿到一个公网能打开的链接。这一刻是这整个项目的心理里程碑——因为它把「我在用 AI 做事情」变成了「我有一个真实存在的东西」。

拿到链接后，做三件小事

① 用手机打开一遍（很多人只在电脑上看，结果移动端是坏的）；② 找一个不懂你业务的朋友看一眼，问他「你知道我卖什么吗」；③ 把链接存到你的项目笔记里，这是你后面所有内容、邮件、客户页面的「落点」。

注意：这一周你的站点是能访问，不是能卖。支付链路、物流说明、政策文案都还要第二周补。这是正常的节奏，不要因为「还不能收钱」就焦虑。

六、第 2 周：产品与内容

第 2 周开始有「日常活儿」了。这一节是本章最实用的部分——我们把每一类活儿写成一张任务卡，每张卡都写清：任务名称 / 描述 / 任务类型 / 引擎 / 时间片权重 / 优先级。你可以直接照抄进「新建任务」弹窗。

任务卡 A · 产品文案（12 个 SKU）

任务名称：NestKeeper 产品详情页文案（12 SKU）

描述：基于项目知识库里的产品资料与竞品笔记，为 12 个 SKU 各写一版英文产品详情页文案。每个 SKU 需要：一句主标题（不超过 60 字符）、3 条卖点（每条不超过 12 词）、一段 80–120 词的产品描述、一个参数表（尺寸/材质/承重/清洁方式）。语气理性克制，不夸大。完成标准：12 个 SKU 全部产出，且每个 SKU 的参数与知识库原文一致，无编造参数。

任务类型：通用任务　引擎：Agent 智能体　时间片权重：3　优先级：P1 - 高

任务卡 B · 产品主图与场景图

这个不是普通任务，走媒体生成（左侧菜单「媒体生成」）。要提醒你一句：它是要花钱的，而且钱记在项目账本上。媒体生成中心的提示原文是「金额由服务端按「档位单价 × 用量」折算并计入项目账本；未定价档位显示 [待定价]（不折算、不谎报金额）」。

图像标签页字段：提示词 / 引擎（gpt / seedream）/ 尺寸。两个可以照抄的提示词见 附录 C。

建议做法：先只生成 2 张试水，看上不上得了台面，再批量生成剩下 10 张。不要一上来点 12 次。

任务卡 C · SEO 内容与内容日历

任务名称：NestKeeper 内容选题与 SEO 大纲

描述：基于目标客群（25–35 岁租房城市年轻人）与三类产品，产出 20 个英文博客选题，并为其中 5 个写出详细文章大纲（含 H1/H2 结构、目标关键词、搜索意图、字数建议）。选题要围绕「租房收纳难题」这类真实搜索意图，不要写品牌自夸内容。完成标准：20 个选题 + 5 份大纲全部产出，每个选题标注目标关键词。

任务类型：通用任务　引擎：Agent 智能体　时间片权重：2　优先级：P1 - 高

引擎怎么选，记住一句话就够

要写代码、要建东西、要跑很久 → 循环执行（loop）；要整合信息、要快速产出文本 → Agent 智能体（agent）。拿不准时：任务类型选「新建软件工程」或「软件修改」时一律 loop；纯文本类一律 agent。系统其实还会按描述里的关键词自己猜（编码/开发/构建→loop，查询/汇总/快速→agent，兜底 loop），但你自己选更稳。

第二周结束时，你应该已经：12 个 SKU 的文案齐了、主图齐了、20 个内容选题齐了。这时候你会发现一件有意思的事——活儿不是「干完」的，是「排队轮流推进」的。你同时挂着五六个任务，每轮 AI 只推进其中几个时间片。这就是「排班」，不是「一件件做」。

七、第 3 周：获客与客户接触

有站了、有内容了，第三周开始做「让人知道」。这一周有两个重点：邮件营销的审批链条，和客户页面。

7.1 SEO 与内容分发

你手上的 20 个选题，先挑 5 个写成初稿。写稿任务卡：

任务卡 D · 博客文章初稿

任务名称：NestKeeper 博客文章初稿（第 1 批 5 篇）

描述：按已确认的 5 份大纲，各写一篇 900–1200 词的英文博客初稿。每篇开头 2 句直击读者痛点，正文用小标题分段，结尾给一个自然的下一步（引导到对应产品页，不要硬推销）。完成标准：5 篇初稿产出，每篇含 H1/H2 结构、目标关键词自然出现、无夸大表述。

任务类型：通用任务　引擎：循环执行（loop）　时间片权重：3　优先级：P2 - 常规

长文用 loop、短文用 agent，这条经验值得记住：要写得长、要反复打磨的，走 loop。

7.2 邮件营销：草稿 → 人工审批 → 发送

这是本章最重要的一段纪律说明。

任务卡 E · 邮件序列草稿

任务名称：新客欢迎邮件序列草稿（5 封）

描述：为新订阅用户设计 5 封英文欢迎邮件序列（第 0 / 2 / 5 / 9 / 14 天），主题分别是：品牌欢迎与承诺、收纳痛点与选品逻辑、单品深度介绍、真实使用场景、限时优惠引导。每封含主题行、预览文字、正文、一个 CTA 按钮文案。语气理性、克制、不夸大。完成标准：5 封邮件全部产出草稿，且每封不含任何未经确认的产品参数或承诺。

任务类型：通用任务　引擎：Agent 智能体　时间片权重：2　优先级：P1 - 高

草稿出来之后，它不会自己发出去。这正是半自动模式在起作用——「对外动作」要你点头。你在「人工节点」页会看到待处理项：

自动运营控制台 › 人工节点

人工处理节点页的筛选有待处理 / 处理中 / 已完成 / 已驳回 / 已升级，卡片上会显示通道 / 自主级别 L{n} / SLA（秒）/ 处理人 / 描述。邮件这类敏感动作一般走黄通道（敏感需确认），自主级别默认 L2（一键确认：AI 暂停等你，你点一下才继续）。

审批这一步，一个环节都不能省

邮件发出去就收不回来，触达的是真实客户，代表的是你的品牌。你可以把审批做得很快——但你不能跳过它。想快，就提前把「品牌调性」「禁用词」「统一口径」写进公司级知识库，让 AI 第一版就贴近你的要求；而不是事后用「取消发送」来补救。另外记住：手机端也能审批（移动端审批页有「批准 / 拒绝」），所以你没有「没在电脑前所以只能让 AI 自己发」这个借口。

7.3 建一个客户页面：给独立站做「产品手册智能问答」

进入项目 › 左侧菜单「研究与获客」 › 客户页面 › 新建分享

「客户页面」是你可以公开分享出去的一条问答链接。客户不需要账号，打开就能问，AI 只按你允许的知识库回答。给独立站做一个「产品手册智能问答」，填法逐项如下：

字段本案例怎么填说明
名称必填 NestKeeper 产品手册智能问答 提示原文 如：产品手册智能问答。不填点保存会提示「请输入分享名称」。名称只是给你自己看的。
简介 关于产品尺寸、材质、使用与保养的常见问题。 对外展示的简介，客户能在页面上看到。这句话决定了客户会问什么，值得好好写。
知识库白名单 只勾「NestKeeper 资料库」里那个产品资料库，不要勾公司级库 勾选框提示原文是 留空表示不开放任何知识库，请显式勾选要公开的知识库，下方还写着一行 「留空 = 不开放任何知识库（访客只能得到无资料的通用回答）」。这是本页最关键的一个字段。一个都不勾，列表里会显示空态「未开放（未勾选知识库）」，保存时还会再弹一次二次确认。
启用 开 关掉等于这条链接不可用。
每分钟限流 5（默认 10） 单位是「次/分钟（每访客）」。公开页面对陌生人开放，起步期调小一点。
每日上限 100（默认 100） 单位是「次/天（总计）」。这是你这个页面一天最多花多少钱的间接控制阀。
过期时间 先留空（永久有效），跑一周再决定要不要设 提示原文 留空表示永久有效。设置过期时间等于给这条链接上了一个自动保险。

点 保存 创建后，会弹出一个窗口，里面是唯一一次能看到完整链接的机会。警告原文是：

界面原文 · 创建成功提示 请立即复制访问链接，token 仅本次展示，关闭后不可再查看

立刻点 复制链接 存好。列表里以后只显示 /s/xxxx**** 这种带掩码的提示——看不到完整 token。真弄丢了也不用慌，操作列里有 重置链接：确认后会生成一条新链接，旧链接立即失效，已经发出去的旧地址要重新发一遍。

为什么不要把所有知识库都放进去

先把最容易搞反的一点说清：「知识库白名单」留空 = 不开放任何库，不是"全部开放"——旧版本的界面文案把它写反了，这一版已经改对（列表空态显示「未开放（未勾选知识库）」，没勾选就保存会弹窗二次确认）。

真正的坑在另一头：把不该公开的库和产品资料挤进同一个库，然后为了公开产品资料顺手勾了这个库。你的项目级库里除了产品资料，还有供应商报价表——那是你的成本价。客户问一句「你们这个收纳盒成本多少」，AI 可能就把报价表里的数字说出来了。勾选处的警示原文就是「切勿把含成本价 / 供应商报价 / 内部制度的库加入白名单」。只勾该给客户看的那一个库，库也要分家，这不是小心谨慎，这是基本操作。

客户页面的公开访问地址形如 /s/{token}，页面标题是「AI 智能问答」，输入框提示「请输入您的问题…」，单条限制 2000 字。你自己先去测三个问题，看回答是不是只引用了产品资料。有一点提前跟客户说清楚：访客的聊天记录只留在他自己那台电脑的浏览器里，刷新或换个浏览器就没了，服务端不留存这段对话；要复盘客户问了什么，看的是列表里的「访问日志」。

7.4 客户咨询怎么接（流程 / 连接器 / 人工节点）

客户从客户页面提问、从邮件回复、从「联系我们」表单进来，这三条路最后都汇到你的处理队列：

客户来源客户页面 / 邮件 / 表单
›
AI 首答基于知识库给草稿或直接回答
›
超范围退款 / 赔偿 / 政策外特例
›
人工节点你在「人工节点」页处理

「超范围问题必须升级」这条规则，要写进你 Agent 的岗位提示词里（第四节给了范例）。想让 AI 能真正连上你的邮箱或表单，需要配「连接器」（智能体连接外部系统的插头，英文叫 MCP）——这一步涉及凭据和外部系统，建议等到第三周之后、流程跑顺了再配。起步期先用客户页面顶上就够了。

八、第 4 周：复盘与第一次调整

第 4 周不做新东西，只做一件事：看数字，然后改一个地方。

8.1 该看哪几屏

  1. 经营日报

    页面标题「经营日报」，按钮 生成日报 刷新。类型有 daily 经营日报 / analysis 分析报告 / audit 内审报告 / redteam 红队演练；状态有 draft 草稿 / confirmed 已确认 / applied 已应用。重点看「草稿」状态的——那是在等你确认的。

  2. 经营驾驶舱

    标题「经营驾驶舱」，按钮 刷新 运行预警评估。六张指标卡：总收入 / 总成本 / 净收入 / 任务完成率 / 预算消耗率 / 活跃预警。预警级别 warn 警告 / critical 严重。

  3. 监控指标

    四张质量卡：AI 产出质量评分（均值 0-10）/ 客户响应时间 P95（秒）/ 人类参与率（%）/ 知识库增长量（近 30 天新增条目）。

  4. 计费明细

    四张汇总卡：累计花费 / 预算已用 / 输入 Token / 输出 Token。这里有一个必须知道的 tooltip 原文：「其中包含按文本长度估算的兜底计费（上游未回 usage 时产生），非精确账单，请勿直接作为账单核销」。

8.2 假设三个典型问题，怎么处置

问题一：某个任务花费异常高

现象：计费明细里，一个叫「独立站建站」的任务吃掉了一半预算，而它还在「运行中」。

怎么查：计费明细 → 看输入/输出 Token 比例。如果输出 Token 特别大，说明它在大段大段地写字；再去「阿米巴核算」看岗位级核算，确认是哪一类活儿在烧。

怎么处置：① 把它的时间片权重从 4 降到 2，让它每轮少占时间；② 如果它是 loop 任务，考虑是不是任务范围太大，拆成两个小任务；③ 在任务描述里收紧范围（「本轮只做首页和产品列表」）。不要直接暂停——建站任务通常是关键路径，暂停它会更慢。

问题二：返工率偏高

现象：验收记录里一堆「返工」结论，AI 干完了又被退回来重做。

怎么查：去「验收记录」页看结论分布（pass 通过 / redo 返工 / reject 驳回），再点开详情看「执行者」和「验收 Agent」分别说了什么。同时看「角色管理 → 绩效」里的返工率。

怎么处置：九成的返工是需求没写清，不是 AI 不行。回去看任务描述——你是不是只写了「优化产品文案」？把它改成可核对的：「12 个 SKU，每个含主标题 60 字符内、3 条卖点、80–120 词描述、参数表与知识库原文一致」。把「什么算做完」写进任务描述，返工率会立刻下来。

问题三：内容产出多，但没有转化

现象：20 篇选题、5 篇长文、5 封邮件都产出了，站点访问也在涨，但没有任何询盘。

怎么查：这类问题基本不是模型问题，是链路问题。去看客户页面的访问日志（客户页面 → 那一行的「日志」）：客户问了什么？有没有「拦截 / 过期」的记录？如果客户问了但没人接，那就是跟进动作缺失。

怎么处置：加一条「线索跟进」任务，并把客户页面的咨询、邮件的回复都接到人工节点上。这一条非常典型——你花了大力气做「让人知道」，却没做「接住人」。

一人公司最稀缺的资源是注意力

上面三个问题，每个都有十种改法，但你的时间只够改一种。决定「下一步只做一件事」比列出十件事重要得多。本案例第 4 周选的是第三件——把「接住人」这条链路补齐。理由：前两件是效率和成本问题，第三件是「有没有生意」的问题。

8.3 触发一次全局重排

看完数字、改完方向，建议手动触发一次 review（重排）。系统默认每 20 轮会自动做一次：AI 审视全局（进度、预算、收益），重新排任务集和时间片。你现在主动触发一次，相当于让 AI 按新的优先级重排一遍，执行效率通常会有明显变化。

九、第 2 个月：第一次扩编

第 2 个月开始，你的项目已经跑了一段时间，系统会开始给你「该长大了」的信号。

9.1 走一遍组织进化页

进入项目 › 左侧菜单「组织与运营」 › 组织进化

页面标题「组织进化」，从上到下五块：阶段状态 / 组织架构 / AI 建议 / 能力开启 / 定量调控（八维）。

  1. 看阶段状态与判定证据

    「阶段状态」块有 重新评估 按钮，后面跟着阶段徽章（起步期 / 成长期 / 规模化期 / 成熟期）和成熟度。展开「判定证据」能看到一张表：指标 / 当前值 / 阈值 / 命中 / 可用。这就是「凭数据说话」——它告诉你为什么判断你现在还在起步期。

  2. 看 AI 建议

    「AI 建议（N 条待处理）」是本页最重要的区域。建议类型有 role_add 增员 / scale_out 扩容 / skill_attach 技能装配 / stage_upgrade 阶段升级；状态有 pending 待确认 / accepted 已确认 / applied 已应用 / declined 已拒绝 / deferred 暂缓 / expired 已过期。每条建议都能展开「为什么（证据）」，看到它的对标基准和指标依据。

  3. 确认采纳

    点 确认 时，系统会弹确认框，原文是：「确认采纳建议「X」？系统将自动完成扩编/装配并上岗。」 点「暂缓」会要求你输入冷却天数（冷却期内不再重复提示）；点「拒绝」要输入原因（用于留痕复盘）。

  4. 上岗

    确认后 AI 会自动建角色、装技能、上岗测试，然后进入调度。你不需要手动去智能体中心一个个建。

9.2 该加营销 Agent 还是客服 Agent

本案例在第 2 个月收到的建议大概率是增员，但加哪个岗位，要看你的证据，不是看感觉。判断标准：

看什么如果……该加的是
任务队列长度 / 等待时间 内容类任务一直排队、等很久 营销 Agent（内容产能不够）
客户页面访问日志 咨询量上来了，但回复慢、有人工节点积压 客服 Agent（接待能力不够）
AI 产出质量评分 内容质量分低、返工多 先别加人，先把提示词和知识库改好
预算消耗率 已经接近 80% 预警线 先别加人，先看钱花在哪了

本案例的设定是：内容任务排队、咨询量小但没有及时接——所以两个都需要，但只加一个，加客服。理由和第八节一样：接住一个真实客户比多发一篇文章值钱。营销可以慢一点，客户丢了就没了。

扩编要花多少钱（示例估算）

建议卡片上会直接显示「估算月成本」和「扩编后总成本变化」——这是系统给你的透明标注，不要跳过。按组织四阶段的量级参考：起步期约 ¥90–380/月，进入成长期（小组分工）大致在 ¥350–1000/月。注意这是量级估算，不是账单；真实花费看计费明细。

9.3 阶段切换：从起步期到成长期

如果你确认已经具备条件，可以主动点页面右上角的 阶段切换。弹窗里有一段 alert 原文值得读一遍：

界面原文 · 阶段切换 阶段切换会批量创建缺失岗位、更新组织节点与阶段状态；提交前系统会做角色唯一 / 技能合法 / 预算覆盖校验。

弹窗字段是「目标阶段」和「岗位集（可选，留空使用阶段推荐默认岗位）」，按钮有 回退上次切换、取消、确认切换。注意它是建议不是命令——你可以切换，也可以回退。升级永远看数据，不看心情。

十、第 3 个月：进入稳定运营的节奏

到第 3 个月，项目应该进入一种「你不盯着它也在跑」的状态。这时候你的工作从「搭东西」变成「看节奏」。

10.1 每周固定动作清单（可勾选）

  • 周一：看「人工节点」有没有待处理的（邮件审批、客户升级、关键决策）
  • 周一：看「经营日报」，重点看草稿状态的报告，确认或调整
  • 周三：看「运行轮次」，有没有卡在「需重做 / 已驳回」的任务
  • 周三：用 RAG 检索搜 3 个关键词，检查知识库还准不准
  • 周五：看「计费明细」和「经营驾驶舱」，预算消耗率有没有异常
  • 周五：看「验收记录」，返工率是不是在下降
  • 周五：看客户页面「日志」，有没有被「拦截」或「过期」的咨询
  • 月末：做一次月度复盘，写下个月「只做的一件事」

10.2 什么时候该考虑开第二个项目

第 3 个月你一定会有这个念头：「我能不能再开一个项目，做另一个品类 / 另一个市场？」

判断标准只有一条：第一个项目是否已经「不需要你每天救火」。具体看三个信号：

  • 最近的经营日报里，人工节点数量在下降（说明 AI 的判断越来越准，你要插手的地方越来越少）。
  • 预算消耗率稳定，不再频繁触发预警。
  • 返工率持续下降且任务完成率稳定。

三个都满足，可以考虑开第二个。只要有一个明显不满足，「还不到时候」往往就是正确答案。因为第二个项目意味着第二台服务器、第二套知识库、第二份注意力预算——而注意力是唯一不能靠花钱补充的资源。

一人公司最大的陷阱是「多点开花」

你有 AI 班子，能力上限确实比传统一人公司高。但你的决策带宽没变。一个项目跑顺了再开第二个，是「复制成功」；一个项目还没顺就开第二个，是「把一个坑变成两个坑」。

十一、这个案例里，我踩过的坑（10 条）

下面 10 条，是走这条路最常见的坑。每条都写清「现象 → 原因 → 后来怎么改」，你可以直接拿去对照自己。

#踩的坑现象原因后来怎么改
1 任务写成「优化网站」 AI 连着三天改前端样式，配色换了七八轮，用户根本看不到的东西反复调 「优化」是个没有边界、也没有「做完」标准的词。AI 只能自己定义什么叫优化——它选了它最容易做的那个（改样式） 把动词换成可核对的名词：「把产品详情页的加载时间降到 X 以内」「12 个 SKU 全部可点开」。改完之后，同一个任务 1 天就验收通过
2 知识库里塞了供应商报价 客户页面被客户问出成本相关内容，差点把底价暴露出去 把报价表和产品资料放进了同一个库，又把这个库勾进了白名单（白名单留空其实是"不开放"，真正的坑是库没分家） ① 把报价表单独建一个库，不进白名单；② 客户页面只勾「产品资料」那一个库；③ 以后凡是成本相关的资料，一律单独建库
3 一上来建了五个 Agent 岗位之间互相等活、任务在「待执行」堆着，钱花了活没多干 业务量喂不饱五个岗位，多出来的成本全花在「协调」和「重复读上下文」上 砍回一个全能岗，跑一个月再按真实瓶颈加人。加人的依据是数据，不是「感觉需要一个」
4 视频额度填了 0 以为 0 是「关闭」，结果根本没上限，做了一次视频测试花掉一小笔 预算说明原文是「0 表示不限制」，0 是放开不是锁死 不想花就填一个很小的正数（如 50），让额度成为真正的上限。同时对不做的品类，靠审批而不是靠额度兜底
5 跳过需求对齐直接建站 AI 做出了三个版本的首页，但一个页面结构都不对，全部推倒 省掉了「软件工程向导」的需求对齐，等于让 AI 猜你要什么 凡是「软件类」的活，一律走软件工程向导，把 7 个页面和「做完的标准」在 PRD 阶段就写死
6 邮件草稿没审就排队发送 草稿里有一句夸大的时效承诺，差点发给全部订阅客户 把「对外动作人工确认」当成麻烦，想去掉这道关 不跳审批，改成「把标准写进知识库」——公司在知识库里写清禁用词和口径，AI 第一版就贴近要求，审批从十分钟变成十秒
7 知识库文档一直是「解析中」 AI 回答里完全没用到产品资料，写得像通用电商文案 纯图片扫描的 PDF 解析不出文字，文档没到「就绪」就不参与检索，但你只看「上传成功」就走了 上传后固定做一次 RAG 自检，搜三个关键词；文档状态不是「就绪」就点「处理」催一下
8 第一周就选了全自动 AI 自己决定了一次小额支出和一次内容发布，你事后才知道 想「一步到位」，把第一周该用来观察的窗口直接跳过了 第一周老实选半自动，看着 AI 怎么判断；等你能预测它下一步要干什么了，再考虑放开
9 预算只设了总预算，没管 Token 月度额度 月底 Token 额度悄悄用完，任务被熔断停了一天 总预算管的是整个项目，Token 月度额度管的是「这个月的模型调用」——两个是不同跑道 每月初看一次 Token 月度额度的余量，在计费明细里看输入/输出 Token 比例，异常就调任务的时间片权重
10 内容产出一堆，没人接住客户 文章、邮件、客户页面都做了，访问量在涨，但零询盘 只做了「让人知道」，没做「接住人」——缺跟进任务和人工节点 加一条「线索跟进」任务，把客户页面咨询和邮件回复都接到人工节点；每周五固定看客户页面日志
把这 10 条总结成一句话

这个案例里几乎所有的坑，根因都是同一句话——「你没有告诉 AI 什么算做完，也没有告诉它什么不能做。」前者靠任务描述，后者靠知识库和提示词。这两件事做好了，这个系统会非常好用；做不好，你会觉得它笨。

十二、本章小结与下一步

  • 顺序比功能重要。公司 → 项目 → 知识库 → Agent → 建站 → 内容 → 获客 → 复盘。跳过任何一步，后面都要回来补。
  • 第一周留在半自动。不是保守，是给自己一个「看懂 AI 怎么判断」的窗口期。
  • 描述和目标写清楚，AI 才有抓手。这两个字段是全流程里唯一会真正改变 AI 行为的项目信息。
  • 软件类的活走软件工程向导，把「什么算做完」在 PRD 阶段写死，返工率立刻下降。
  • 对外动作必须有人工审批。邮件、发布、上架，一个环节都不省；想快就靠知识库，不靠跳过审批。
  • 扩编看数据不看感觉。组织进化页的建议、判定证据、估算成本，三样都看清楚再点「确认」。
  • 一个人公司最稀缺的是注意力。每个月只做一件事，比列十件事有用。

你会注意到，这个案例里最难的从来不是「怎么建站」——建站这件事，AI 干得比大多数人好。难的是你有没有想清楚要什么、有没有把标准写出来、有没有在关键的地方点头。这三件事，AI 替不了你。

这个案例是「从零开始做一个新业务」。下一章我们换一个场景：你手上已经有一个软件产品，或者要接私活给客户做企业站、小程序，那条路和这条路的打法完全不同——去读 第 16 章 · 案例：软件产品与网站设计。
