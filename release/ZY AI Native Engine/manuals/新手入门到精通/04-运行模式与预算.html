第04章 运行模式、自主级别与预算

读完这一章，你能自己拍板三件事：让 AI 有多自由、让它什么时候停下来问你、给它多少钱并且烧不穿。

阅读约 15 分钟 新手友好 重点：三种模式 / L0–L3 / 预警熔断

你将学会

  • 分清「运行模式 / 自主级别 / 权限租赁」这三个控制 AI 自由度的旋钮
  • 看懂三种运行模式怎么选，以及「手动」和「人工审核」为什么是同一个意思
  • 说出 AI 在哪些环节会停下来等你点头
  • 讲清楚钱装在三个口袋里，token 到底怎么算
  • 看懂预算的一生：预警 → 熔断 → 补预算 → 恢复

一、三个旋钮，控制 AI 有多自由

新手最常问的一句是「AI 会不会背着我乱花钱、乱发东西」。答案不是「会」也不是「不会」，而是你可以用三个旋钮把它的自由度拧到你舒服的位置。这三个旋钮是不同层次的东西，别混在一起看：

旋钮一 · 运行模式

管「整个项目」的节奏

这个项目整体按什么节奏跑：全自动一路推，半自动关键处停一下，手动（人工审核）基本每一步都要你看。

在新建项目向导里选一次，之后还能在自动运营控制台改。

旋钮二 · 自主级别（L0–L3）

管「某一件具体的事」

针对单个人工处理节点，决定这件事要你多重的确认：L0 完全不管，L3 强制人工审核。

这是更细的一层，用在单个节点上，不是整个项目。

旋钮三 · 权限租赁

管「一次敏感动作」的临时授权

AI 要做一件敏感但偶发的事（如给某个邮箱发信），向你申请一张有期限、有金额上限的临时授权。

到期或超上限自动回收，不是长期放开。

打个比方：运行模式是你给整个公司定「日常是不是全自动上班」；自主级别是你给某一件事单独标「这件事必须我签字」；权限租赁是你临时批给下属一张「只能花 50 元、今天有效」的采购卡。

一句话记住

运行模式管全局节奏，自主级别管单件事，权限租赁管一次性授权。三个加在一起，才构成 AI 的「自由度」。

二、三种运行模式，怎么选

先说一件容易踩坑的事：「手动」和「人工审核」是同一个意思，只是出现在不同的页面上。新建项目向导里它叫「手动」，等你进了项目、在自动运营控制台「调整运行模式」里，它叫「人工审核」。别以为是两种不同的模式。

两处叫法，别混着记

新建项目向导的选项：全自动 / 半自动 / 手动。
自动运营控制台 → 调整运行模式的选项：全自动 / 半自动 / 人工审核。
「手动」和「人工审核」是同一个意思，只是两个界面的翻译不一样。

补一句给爱较真的人：这两处写入后端的内部取值其实不是一个字符串——向导写的是 manual，控制台写的是 manual_review，后端把两者都当成「不启用自动运营循环」，所以效果完全一样、不会出现「选了却没生效」。目前平台侧还没把这两个字段合并成一个，但对你使用没有任何影响，看到两处叫法不同不必惊慌。

三种模式的官方解释（原文）：

全自动

AI 自动拆解任务、调度轮次、评审验收，全程自动执行，仅在关键节点通知你。

适合 你已经信任它、且业务动作大多在「内部」的场景。

半自动 默认

AI 自动执行，但在关键决策节点（目标变更、大额支出、对外动作等）由人工确认后继续。

适合 大多数人——自动干，但碰到「花钱、对外、改方向」这类大事停下来问你。

人工审核

AI 产出方案后必须人工审核通过才执行，节奏较慢但最可控。

适合 刚开始用、想看清 AI 每一步，或业务红线多的团队。

重要：人工审核不启动自动运营循环

只有 全自动 / 半自动 两种模式会启动「自动运营循环」，AI 才会自己一轮一轮往下推。选了人工审核，系统不会自动跑循环——任务靠你手动触发，AI 每次产出方案后等你审核。所以：想让它「自己动起来」，就别选人工审核。

怎么选：看你的红线在哪

你的情况 建议模式 为什么
刚上手，第一次用 半自动 既能体验「自动推」，又在大事上把着关，最不容易出岔子
要看清 AI 每一步、业务对合规要求高 人工审核 每步都要你点头，节奏慢但完全可控
已跑熟、动作都在内部、信任 AI 全自动 只在关键节点通知你，省心
先看看 AI 怎么干、不想它自己动 人工审核 不启动循环，任务你手动触发
模式随时能改，不用一次选对

运行模式不是一锤子买卖。你随时可以在自动运营控制台里「调整运行模式」。从一个保守的模式起步（比如半自动），跑顺了再切全自动，是最稳的打法。

切换模式时，系统会给你一句明确提示（原文）：「切换后将暂停自动运营循环，仅保留人工审核驱动的执行，可在之后重新启动或调整」。意思是：如果你从全自动/半自动切到人工审核，正在跑的自动循环会停下来，之后每一件事都要你人工审过才执行；你想让它再自动起来，再切回全自动或半自动即可。

三、AI 什么时候停下来等你

知道了「模式」，你大概还想知道：它到底会在哪些地方停下来问我？把「停下来等你」的节点列清楚，你心里才有底。它停下等你，主要通过两套东西：三通道（红/黄/绿）和自主级别（L0–L3）。

三通道：按风险分颜色

通道 触发 处理
绿 例行 常规内部事项 按级别处理，L0 直接执行归档
黄 敏感 敏感写操作（发布 / 删除 / 付费 / 外发等） 生成权限租赁，超权限上限需你授权
红 强制 命中红通道禁止清单 强制 L3 人工审核，AI 不得代行

自主级别：一件事要你多重的确认

级别 行为 要不要等你
L0 全自主执行，不创建节点、不通知 不等，直接干
L1 通知不等待：创建节点 + 通知，AI 继续推进 通知你，但不拦
L2（默认） 一键确认：AI 暂停等待，面板一键确认后继续 停下来，等你点一下
L3 强制人工审核：必须审核通过（可多人 / 审批流）才继续 停下来，等你正式审核

这些「停下来等你」的节点，最终都会集中到一个页面：人工处理节点。你在那里看到一张张卡片，每张标注「通道 / 自主级别 L{n} / SLA（秒）/ 处理人」，然后点确认完成，AI 才继续往下走。通知也会推到通知中心和飞书/Telegram，你手机上就能批。

哪些具体动作会「停下来等你」？记住这四类最常见的：

  • 对外动作：发布内容、发营销邮件、给客户回复，这类对外的都要过你。
  • 花钱动作：调用第三方付费接口、大额支出。
  • 敏感改动：删除、覆盖、装软件这类可能破坏现状的动作。
  • 改方向：目标变更、KR 调整这类「往哪走」的决策。
SLA 是什么

每个节点带一个 SLA 超时（秒）。它停着等你，如果超过这个时间你还没处理，系统会按配置降级为 L1（通知不等待，继续跑）或沿升级链逐级升级（项目负责人 → 平台超管），不会一直卡死。

四、预算装在三个口袋里

钱的事，新手容易糊涂，是因为系统里其实有三层账，各自独立：

口袋一 · 平台账户（真实资金）

你往平台真金白银充的钱。扣的是 AI 算力费、云服务器费、媒体生成费等真实开销。

在公司账本页看，余额不足会提示「请及时充值避免实例熔断」。

口袋二 · 项目预算（虚拟核算）

每个项目自己的一本虚拟账，记收入、支出、预算消耗，用来算这个项目赚不赚钱。

在项目账本和项目详情的预算明细页看。

口袋三 · AI 运行预算（熔断线）

专门给模型调用（token）设的一条额度线。超了它就暂停循环，防止 AI 无脑烧 token。

在自动运营控制台看「AI 预算消耗」。

这三层账的关系是：平台账户是「银行余额」，你往里充钱；项目预算和AI 运行预算是「这个项目的两本花销账」，分别用来算「这单生意赚不赚」和「AI 烧 token 超没超」。平时盯项目时，你主要看后面两个；担心「平台账户够不够扣」时，才去看公司账本。

新建项目时，预算设定页会要你填几个额度，单位都是人民币（元），0 表示不限制：

  • 总预算：覆盖整个项目所有支出（含 token、第三方接口、算力、人工等）。
  • Token 额度：AI 运行预算，模型调用这一条线。
  • 图片 / 视频 / 服务器额度：媒体生成和云服务器各自的口袋。
预算科目怎么记

系统把开销归到几个科目（原文）：token_fee（模型调用）/ third_party_api（第三方接口）/ compute_fee（算力）/ human_intervention（人工介入）。留空科目不计入，所以填的时候想清楚哪些要计入预算。

五、钱到底怎么算

AI 花得最多的是模型调用，按 token 计费。默认单价（元 / 百万 token，可在「运行配置 → 定价」里改）：

输入
1 元 / 百万 token
输出
2 元 / 百万 token
缓存读
0.02 元 / 百万 token

每次模型调用，系统读会话日志里的 usage 统计 token，乘单价算出这笔钱，写进计费流水，累进 AI 运行预算。单价按发生时快照落库，你之后改了单价，不改历史流水。

举个具体的例子，帮你建立「钱花在哪」的直觉：

一笔调用是怎么算钱的

假设 AI 回答你一个问题，这一轮模型读进去 100 万 token 的上下文，吐出来 0.5 万 token 的回答：

  • 输入 100 万 token × 1 元 / 百万 = 1 元
  • 输出 0.5 万 token × 2 元 / 百万 = 0.01 元
  • 缓存读（如果命中缓存的那部分按 0.02 元 / 百万另算，几乎可忽略）

这一笔大约 1 元出头。你一天跑几百轮、每轮调几次模型，钱就是这么一点点累起来的。所以系统的预算预警和熔断才那么重要——它盯着这个累计值，到线就提醒你。

关于「估算计费」，原文提醒你

计费明细页有一句 tooltip 原文：「其中包含按文本长度估算的兜底计费（上游未回 usage 时产生），非精确账单，请勿直接作为账单核销。」意思是：偶尔上游模型没回 token 用量时，系统会按文本长度估一个数记上，目的是「不留黑洞」。它不是精确账单，别拿它当发票去核销。

技术细节放这里，进阶再展开：

三种计费口径：measured / estimated / unmetered

系统记账时分三种口径：

  • measured（实测）：上游回了真实 usage，按真实 token 数算钱，这是绝大多数情况。
  • estimated（估算）：上游没回 usage，按文本长度估算一个数，流水前缀标 est:。就是上面 tooltip 说的那部分。
  • unmetered（未计量）：确实无法计量的调用，记 0 元留个痕，前缀标 unmetered:，保证「有这笔调用」可查。

同一笔调用只记一次，靠「项目 ID + 日志引用」去重，不会重复扣费。

六、预算的一生：预警 → 熔断 → 补预算 → 恢复

预算不是「花完了才提醒你」，它有一条完整的安全链：

  1. 80% 预警

    AI 运行预算用到 80%（默认线），系统发通知提醒你，并自动降级运行——把模型切到低成本路由、放慢节奏，先稳住不直接停。

    通知中心 › 预算预警

  2. 超限熔断

    预算耗尽（AI 运行预算或总预算任一条超了），系统暂停循环，AI 不再继续烧钱。计费页和预算运行态会显示「已熔断」。

    自动运营 › 预算运行态（熔断：是）

  3. 补预算

    你去充值（平台账户）或调高预算（项目预算 / AI 运行预算）。这一步是你的事，AI 不会替你拍板投多少钱。

    项目详情 › 预算明细 › 调整预算

  4. 恢复

    补完预算，到自动运营控制台点 恢复 或 启动，系统复核两条预算线确实解除了，清掉熔断标记，继续跑。

    自动运营控制台 › 恢复 / 启动
两条熔断线是分开的

系统有两条独立的熔断线：AI 运行预算线（token 烧超了）和总预算线（整个项目花超了）。哪条先到哪条先停，各自独立记录、独立通知，不会一条把另一条的通知吃掉。

还有一道「单轮上限」，专治一轮烧太多

除了上面两条「累计」线，项目详情的运行配置里还有一个 「单轮最大预算」（参数名 single_round_max_budget，默认 100 元，0 表示不限）。它盯的不是累计值，而是单独一轮的实际花费：每轮结束结算时，如果这一轮花的钱超过了它，系统会立刻发一条「单轮预算超限」通知并暂停项目循环，提示你去查这一轮是不是太长、或者循环重试太多次，处理好、调好额度再恢复。

新手容易忽略它：总预算还有一大截，为什么项目突然停了？多半就是某轮（比如一次跑飞了的长任务）单轮超了这个上限。它和 80% 预警、超限熔断一样，都是防止「一次意外烧掉一大笔」的保险。

「降级运行」具体降的是什么？放在折叠块里，进阶再看：

「降级运行」到底做了什么

当 AI 运行预算用到预警线（默认 80%）且你开了降级开关，系统不会马上停，而是降级继续跑：

  • 把模型路由切到低成本模型，同样的事花更少的钱先顶着。
  • 降级是按项目隔离的——只影响这个项目，不会拖累你旗下其他项目一起变慢。
  • 降级后仍超预算，才会进入真正的「熔断」暂停。

一句话：预警是「先别停，勒紧裤腰带」，熔断才是「真停」。这样你能在「提示」和「硬停」之间多一次缓冲。

七、兜底保护，和「项目怎么不动了」

除了预算熔断，系统还有一道更「兜底」的保险：当 AI 反复失败、或触发了异常，它不会硬着头皮烧钱，而是自动停下来等你。

失败兜底分三级，越到后面停得越彻底：

层级 发生什么 结果
第 1–2 次失败 降级重试：换引擎 → 换角色版本 → 缩小任务范围 尽量自己救回来
第 3 次失败 升级：管理者 Agent 复盘 + 创建人工处理节点 转成人工节点等你处理
超上限 告警退出：通知 + 暂停项目循环 停下，防烧钱

这就是「兜底保护」。它会在两个地方提醒你，措辞不一样，但指的是同一件事：项目详情页说「自动运营已因兜底保护暂停」，自动运营控制台说「项目已因兜底保护暂停」。看到任一句，都按下面处理：

兜底保护原文（两个页面各一句）

自动运营控制台横幅标题是「项目已因兜底保护暂停」，正文「兜底暂停为持久状态（跨重启保留），需人工在运行配置 / 任务面板处理后，点击「恢复」继续。」——注意这里只让你点「恢复」：兜底暂停时页面顶部的状态标签会显示红色的「已暂停（兜底）」，不会再绿油油地写着「运行中」；而「启动」按钮此时是灰的、点不动（内部状态还没切走），所以别再惦记它，直接点「恢复」。
项目详情页横幅标题是「自动运营已因兜底保护暂停」，正文里那句「在自动运营控制台点击「恢复」或「启动」继续」是旧文案——实际能用的就是控制台的「恢复」。
两条横幅都会显示「原因」和「暂停时间」——先看原因。

翻译成人话：它停下来了，而且重启服务器也不会自己又跑起来（持久状态）。你要先看它为什么停、处理好，再去点「恢复」。

所以，「项目怎么突然不动了」，通常是下面几种之一，对着查：

  • 预算熔断——去补预算，再点恢复。
  • 兜底保护暂停——看失败原因，处理好再点恢复。
  • 你或同事手动点了「暂停」——点「恢复」即可。
  • 选了人工审核——本来就不自动跑，任务靠你手动触发。
  • 停在某个人工节点等你确认——去人工处理节点页点确认完成。

八、终止项目与结项

项目不是只能「暂停」和「恢复」，也可以正式收尾。当目标达成、或你决定不做了，可以终止项目。

在自动运营控制台点 终止项目，系统会要你输入终止原因，然后：

  • 把项目置为终止态，轮前检查返回「停止推进」，AI 不再跑。
  • 自动生成一份结项报告：目标达成率、任务完成率、验收返工率、Token 花费、收入、ROI、知识沉淀清单、经验总结。
  • 全程留痕，之后还能在结项报告页翻看。
终止 vs 暂停，别搞混

暂停是可逆的「歇一会」，随时恢复继续跑。终止是正式收尾，会生成结项报告。想清楚了再终止。

九、不同规模团队，预算怎么给

「我该设多少预算」没有标准答案，但可以按组织阶段给个量级参考（来自产品文档的阶段性估算，不是承诺）：

阶段 组织形态 典型月成本（估算） 在干什么
起步期 一人全能 约 $10–30 一个人跑一个项目，少量 token + 一台小服务器
成长期 小组分工 约 $50–150 多任务并行、营销上量、开始生成媒体
规模化期 部门建制 约 $200–800 多项目、更大并发、更多连接器调用
成熟期 事业部自治 约 $500–2000+ 多业务线并行、自动扩编、高频使用
这是量级参考，不是账单

实际花费取决于任务量、模型调用频率、媒体生成量、服务器规格，差别会很大。真正的账单以平台「公司账本」和项目「计费明细」为准。

给新手一个实操建议：先少后多。第一次把 AI 运行预算设成一个「烧穿了也不心疼」的数（比如起步期先设个几百元），跑顺了、看懂了钱花在哪，再逐步调高。宁可先熔断一次、补预算，也别一上来设个「不限制」。

还有一点能让你安心：系统有三道保险是强制开启、开关不可关的（参数可调，但关不掉）——资源治理、预算熔断、渐进式信任。也就是说，无论你怎么折腾设置，「预算熔断」这道防烧钱的闸门永远在线，不会因为误操作被关掉。你能调的只是预算给多少、预警线设多少，而不是「要不要这道闸」。

十、本章小结与下一步

开始下一章之前，把最常见的几个疑问快速过一遍：

「手动」和「人工审核」到底是不是一回事？

意思是同一个。新建项目向导里叫「手动」，进项目后在自动运营控制台里叫「人工审核」，两个界面的翻译不同；内部取值一个是 manual、一个是 manual_review，但语义一致——都表示「不启用自动运营循环」。

我选了全自动，它会不会背着我乱花钱？

不会失控。全自动只是「节奏」上不等你，但花钱、对外发布、敏感改动这些仍会走人工节点或权限租赁停下来等你；更重要的是预算预警和熔断在兜底——花到 80% 提醒你，花超了直接暂停。

预算设成 0（不限制）会怎样？

0 表示这条预算线「不限制」，也就是它不会触发熔断。新手建议别设 0，先设一个「烧穿也不心疼」的数，跑顺了再放宽。

项目不动了，怎么判断是哪种「停」？

对着本章第七节查：预算熔断（去补预算）、兜底保护暂停（看失败原因）、手动暂停（点恢复）、选了人工审核（本来就不自动跑）、停在人工节点（去点确认完成）。

  • 三个旋钮：运行模式管全局节奏，自主级别（L0–L3）管单件事，权限租赁管一次性授权。
  • 三种模式：全自动（关键节点通知）、半自动（关键决策处人工确认，默认）、人工审核（每步审核）。「手动」与「人工审核」是同一个意思（内部取值分别为 manual / manual_review，语义一致）。
  • 关键事实：只有全自动 / 半自动才启动自动运营循环；人工审核不启动，任务靠你手动触发。
  • 三个口袋：平台账户（真实资金）、项目预算（虚拟核算）、AI 运行预算（token 熔断线）。
  • 钱怎么算：输入 1 元 / 输出 2 元 / 缓存读 0.02 元（每百万 token），有少量「估算计费」不是精确账单。
  • 预算的一生：80% 预警（降级）→ 超限熔断（暂停）→ 补预算 → 恢复。
  • 兜底保护：三级失败兜底，最后「持久暂停」等人工处理，重启也不会自己跑。
