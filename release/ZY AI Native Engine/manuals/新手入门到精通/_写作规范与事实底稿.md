## 一、这本手册是什么

**书名**：《ZY 企业智能引擎 · 新手入门到精通》
**读者画像**（写作必须时刻想着他）：

1. 一个人创业的 **OPC 一人公司 CEO**：没有技术团队，看得懂界面、看不懂代码，预算敏感。
2. **中小企业管理团队**：老板 + 运营 + 产品，想知道"这东西到底怎么落地到我行业"。
3. **已有业务要上线的负责人**：手上有现成项目、现成资料，想导入而不是从零开始。

读者**不知道**我们的内部术语（auto-ops、RunConfig、HMAC、done_when）。每个术语首次出现必须用一句人话解释，并给"在界面哪里看到它"。

**这本书要回答的核心问题**（用户原话，必须都被覆盖）：

- 我怎么创建公司、怎么创建项目？**这些信息对后续有没有影响？**
- 适合创建哪些项目？新项目怎么弄？**已经存在的项目与资料怎么导入？**
- 怎么创建 / 修改项目中的**复杂软件功能**？（通过自动运营里的"新建任务"）
- 我和 AI 可以提哪些问题？
- 作为 OPC 一人公司 CEO 或管理团队，我应该怎么开始？有哪些行业示例？
- 我平时应该关注哪些指标？
- 如何创建智能体、如何管理、**能否自动管理**？
- 我发起任务，是自动调用智能体还是怎样？
- 100 个问题的 FAQ。
- 前端页面的**按钮、输入说明**。

**语气**：像一位陪你上手的同事，第二人称"你"，句子短。不要学术腔，不要营销腔，不写"本系统致力于……"。可以直说"这一步大多数人会填错，记住一句话：……"。

## 二、硬性交付要求（不合规要返工）

### 2.1 篇幅（分档要求）

| 章节 | 汉字数下限 | 目标 |
| :--- | :--- | :--- |
| 01–04（已交付） | 4500 | 5000 |
| **05–14** | **10000** | 13000–18000 |
| **15–17 案例** | **12000** | 15000–20000 |
| **18 FAQ 100 问** | **20000** | 25000+ |
| **19–20** | **12000** | 15000–25000 |

**怎么"写厚"而不灌水**：正文主干保持精炼可读，多出来的篇幅放进**附录**（见 2.1.1）。附录是"全书最有复用价值的部分"——字段字典、状态全表、模板全集、报错对照、时间线、打印清单、设计依据摘录。读者平时不读，遇到问题一定来查。

表格、清单、`<details>` 折叠内容都算字数，但**不许灌水**：不要反复用"总结一下"凑行数，不要为了凑字把同一件事换三种说法。

### 2.1.1 附录规范（05 章起每章至少 2 个附录）

附录跟在正文「本章小结与下一步」**之后**，用 `## 附录 A · XXX` 形式（`<h2>` 也要带"附录 A ·"前缀，页内目录会自动收录）。

| **状态与文案全表** | 该主题所有状态码 + 界面中文 + 含义 + 出现位置 | 05–11、19 |

**附录写作要求**：每条都要能被单独使用（脱离正文也看得懂）；表格优先；不要写成正文的复述。

### 2.2 文件形态

- 纯静态 HTML，单文件，**UTF-8**，可直接 `file://` 双击打开。
- **不要**引用任何外网资源（无 CDN、无字体链接、无图片外链）。图形一律用文字、CSS 方块、表格表达。
- 不要写内联 `<style>` 大段样式（页面级微调允许极少量）；统一用 `assets/manual.css`。
- 不要写自己的 `<script>`（导航/进度条/复制按钮由 `assets/manual.js` 自动注入）。**唯一例外**：某页确需特殊交互时，可在页尾加**不超过 20 行**的 `<script>`，但不得依赖网络。

### 2.5 写作手法要求（"交互感"靠这些实现）

1. **每章开头一段"你将学会"**（用 `ul.zy-check` 的 3–5 项可勾选清单）。
2. **导览式讲解**：讲每个页面/按钮时，用固定三段式：
   - 路径：`<div class="zy-path">…</div>`
   - 界面上你会看到什么（复述**真实**按钮/字段文案，用 `.zy-btn` / `.zy-field` / `.zy-table`）
   - 点下去会发生什么 + 常见坑（`.zy-note`）
3. **前后影响**：凡是用户填的信息，必须回答"填错了以后能改吗？会影响什么？"
4. **大量使用 `<details>`** 做"进阶 / 展开看看"，让正文主干轻，深度内容可折叠。
5. **提问模板用 `.zy-copy`**，让读者一键复制去问 AI。模板要具体、带项目背景占位符（如「我的项目是【跨境电商独立站】…」）。
6. **案例要有数字与时间线**（如"第 3 天拿到了第一个可访问链接"），但**不要承诺无法验证的结果**，用"典型情况是……"。
7. 每章结尾给一节 `## 本章小结与下一步`（3–6 条要点 + 指向下一章的链接）。
8. 术语首次出现加粗并就地解释。

### 2.6 事实纪律（最重要，违反会误导用户）

1. **只能写代码/文档里真实存在的界面文案。** 引用任何按钮、字段、菜单、状态文字前，用 Grep 在 `platform-web/src/` 或 `project-server/` 里核对原文。查不到就不要写。
2. 找不到的，宁可写"当前版本界面上没有直接入口，需要在……"，也不要编一个按钮。
3. 能力现状用统一标注（本书约定）：
   - `<span class="zy-badge green">已上线</span>` —— 前端/后端都有，能用。
   - `<span class="zy-badge amber">部分可用</span>` —— 后端有、前端入口弱，或仅特定条件下可用。
   - `<span class="zy-badge sky">规划中</span>` —— PRD 在案未开发。
4. **两套"运行模式"文案确实存在，按页面区分，不许混用**：
   - 「新建项目向导」的选项是 **全自动 / 半自动 / 手动**。
   - 「自动运营控制台 → 调整运行模式」的选项是 **全自动 / 半自动 / 人工审核**。
   - 讲的时候要说清"创建时叫手动，进项目后叫人工审核，是同一个意思"。
5. **`project-server/web/index.html` 是 mock 原型，不是真实界面**，它的任何文案（如"全自动化/半自动化/人工执行"、假用户"张明远"）都**不许**引用。
6. 数据/接口细节（`/api/v1/...`）面向进阶读者，可放折叠块，不要占正文主干。

## 三、事实底稿（已核实，可直接引用）

### 3.1 产品是什么（三端）

| 端 | 用户看到的叫法 | 它管什么 | 读者要不要直接操作 |

- 第 5 步「应用评审」覆盖前会保留 `PRD.prev.md` / `TAD.prev.md`；「再生成一次」覆盖手改草稿前会二次确认，并提供「还原上一版」。
- 需求对齐页在空会话点「下一步」会被拦截，不会用空上下文覆盖已确认文档。

**软件修改弹窗**：标题「软件修改」；字段「源软件工程」「工程 ID」；输入 placeholder「描述你想如何修改这个软件工程...」+ 按钮「发送」；「任务提示词草稿」+ 按钮「再生成一次」；草稿 textarea placeholder「AI 回复将自动填入此处，可手动编辑后再确认创建」；底部「取消」「确认创建任务」；成功「软件修改任务已创建」；警告「任务提示词草稿为空，请先与 AI 对话生成」。（软件修改任务读写其「源软件工程」对应软件目录，文档按软件名隔离，见上。）

**全局交互与错误文案（跨页面）**：
- 502 / 503 / 504 **不再退化成「请求错误 (502)」**：优先透传后端 message，缺省给中文解释与下一步动作。
- 超时 / 网络异常按读、写区分：**写操作**提示「可能已在服务端生效，请先刷新确认再重试」。
- 对话页的失败改为独立错误条 + 可折叠「技术详情」（见上「AI 对话页」），底层错误原文不再拼进 AI 消息正文。
- 实例监控「实例状态」列已中文化（运行中 / 已停止 / 创建中 / 已销毁 / 待创建）。
- 边缘接入页补了未连接时的安装引导（告警标题「尚未连接边缘客户端」+ 三步指引）；WebSocket 端点等底层参数折叠进「**高级信息（排障用）**」。
- 「运行模式」单选组在任何情况下都有选中项（不再出现"一个都没选"）。

### 3.4 状态与标签字典（原文，写手册直接查这里）

- 用户状态：active 正常 / banned 已封禁 / inactive 未激活。

### 3.5 计费与预算事实

- 两条账：**平台账本**（真实资金：充值、AI 算力费、云服务器费、媒体生成费）+ **项目账本**（项目虚拟核算：收入、支出、预算消耗）。
- token 单价：输入 1 元/M、输出 2 元/M、缓存读 0.02 元/M（运行配置页可改「定价（元/百万 token）」）。
- 预算节奏：**预警线（`warn_line_pct`，默认 80%）预警**（通知并降级运行）→ **超限熔断**（暂停循环）→ **补充预算后恢复**（在自动运营控制台点「恢复」或「启动」）。控制台与「计费明细」页用**同一个**预警阈值，不再硬编码 90%。
- **单轮预算上限（`single_round_max_budget`，默认 100 元）真正生效**：轮末结算超限即告警并暂停项目。
- 兜底暂停是**持久状态（跨重启保留）**，必须人工处理后手动恢复。
- 计费含"按文本长度估算的兜底计费"（上游未回 usage 时），**不是精确账单**，别当发票用。

### 3.6 调度与执行机制事实（第 9、11 章要用）

- 默认 **10 个时间片**，任务按「时间片权重」占用时间片，每轮推进一个时间片 → 任务轮流获得处理时间。
- **接力**：每轮结束保存 `task_summary`（本轮目标/动作/未完成点/下一步），下一轮注入继续。
- 任务"完成"的判定：输出末尾出现 `[Task finished]` 标记 → 触发**独立验收 Agent**（通过 pass / 返工 redo / 驳回 reject）。**注意：platform-web 目前没有让你直接填 `done_when` 的输入框，该字段在接口层存在。写手册时说"界面暂未开放直接填写验收标准，可通过任务描述写清'什么算做完'"。**
- **review 轮**：距上次 review ≥ 20 轮（默认）或全部任务完成时触发；AI 审视全局（git log、进度、预算、收益）后重排任务集与时间片。也可手动触发。
- **free 等待**：任务集为空或全完成时进入，只做常规检查、按间隔再 review，避免空转烧钱。界面消息原文：「项目已完成全部任务并空闲等待 N 轮（不再消耗 LLM）。如需继续运营，请注入新信息并触发 review 重排任务」。
- **失败兜底三级**：第 1–2 次降级重试（换引擎 → 换角色版本 → 缩小任务范围）→ 第 3 次升级（管理者 Agent 复盘 + 创建人工处理节点）→ 超上限告警退出（通知 + 暂停项目循环，防烧钱）。
- 引擎选择：**loop**（调 qianshou 子进程，复杂 / 编码 / 长时任务，**默认**）；**agent**（进程内 LLM+ToolCall，信息整合 / 接口调用 / 快速任务）。优先级：**任务级 > 角色级 > 项目默认**；未指定时系统按描述关键词启发式预测（编码/开发/构建→loop；查询/汇总/快速→agent；兜底 loop）。
- 暂停行为：pause 是"当前轮执行完成后进入等待"，**不杀正在执行的子进程**，避免丢上下文；resume 从下一轮继续。
- 运行模式与 auto-ops：**只有 full_auto / semi_auto 会启用自动运营循环；manual_review（人工审核）不启用**（这时任务靠你手动触发）。
- 中断恢复：豁免期（默认 2 天）内直接续接；超过则做环境漂移检查（代码变更/依赖/凭据/数据库结构/知识库）→ 按时长分级（<7 天 / 7–30 天 / >30 天）→ 给 `resume / resume_with_adjust / replan` 结论。
- 安全：工作目录严格限定项目根目录；所有 LLM 调用统一经网关路由；写操作与对外动作需人工审核。

| :--- | :--- | :--- | :--- | :--- |

### 3.7.1 组织与审批的若干硬事实（第 8、14 章）

- **上岗测试有真实判定**：判定「角色在岗 / 有启用版本且提示词非空 / 期望技能已装配」，结论落库；**未通过会生成人工处理节点并停用该角色**（阻断调度）。
- **一键扩编（采纳建议）有名称唯一约束**：重复创建同名角色会返回明确的业务错误，不会产生同名重复角色。
- **角色模板按 `category` 匹配**（同名 `manager` 不再跨分类串模板）。
- **审批 / 驳回非目标状态的任务会返回明确错误**，不再"点了没反应"。
- ⚠️ **技能白名单仍是"建议性"**（仅进上下文，未强制拦截 Agent 调用）。

### 3.9 明确"没有/不成立"的事（不许写）

1. **`project-server` 没有独立前端界面**——用户全部在 platform-web 操作，项目服务器能力由平台透传。所以"登录项目服务器去操作"这类说法是错的。
2. **edge-client 托盘菜单全是英文**（标题 `ZY Edge Client`、状态项 `Status: Disconnected/Connected`、`Open Logs`、`Quit`）。其中 **`Open Logs` 会打开日志目录（已是真实实现）**；**原 `Reconnect` 菜单项已移除**（连接层已按指数退避自动重连，手动入口既不必要也易误导）。不要编中文菜单，也不要再写 `Reconnect` 是待实现项。
3. **界面没有 `done_when` 输入框**（见 3.6）。
4. **没有找到 "接力推进 / free 维护" 这两个词的用户可见文案**（只在设计文档里），写手册用「任务接力」「空闲等待」这种人话。
5. **没有 Slack / Discord 通道**（当前是飞书 / Telegram / 邮件）。
6. 不存在"一键把整个 WordPress 站点导入"这类能力，不要承诺。
7. **技能白名单未强制拦截**（见 3.7.1）；**`notification` 开关未门控**（见 3.3 设置页）；**会议导入列表无筛选/搜索**（见 3.3）。这些都要写成"未生效 / 仅前端 / 待排期"，不许写成"已修"。
8. **两套运行模式仍是两个字段、平台侧尚未合并**（见 3.4）；平台侧 `project.mode` 的白名单也没加 `manual_review`。写手册按 3.4 的说法处理，不要断言"内部是同一个字符串"。
9. **安全 / 权限 / 审计整批能力尚未落地**（本批明确未做）：AI Agent 不可授予管理权限仅**前端过滤**（后端未拦）、公司治理操作**无审计留痕**、解散公司为软删除（**不彻底**）、邀请「已过期」状态后端**从不写入**、**所有权可自转让**、移动审批页 `project_id` 有 localStorage 兜底读值、变更日志**缺「谁」列**、KillSwitch 只有**全局硬停**（无按项目/按任务粒度）、权限租赁 `scope` 为**手填 JSON 且仅语法校验**；`/approval/:nodeId` 仍**强制登录**（与"通知触达移动端即可审批"的场景冲突）。这些在手册里必须保持"未生效 / 仅前端 / 待排期"的准确表述。
   - ⚠️ **不要**把「审批意见不采集」写进这一条：经代码核对，移动端与桌面端（v2.8 起）填写的审批意见**都会落库**并沉淀为该角色经验（见 3.7 节末尾说明）。
10. **HMAC Secret 轮换只告警、不自动下发**：轮换后 API 返回 warning，在跑项目可能短暂失联（自动同步跨端协议未做）。
11. 部署脚本的**代码仓库地址是必填配置**（`AE_DEPLOY_REPO_URL` / `AE_DEPLOY_REPO_BRANCH`）：未配置时自动开通会**显式报错**（fail-closed），不会用占位地址静默跑。开通编排的 panic 恢复路径会**回滚已创建资源**并把实例置 `failed`。

## 三·补二、取材优先级与算力节约要求（**用户明确要求，务必遵守**）

> 本手册是**使用说明书**，不是架构说明书。读者要知道的是"界面上有什么、点了会怎样、为什么这么设计"。但**代码审查是本轮的组成部分**，所以代码该看还是要看，只是方式要省。

### 取材优先级（从高到低）

1. **`wiki/` 下的文档优先**：`PRD-v2.md`、`PRD-v2.5-final-feat.md`、`TAD-v2/*.md`、`TAD-v2.5-final-feat.md`、`wiki/docs/v2.5/API/*.md`、`wiki/manuals/zy-engine/release/**/*.md`。**先用这些把机制和意图搞清楚，能从这里拿到的就不要去代码里找。**
