第 06 章 · 第二步：看懂界面

第06章 界面导览（下）：项目内页面

进入项目以后，侧边栏会突然多出 6 个分组、40 多个页面，这是整个产品最让人迷路的地方。这一章给你一张完整地图：每个页面在哪、是干什么的、什么时候才需要点进去。

阅读约 25 分钟 新手友好 重点：6 大分组 / 40+ 页面 / 功能门控

你将学会

  • 说清「为什么我进项目以后，侧边栏突然多出一截菜单」
  • 把项目内 6 个分组背下来：建项与定义 / 组织与运营 / 接入与执行 / 研究与获客 / 治理与资源 / 运维与报告
  • 知道 40 多个项目页各自是干什么的，哪几个是你每天要看、哪几个按需才看
  • 看懂「功能开关」这道门：为什么有些页面点进去提示「加载失败，请确认……功能已启用」
  • 遇到「我想干某件事」时，能立刻查到该去哪个页面、点哪个按钮

先给你一张全景图

平台侧的 10 个一级页面你已经在第 05 章看过了。这一章只看项目内页面——也就是你从「项目管理」点进某一个具体项目以后，才会出现在左侧的那一截菜单。

先记住一件事：所有项目内页面，都是围着「这一个项目」转的。它们读的是这个项目自己的服务器、自己的账本、自己的知识库；你在 A 项目干的事，不会跑到 B 项目去。这是「单实例单项目物理隔离」在界面上的体现。

从上到下，恰好是一个项目从「还在定义方向」→「搭班子干活」→「接外部世界」→「对外获客」→「老板做治理」→「定期存档复盘」的顺序。你迷路时问自己一句「我这件事属于哪一段」，基本就能找到入口。

零、先进项目：从平台走到项目里

项目内页面不是单独的一个网址，你必须先「进入项目上下文」，侧边栏才会长出那 6 个分组。入口只有一个：

项目管理 › 项目列表 › 点某张项目卡片 › 项目详情页

路径说明：左侧一级菜单点 项目管理，页面标题是「项目管理」，右上角是 新建项目。下面是一张张项目卡片，每张卡片显示项目名、状态标签、描述、类型、行业、创建时间，卡片右下角还有一个 连接测试 按钮（用来探测这个项目的服务器通不通）。

点卡片任意位置，就会跳到项目详情页。这时候你会注意到左侧边栏变了：在「项目管理」下方，多出了 6 个可以展开的分组。此时浏览器地址里带了这一段：/project/34/...——里面的 34 就是项目 ID。

交互事实：路由里带 projectId，侧边栏才显示这 6 个分组

侧边栏是「看地址认人」的：只有当前网址里含 project/:projectId 时，才渲染这 6 个分组。这也是为什么你分享一个项目内页面的网址给同事，他打开后侧边栏会直接展开到对应分组、并高亮当前页；而如果你在某项目页面按浏览器刷新，也不会掉回平台首页——只要网址里的项目 ID 还在，侧边栏就不会塌掉。

项目详情页本身是什么

项目详情页是「这个项目的体检报告」，页面头部按钮有：返回 启动 暂停 恢复 停止 标记完成 编辑（按钮会按当前状态互斥显示，不是一直都能点）。下面是 5 个页签：概览 / 预算明细 / 服务器实例 / 开通日志 / 运行配置。

页签里面有什么你什么时候看
概览项目基本信息、当前状态、运行模式摘要每次进项目第一眼
预算明细按钮 调整预算，「已消耗 ¥x / ¥y」，额度项 Token / 图片 / 视频 / 服务器想知道还剩多少钱时
服务器实例IP 地址 / SSH 端口 / 项目服务器端口 8090 / 规格 / 地域 / Provider / 实例状态 / HMAC Secret（显示 复制 重新生成）；按钮 编辑实例 查看部署脚本 录入服务器 确认部署完成 录入服务器 IP开通项目、换服务器时
开通日志部署过程的逐条日志，空态「暂无日志」服务器起不来时排查
运行配置调度配置、执行器配置、定价（元/百万 token），按钮 保存配置调性能/调价时，进阶

这里有个对新手非常重要的提醒：你不需要 SSH 登录到项目服务器。项目服务器没有独立的前端界面，它的能力全部由平台透传给你，你在平台点的每个按钮，背后才是那台服务器在干活。所以「登录服务器去操作」这种说法在本产品里是不成立的。

兜底暂停是持久状态，别以为重启就好

如果自动运营因为异常触发了兜底保护，项目详情页的运行配置区会出现一条告警，原文是「自动运营已因兜底保护暂停」。它是持久状态（跨重启保留），你必须人工处理完问题，再去「自动运营控制台」点 恢复 才会继续。注意：兜底暂停时控制台顶部的状态标签会变成红色的「已暂停（兜底）」，不会再显示绿色「运行中」；旁边的「启动」按钮是灰的、点不动，请认准「恢复」。详见第 04 章。

一、建项与定义

这个分组只有 2 个入口，但它是「项目的大脑对话区」。项目刚开始的时候，你的方向、策略、资料，绝大多数是从这里喂进去的。

AI 问答

建项与定义 › AI 问答 › 页面标题「AI 问答」

页头三个按钮：返回项目 引导建项 项目导入。中间是一张大卡片「AI 问答」，右上是三个复选项：知识库检索、案例 Few-Shot、联网搜索。

这三个复选项用大白话说：

  • 知识库检索：让 AI 先翻你的项目/公司资料再回答（行业黑话叫 RAG）。默认开。
  • 案例 Few-Shot：让 AI 先看几个你标过的「优秀案例」当范例再回答，回答会更贴你的口味。默认开。
  • 联网搜索：允许 AI 上网找新信息。默认关——因为联网会变慢、也会额外花钱。

输入框的占位提示原文是「请输入你的问题，例如：如何搭建获客流程？」。下面三个按钮 提问（回答中是 回答中…）停止 清空。没提问之前，对话区显示占位文案「输入问题，AI 将基于项目知识库与优秀案例进行引导式回答」。

这一页还承载着「数据飞轮」——你给回答的每一次反馈、每一个「优秀案例」，都会反哺 AI 以后的表现。反馈有两条路：最顺手的是直接挂在回答卡片上，右侧的两张小卡片则是兜底入口。

不用再手填「交互 ID」了

以前要给某次回答反馈，得先在卡片里手输一个「交互 ID」，很多人根本不知道去哪找。现在改了：你提完一个问题、AI 给出回答后，回答卡片下方会直接出现一排按钮——采纳 拒绝 修改 提升为案例，旁边还写着「本条回答（交互 ID xxx）」。点哪个，系统就自动带上这条回答对应的交互 ID 和会话凭证，你不用填任何东西。

页面右侧那两张卡片（「反馈提交」「案例晋级」）仍然保留，但已降级为「只读展示 + 复制」的兜底路径：「交互 ID」一栏变成一枚只读标签，旁边一个 复制 按钮（复制成功提示「交互 ID 已复制」），还没提问时显示「提问后自动获取」。卡片里的「提交反馈」「提升为案例」按钮在没拿到 ID 前是灰的、点不动。

入口你会看到什么作用
回答卡片上的按钮（推荐） 采纳 拒绝 修改 提升为案例 一键对这条回答表态，自动带上交互 ID 与会话凭证，系统据此学习你的偏好
右侧「反馈提交」卡 只读的「交互 ID」+ 复制；反馈类型（采纳 / 拒绝 / 修改）、备注，按钮 提交反馈 兜底路径：想填备注、或回答卡片上的按钮不见了时，用它补交反馈
右侧「案例晋级」卡 只读的「交互 ID」+ 复制；标签（占位「逗号分隔，如：获客,营销」），按钮 提升为案例 把一次好回答「提升为优秀案例」，之后就能被 Few-Shot 引用。成功后提示「已提升为优秀案例」
反馈不会记到别人头上

服务端会强制校验归属：提交反馈 / 晋级案例时必须带会话凭证，而且它必须和那条交互记录对得上。如果 ID 或凭证对不上，会直接返回错误（403 无权限，或 404 记录不存在），绝不会把反馈写到别人的交互记录上。所以哪怕你手动粘贴了一个来路不明的 ID，也只会失败，不会造成数据错乱。

它和平台级「AI 对话」的区别

平台一级菜单里也有个 AI 对话（第 05 章讲过），那是通用聊天。这里的「AI 问答」是绑死在这个项目上的：它默认去查本项目的知识库和优秀案例，回答带着项目上下文。所以「跟我项目有关的问题」问这里，「随便聊聊」去平台 AI 对话。

另外提醒一句：案例晋级需要先选好公司上下文，否则会提示「缺少公司上下文，请先在右上角选择公司」。

进阶：「引导建项」和「项目导入」这两个按钮通向哪

页头的 引导建项 跳到「引导建项」页（页面标题就是「引导建项」）。它是一套分阶段会话：阶段依次是 research 调研 / input 信息录入 / summarize 摘要整理 / strategy 策略生成 / import 导入 / done 已完成。页面里有一张「项目执行策略」卡，按钮 重新生成 确认策略 完成建项。这里有一条硬规则要记住：没确认策略时，启动自动运营会被拦住（界面上的告警原文是「未确认策略时，启动自动运营会被拦（/autoops/start 要求已确认策略）」）。

项目导入 跳到「现有项目导入」页，用于把「已经进行中的项目」搬进来：左卡填项目名称（占位「已进行中项目的名称」）、项目描述（「一句话说明项目定位」）、既有资料（拖拽上传，提示「支持 txt/md/docx/pdf/xlsx/csv 等，单文件 ≤ 50MB；需先创建会话」）、聊天记录；按钮 上传到会话 创建导入会话；右卡是「AI 整理的项目上下文」（项目背景 / 当前阶段 / 关键联系人 / 未决事项），按钮 整理并完成建项，最后 下一步：确认执行策略。这两页的完整操作放在第 07 章讲。

模板

建项与定义 › 模板 › 页面标题「项目模板」

注意一个小细节：侧边栏里这一项叫「模板」，点进去页面标题是「项目模板」，是同一个页面。它管的是「可复用的项目配方」。

页面主体是一张模板表，工具条有：类型筛选（电商 / SaaS / 内容媒体 / 区块链 / 通用）、行业筛选，按钮 从项目导出模板 和 沉淀项目为模板。表格列有：图标、名称、分类、行业、描述、使用次数、来源（内置 / 自定义），行操作是 详情 应用。空态「暂无项目模板」。

两个「导出」方向要分清：

  • 从项目导出模板：对着某个项目，把它的 Agent 配置等打包成模板，弹窗要你填模板名称（占位「给模板起个名字」）、分类、描述（占位「模板用途说明」）。
  • 沉淀项目为模板：一句话确认「将当前项目沉淀为可复用模板（自动收集 Agent 配置、审批节点快照、预算预设）？」，成功后提示「项目已沉淀为模板」。
页面在，但要先开功能开关

「模板」属于「项目模板」功能。如果后端没给这个项目开 project_template，你会看到「项目模板功能未启用，请在功能开关中开启 project_template」。开启方法见本章第五节末尾的「功能开关」小节。

二、组织与运营

这是项目内最重、最常用的分组。前面几章反复出现的「AI 团队」「自动运营」「三权分立验收」，操作界面全在这里。侧边栏只列了 4 个入口：智能体 / 组织进化 / 自动运营 / 目标管理，但「自动运营」下面还挂着 16 个快捷子页。

智能体

组织与运营 › 智能体 › 页头「智能体中心」

如果你直接用小网址打开这一页、而地址里没有项目 ID，页面会警告：「请先进入具体项目（URL 含 projectId）后再访问智能体中心」。正常从侧边栏进就不会看到这句。

页面用 4 个页签组织：组织 / 任务 / 配置 / 运行。

页签你会看到什么关键按钮
组织 标题「Agent 组织（管理者 → 员工）」；组织架构树 + 成员列表（列：名称 / 岗位 / 类型 / 状态 / 操作）；下方「岗位模板库」（按行业筛：软件开发 / 电商运营 / 内容创作 / 智能制造 / 通用）和「技能库」（列：名称 / skill_id / 版本 / 分类 / 范围 / 状态） 刷新 新建 Agent（成员行：详情 / 技能 / 暂停|启用）；新增模板（岗位模板库）；技能行有编辑、以及 提升为组织级

「新建 Agent」弹窗字段：名称、岗位角色（下拉可自定义输入）、类型（管理者 / 员工）、上级管理者、负责人、角色描述、职责边界、人工红线。点成员行的「详情」，还能看到绩效汇总：平均质量分、任务数、返工率（rework_rate）、主要返工原因。

返工率是判断「这个 AI 员工行不行」的第一指标

返工率 = 它交付的活儿被验收打回重做的比例。返工率高，说明提示词、技能或岗位说明书没写对。第 08 章会教你对着这个数字怎么调。

技能库里的「范围」分组织级和项目级；项目级技能旁边有「提升为组织级」按钮，意思是从「只在本项目用」升级为「全公司共用」。

组织进化

组织与运营 › 组织进化 › 页面标题「组织进化」

这个页面回答一个问题：「我这个 AI 团队，现在该多大、该配哪些岗？」 页头按钮 返回项目 阶段切换 刷新。下面从上到下五块：

  1. 阶段状态

    标题「阶段状态」，右上 重新评估。展示两个徽章：阶段（起步期 / 成长期 / 规模化期 / 成熟期）和成熟度（未达成 / 接近 / 已达成），下面一句话说明判定理由。展开「判定证据」，会看到一张表：指标 / 当前值 / 阈值 / 命中（命中|未命中）/ 可用（可用|缺失）。具体指标包括任务完成数、账本营收、知识库文档数、活跃 Agent 数、任务队列长度、轮次等待时间、CRM 线索数、客户咨询量——其中「可用=缺失」的指标不参与判定。

  2. 组织架构

    一棵树，每个节点显示月成本、负载、成功率、产出。部门节点用橙色标签区分。空态「暂无组织节点」。

  3. AI 建议

    标题形如「AI 建议（N 条待处理）」。每条建议带类型标签（增员 / 扩容 / 技能装配 / 阶段升级）和状态标签（待确认 / 已确认 / 已应用 / 已拒绝 / 暂缓 / 已过期）。可展开「职责边界 / 技能草稿 / 成本估算」（含估算月成本、扩编后总成本变化）和「为什么（证据）」两段。状态是「待确认」时才出现操作按钮：确认 暂缓 拒绝。

  4. 能力开启

    标题「能力开启（已开启 X / 阶段推荐 Y）」，一条进度条 + 能力清单，每项显示所属阶段徽章和「已开启 / 未开启」。

  5. 定量调控（八维）

阶段切换是「批量动作」，会先做校验

点 阶段切换 会弹窗，提示原文：「阶段切换会批量创建缺失岗位、更新组织节点与阶段状态。提交前系统会做检查：已存在的岗位自动跳过；技能库中缺失的技能跳过装配并生成人工提醒；预算不足仅预警、不阻断（MVP 策略）。」——这句话就是它的真实行为，逐条理解：已存在的岗位不会重复建；缺技能不会阻断，只是跳过装配并给你留一条人工提醒；预算不够也只是预警、不拦着你切。字段有「目标阶段」和「岗位集（可选，留空使用阶段推荐默认岗位）」，按钮有 回退上次切换 取消 确认切换。阶段只是建议，切换永远要你人工确认，而且支持回退。

确认采纳一条 AI 建议时，文案是「确认采纳建议「X」？系统将自动完成扩编/装配并上岗。」；暂缓需要你输入冷却天数；拒绝需要你输入原因。本版本给扩编加了名称唯一约束：就算你手快连点两下，也不会再冒出两个同名角色；重复创建会返回明确的业务错误，而不是默默建一条。详细玩法见第 08 章。

自动运营

这是你每天真正要盯着的那一页。页头右上有一个大状态标签（运行中 / 已暂停 / 已暂停（兜底）/ 已停止 / 未知）。操作按钮一整排：启动 暂停 恢复 停止 终止项目 触发重排 刷新。触发重排 会二次确认「将在下一轮调度时触发一次 review 重排（AI 重新评估任务集）。确定触发？」——等于手动催 AI 在下一轮重新评估一遍任务集、重排优先级，平时不用点。

预警线不再是写死的 90%，以项目配置为准

控制台和「计费明细」页的「预警」标签、配色，统一由后端的预警阈值字段 warn_line_pct（对应预算配置 budget_warn_pct）驱动，默认 80%。也就是说，进度条到 80% 就会亮预警色，不再是以前那个写死的 90%。你要改提前量，去项目预算配置里改，两个页面会一起变，不会再出现「控制台一个数、计费页另一个数」的对不上。

点「运行模式」的 修改，会打开「调整运行模式与预算科目」弹窗。三种模式是单选：全自动 / 半自动 / 人工审核，官方解释原文：

  • 全自动：AI 自动拆解任务、调度轮次、评审验收，全程自动执行，仅在关键节点通知你。
  • 半自动：AI 自动执行，但在关键决策节点（目标变更、大额支出、对外动作等）由人工确认后继续。
  • 人工审核：AI 产出方案后必须人工审核通过才执行，节奏较慢但最可控。选它还会出现警告「切换后将暂停自动运营循环，仅保留人工审核驱动的执行，可在之后重新启动或调整」。
两种「运行模式」文案确实不一样，别混淆

「新建项目向导」里的三个选项是 全自动 / 半自动 / 手动；进项目后这里叫 全自动 / 半自动 / 人工审核。创建时叫「手动」，进项目后叫「人工审核」，是同一个意思。另外记住：只有「全自动 / 半自动」会真正启用自动运营循环，「人工审核」不启用，任务要靠你手动触发。

小细节：这个单选组永远有一个选中项，不会再出现「三个选项一个都没亮」的尴尬——虽然这两处写入的内部取值不完全相同（向导 manual / 控制台 manual_review），但打开弹窗时系统会自动落到正确的那一项上，你照着当前状态改就行。

弹窗下半部分是「预算科目（金额/元）」：可以增删科目行，提示原文是「常用科目：token_fee（模型调用）/ third_party_api（第三方接口）/ compute_fee（算力）/ human_intervention（人工介入），留空科目将不计入。」

进阶：16 个子页的路径有规律，记住它就不用翻菜单

这 16 个页面的路径全部以 /autoops/ 开头，所以侧边栏的「自动运营」项在你打开任意子页时都会高亮——它用的是「最长前缀匹配」。据此你可以直接手改网址跳转，例如把 …/autoops/tasks 手动改成 …/autoops/rounds，比回控制台再点一次快。

三个例外要注意：目标管理虽然也是 /autoops/objectives，但它在侧边栏单独列了一项（因为它是老板视角的入口，不只属于运营日常）；阿米巴核算和经营驾驶舱的数据其实来自项目账本模块，只是入口挂在自动运营下；验收记录 / 测试运行是验收链路的证据页，日常很少点，出争议时才用。

进阶：自动运营控制台上那几张卡，分别回答什么问题

很多人第一次看控制台会觉得「信息太多」。其实每张卡只回答一个问题：

  • 运行模式——AI 现在有多少自由度？（全自动 / 半自动 / 人工审核）
  • 自主级别——遇到需要拍的板，是等你还是自己过？（L0–L3）
  • 任务数——手上还有多少活？
  • 累计花费——这个项目一共烧了多少钱？
  • AI 预算消耗——本轮的钱还剩多少？（达到预警线出红色「预警」，默认 80%）
  • 预算运行态——有没有触发刹车？（熔断 / 降级 / 已终止）

顺序建议：先看「预算运行态」，再看「AI 预算消耗」，最后扫一眼「任务数」。这三眼看不出问题，就当它健康。

目标管理

组织与运营 › 目标管理 › 页面标题「目标管理」

按钮 新建目标。目标有三个状态：active 进行中 / achieved 已达成 / archived 已归档。点某条目标进详情，会看到三块内容：关键结果（KR）、关联任务、权衡权重（成本 cost / 质量 quality / 风险 risk / 速度 speed）。空态分别是「暂无目标」「暂无 KR」「暂未关联任务」。

新建目标的字段有标题（占位「如：Q3 市场份额增长 15%」）、描述、父目标 ID（占位「0 为顶级目标」）。「权衡权重」是这一页最值得琢磨的东西：它告诉 AI 在「快、好、省、稳」之间怎么取舍。你的目标如果是「尽快上线」，就把速度调高；如果是「对外发布的品牌内容」，就把质量、风险调高。第 09 章会给你几组现成配比。

连接器

接入与执行 › 连接器 › 页头「连接器（MCP）」

先解释 MCP / 连接器是什么：给 AI 装一个「连接外部系统的插头」。AI 本身只会思考、只会写字，接不上你的邮箱、CRM、数据库、飞书。连接器就是那个插头，插上以后 AI 才能真的去「发一封邮件」「查一条客户记录」。

注册连接器时要填名称、配置（占位里举了飞书的例子 {"app_id":"...","app_secret":"...","verification_token":"..."}）、数据访问范围说明。配置字段旁边现在有人话提示和示例——不确定格式时照示例填，或者直接找你的 IT 要。注册时请守住两条原则：

「编辑」= 更新同一条连接器并升版本，不是新建一条

点某个连接器的 编辑，弹窗标题写的是「编辑连接器（重新注册新版本）」，它会复用同一个 connector_id、把这个连接器升级一个新版本，不会再生成一条新的。所以以前那种「编辑几次，列表里冒出一堆同名连接器」的乱象没有了。如果传的 ID 不存在，会明确报 404，而不是悄悄新建一条。

另一个必须记住的点：原有配置永远不会回显。出于安全考虑，后端加密存储配置、从不下发，所以编辑弹窗里配置那一格是空的，你必须重新填写完整配置 JSON——弹窗里也挂了醒目提示：「已有配置不回显。请重新填写完整配置后再保存；若留空，将以空配置注册一个失效的新版本。」点保存前会有二次确认，原文是「将把该连接器更新为新版本（仍是同一条连接器），原配置不会自动保留。确认继续？」（若配置为空，则提示「将把该连接器更新为空配置的新版本，连接器可能因此失效」）。别以为配置还在、直接点保存，那样等于把连接器清空了。

顺带一提：历史遗留的重复连接器不会自动清理。如果你之前已经因为反复编辑攒出了同名多条，需要手工处理（建议按「名称 + 供应商」保留版本号最大的那条，其余软删）。

这样做

  • 最小权限：只给这一个动作需要的权限。要发邮件，就给「发邮件」，别顺手给「读全部邮件」。
  • 写操作挂人工审核：在「权限治理」里把审核策略写清「所有发送操作需人工审核」，然后在「审计」页逐条放行。
  • 先在一个项目试通，再考虑推到公司级复用。

别这样做

  • 给 AI 一个「万能钥匙」式的管理员账号。
  • 把写操作设成免审核，指望「它应该不会乱发」。
  • 把连接器密钥直接写在项目描述、任务描述里（那会进日志）。

列表里的访问链接平时只显示前缀（出于安全考虑），想看完整链接只能点 重置链接 生成一条新的，旧链接立即失效；重置同样有二次确认。所以「重置链接」不是「查看链接」，是把旧链接作废、换一把新钥匙——想收回已经发出去、可能泄露的客户链接时用它。

客户打开的那个公开页叫「AI 智能问答」（网址形如 /s/{token}），输入框占位「请输入您的问题…」，限 2000 字，右下角显示「N / 2000」字数。页面顶部有一行说明原文：「对话记录仅保存在本机浏览器，刷新后可继续；关闭标签页后清除。」——所以客户手滑刷新不会丢对话，但关掉标签页就没了，别指望它像登录用户那样长期留痕（共用电脑上这也是隐私保护）。

这里有条被传歪了的规则，必须掰正：留空 = 「什么都不开放」

先纠正一个流传很广的错误说法：很多人以为「知识库白名单留空 = 对项目全部知识库开放」。恰恰相反。后端一直是「不勾选 = 不开放任何知识库」（安全上的 fail-closed 默认）——留空的公开页检索不到任何企业资料，访客只能得到没有项目资料支撑的通用回答。这个语义后端一直没变过，偏的是以前的界面文案把话说反了，本批把界面改对了：列表里没勾选就显示「未开放（未勾选知识库）」，勾选处有醒目提示，而且留空直接保存时会弹二次确认「未勾选任何知识库，保存后公开页面将无法检索到任何企业资料（只做通用回答）。确认继续？」（按钮「确认保存」/「返回勾选」）。

但别因此放松警惕：只要你勾了一个库，那个库的内容就对公开页开放检索。所以真正要守的纪律是——千万不要把内部资料（成本表、客户名单、供应商报价、未发布方案）放进会被勾选的知识库；勾选时的提示原文就是「公开问答可能引用所选知识库中的原文，请确认其中不含成本价、供应商报价等敏感信息」。最稳妥的做法：专门给对外场景建一个「对外知识库」，白名单只勾它一个。

项目账本

治理与资源 › 项目账本 › 页面标题「项目账本」

副标题原文是「项目虚拟核算：收入、支出与预算消耗」。注意这是「虚拟核算」，跟一级菜单里的「公司账本」（平台账户真实资金流水：充值、AI 算力费、云服务器费等）是两本不同的账，别搞混。

页头按钮 记一笔 和 项目预算。

  • 记一笔：字段 类型（收入/支出）、分类（第三方服务 / 采购成本 / 薪酬 / 营业收入 / 其它）、金额、描述、关联单号。
  • 项目预算：字段 预算总额 / 预警阈值(%) / 告急阈值(%)。

项目预算的告警文案会出现在通知里，原文有三档：「项目预算已耗尽，请及时补充预算避免项目暂停。」「项目预算已用 x%，处于告急状态。」「接近预警阈值。」（公司余额那本账的告警是另一句：「余额 … 已低于预警阈值 …，请及时充值避免实例熔断。」）

这一页还有几个进阶区域：看板卡片（可 新建卡片）、AI SQL 控制台（用自然语言生成 SQL 查账）、分类统计、预算预警。项目流水空态「暂无项目流水」。

渐进式信任

安全底线 强制开启，开关不可关（参数可调）

治理与资源 › 渐进式信任 › 页面标题「渐进式信任」

「渐进式信任」人话就是：按 AI 的表现，逐步给它更大的权限。干得稳就多放权，出过错就收回来。两个页签：

  • 信任档案：列 Agent / 信任等级 / 评分 / 成功 / 失败 / 最近成功 / 备注，行内按钮 调整等级。空态「暂无信任档案」。
  • 审计记录：列 时间 / Agent / 变更类型 / 评分变化 / 等级变化 / 原因 / 审批人。空态「暂无审计记录」。

「调整信任等级」弹窗字段：Agent、当前等级、目标等级、原因。

这一页打不开时，先看功能开关

这一页是产品设计里的安全底线，正常应始终开启。如果加载不出来，页面会提示「加载信任数据失败，请确认渐进式信任功能已启用」——按本节末尾的步骤去「设置 → 功能管理」确认 trust_model 是开着的。

治理与资源 › 冲突仲裁 › 页面标题「冲突仲裁」

当两个 AI（比如「增长派」和「风控派」）给出互相矛盾的建议时，把议题丢到这里，由仲裁 Agent 分析并给最终结论。页头 新建案件 刷新。两个页签：

事件总线

治理与资源 › 事件总线 › 页面标题「事件总线」

「事件总线」是系统内部各模块之间传递消息的『广播站』。对普通读者来说，可以理解成「系统内部发生的事情的流水账」：什么模块在什么时候丢了一条什么事件、被谁领走处理了。页头 新建事件 刷新，可按「全部状态」筛。列表列：ID / 来源 / 类型 / 标题 / 优先级 / 状态 / 评分 / 创建时间，操作 处理 分配。空态「暂无事件」。

什么时候来：排查「某个动作到底有没有被触发」，或者想手动补一条事件。平时不用管。

进阶：这三本「账」和三种「权限」别搞混

三本账：平台账本（一级菜单「公司账本」，真实资金流水：充值、AI 算力费、云服务器费）、项目账本（本分组里的「项目账本」，项目自己的虚拟核算：收入、支出、预算）、阿米巴核算（把每个岗位当独立小账本算投入产出）。前者是真钱，后两者是管理口径。

三种权限机制：「自主级别 L0–L3」决定 AI 遇到事情要不要等你；「渐进式信任」决定同一个 AI 表现得越好、能拿到多大权限；「权限租赁」是临时放行某一次高危动作（比如这一次允许它给客户发一封邮件）。一句话区分：级别是长期人设，信任是表现评分，租赁是一次性通行证。

治理与资源这几个页面打不开？八成是功能开关没开

现在受功能开关门控的页面变多了，而且门是真的会拦：开关没开时请求会返回 403 并明确报「功能未启用，请在功能开关中开启 xxx」，例如「战略规划功能未启用，请在功能开关中开启 strategy」「渐进式信任功能未启用，请在功能开关中开启 trust_model」「自动构建部署功能未启用，请在功能开关中开启 deploy」；「资源治理 / 冲突仲裁」也会报「资源治理功能未启用」或「加载仲裁案件失败，请确认冲突仲裁功能已启用」。这一批真正生效的开关有 6 个：deploy（构建部署）、report（自动报告 / 复盘报告）、auto_report（智能报告）、marketing（营销自动化）、strategy（战略）、trust_model（渐进式信任）。看到这类提示先按下面的步骤检查开关，多数情况就是门没开。

开法：一级菜单 设置 → 页签 功能管理 → 先用「选择项目：」下拉选中这个项目（卡片顶部会显示「当前配置：XX」，避免改错项目；没选时提示「请先选择一个项目以管理其功能开关」）→ 在分组卡片里把对应开关打开。卡片是按后端下发的分组动态渲染的（形如「基础功能」「高级功能」），分组名和功能名都以后端字典为唯一来源，归不进去的会进「其它功能」——所以你看到的分组可能和文档举例略有出入，按实际显示的走即可。带「安全底线」标签的项是灰色锁死的，开关点不动，鼠标悬停提示「该功能为安全底线，不允许关闭」，后端也会拒绝关闭（如「「XX」为安全底线功能，不允许关闭」），这是有意的安全设计（渐进式信任、资源治理属于这一类）。旁边还有个「AI 智能建议」：点 分析项目并建议，AI 会列出建议开的高级功能（带高/中/低优先级和「开启」按钮）。想全部回到出厂设置，点 重置为默认（会有二次确认）。若页面显示「功能开关加载失败」或「项目列表加载失败」，都有失败态与重试按钮，不会静默变成空列表。

报告

运维与报告 › 报告 › 页面标题「自动报告」

侧边栏叫「报告」，页面标题是「自动报告」。按钮 刷新。上方是三档推送配置：日报 / 周报 / 月报（各是一个开关），「推送渠道」可勾 飞书 / 邮件 / Telegram，按钮 保存配置。下方是报告历史表，可按类型筛选（日报 / 周报 / 月报），按钮 生成报告；行操作 查看 推送。空态「暂无报告记录」。

什么时候来：开项目时配一次推送渠道，之后就让它自动发。

备份

运维与报告 › 备份 › 页面标题「自动备份」

侧边栏叫「备份」，页面标题是「自动备份」。两个页签：

  • 备份历史：按钮 立即备份。列 ID / 类型 / 大小 / 状态 / 校验和 / 开始时间 / 结束时间，操作 校验 还原（只有状态是已完成才可点）删除。空态「暂无备份记录」。
  • 备份配置：字段 备份类型、Cron 表达式（占位「例如 0 3 * * *（每天凌晨3点）」）、保留天数、启用，按钮 保存配置。

什么时候来：开工时设好「每天凌晨自动备份 + 保留 N 天」，之后基本不用管。要改代码/改结构前，先点一次「立即备份」，给自己留个后悔药。

安全底线三项：强制开启，开关不可关（参数可调）

下面三项是产品设计的安全底线，强制开启、不可关闭，但它们的参数可以调：

  • 资源治理（resource_governor）：预算闸门与限流。可以调日/周/月预算、预警阈值、熔断阈值，但不能整个关掉。
  • 预算熔断：预算耗尽自动暂停循环，防止无感烧钱。它是「资源治理 + 自动运营」共同保证的机制，不能绕过。
  • 渐进式信任（trust_model）：高风险操作要攒信任分、低信任强制人工审核。可以调等级，但不能关。

一句话：「让 AI 更自由」的旋钮有很多，「让 AI 失去刹车」的开关一个都没有。

两点提醒

第一，report 和 auto_report 是两个不同的开关，但界面上显示名都叫「自动报告」，只能靠后面的标识区分；真正让「报告」页打得开的是 auto_report。第二，改完开关如果页面还是报「功能未启用」，先点一下页面右上角的刷新，再确认你选中的项目是不是当前这个项目。

附录 D · 项目侧边栏分组设计说明

为什么产品要把 40 多个页面塞成 6 个分组，而不是按功能平铺？这一节讲清背后的取舍，也给你每个分组的「使用节奏」。

分组依据：项目生命周期，不是功能相似度

如果按「功能相似度」分组，会变成「所有 AI 相关的放一起」「所有钱的放一起」——那样对新手更糟，因为新手的问题是「我现在这个阶段该干什么」，而不是「这个功能属于哪个类别」。所以分组是按一个项目的生命周期排的：

建项与定义还在定方向
→
组织与运营搭班子干活
→
接入与执行接外部世界
→
研究与获客对外拿结果
→
治理与资源老板做决策
→
运维与报告存档与复盘

这不是「越往下越重要」——恰恰相反，越往下越低频但越高权。你日常在中间（组织与运营），偶尔去两头（建项、治理）。

每个分组的典型使用节奏

分组典型使用节奏只看哪一两个页就够

给新手的一个小建议

刚开始用的一两周，别急着把 6 个分组都点一遍。先把侧边栏收起来只留「组织与运营」那一组，把「任务管理 / 人工节点 / 经营日报」三个页面用熟。等你对「AI 一天在干什么、钱怎么花、哪里要拍板」有了手感，再往两头的分组探索。一次学一个分组，比一次吞 40 页舒服得多。
