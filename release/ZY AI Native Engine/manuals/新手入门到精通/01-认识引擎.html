一、一句话说清它是什么

ZY 企业智能引擎，说白了就是给一人公司、中小企业用的「AI 经营班子」。它不只是一个聊天窗口，而是一整套会自己拆目标、自己派活、自己验收、自己记账的运营体系。

你有一个网站控制台（叫大服务平台），登录进去，你旗下每一条业务线就是一个独立项目；每个项目背后，都对应一台独立的项目服务器，上面跑着一支 AI 团队。这支团队不是一个人工智能，而是有岗位分工的智能体（Agent）队伍——有管理者负责协调，有员工负责具体执行。你下达一个目标，它们会按「轮次」自动推进任务，干完由另一个智能体独立验收（防止自己干自己判），再把你花的钱一笔笔记进账本。

先记住三层容器：公司 → 项目 → 任务

公司是「组织容器」——放人、放钱、放全公司共用的知识。项目是「生意容器」——一条业务线就是一个项目，它有自己独立的服务器、独立的预算、独立的账本。任务是「干活单元」——AI 团队按轮次推进的最小对象。你在系统里做的所有操作，都长在这三层结构上。

打个比方：公司是你开的这家店，项目是店里的一条产品线，任务是这条产品线今天要做的一件具体的事。迷路时先问自己一句「我现在在哪一层」，方向立刻清楚。

举个具体例子：你想做一个「跨境电商独立站」。在这个系统里，你先建一家公司，再建一个「独立站」项目；项目背后的 AI 团队会自己把「选品、建站、写商品文案、搭营销页面、做客户问答页」拆成一条条任务，一轮一轮做下去，做完了由独立验收 Agent 把关。你每天只需要登录平台，看看任务跑到哪了、哪些节点要你拍板、花了多少钱。

它和普通 AI 聊天工具有什么不一样

聊天工具是「你问一句、它答一句」，答完就散。这里是「你给一个目标、它自己拆成任务、自己轮流推进、自己验收、自己记账」，你只需要在关键节点点头。所以这本书后面专门有一章讲「发起任务后系统到底做了什么」（第 11 章），还有一章讲「怎么指挥这支队伍」（第 09 章）。

二、三个端，你只碰一个半

这套系统由三个「端」组成。新手最容易搞混的，就是搞不清哪个端该自己操作、哪个端根本不用碰。先把这张表看懂，后面能少走很多弯路。

端 你看到的叫法 它管什么 你要不要直接操作
大服务平台
已上线		 你天天打开的网站 账号、公司、项目、实例生命周期、平台真实账本、超管后台 主要在它上面操作。你 90% 的时间都花在这里
项目服务器
已上线		 每个项目背后那台「独立服务器」 这个项目自己的 AI 循环、任务、知识库、账本、看板。单实例单项目，物理隔离 不用登录，也没有登录入口。它的能力全部由平台页面透传给你
本地边缘客户端
部分可用		 装在自己电脑上的小工具（托盘图标） 扫描你本地电脑上的文档、上传到项目知识库；接收指令跑边缘任务 需要下载安装，但只在「导资料」时用（详见第 07 章）
重要：不要去找「登录项目服务器」的入口

很多第一次用的人，建完项目后就开始找「怎么登录我的项目服务器」。没有这个入口。项目服务器虽然是一台真实的独立服务器，但它不提供给你单独操作的界面——它的一切能力（任务、轮次、知识库、账本、看板）都已经由大服务平台的页面透传出来了。你在平台的项目详情页里点的每一个按钮，背后就是平台替你去指挥那台项目服务器。你只管在平台页面上操作即可。

用一张流向图说清你、平台、项目服务器之间的关系：

你（浏览器）只在网页上点按钮、看结果
→
大服务平台管账号、公司、项目、真实账本，替你转发指令
→
项目服务器跑 AI 团队：拆任务、跑轮次、独立验收
→
AI 团队 / 外部系统写代码、写文案、调模型、连邮箱等连接器
「一个半」是什么意思

「一个」是大服务平台——你天天要打开它。「半个」是本地边缘客户端——只在往项目里导入本地资料、或让它帮你扫描本地文档时才打开一下。至于项目服务器，你「不碰」，它是个后台执行引擎。

边缘客户端的托盘是英文的

它右下角的图标叫 ZY Edge Client，右键菜单是英文：Status: Connected / Disconnected / Connecting... / Reconnecting...（连接状态）、Open Logs（打开日志目录，已可用）、Quit（退出）。Open Logs 点一下会用系统默认程序打开日志所在目录，排障时很方便；原来的「Reconnect」菜单项已被移除——因为程序断线后会自己按退避节奏重连，不需要手动点（所以在旧教程里看到 Reconnect 按钮，是过期信息）。它的详细用法在第 07 章。

进阶：三个端背后是怎么连起来的

技术上，三端用 Go + Vue3 写成，数据库优先 PostgreSQL。你在平台页面上的每一次操作，前端只跟「大服务平台」通信；平台再拿这个项目的实例密钥，用 HMAC-SHA256 签名后转发给对应的「项目服务器」执行——这套「前端 → 平台 → 项目服务器」的转发对你是完全透明的，你不用关心。项目服务器每 30 秒还会用 HMAC 向平台上报一次心跳（健康状态、任务队列、CPU/内存/磁盘），让超管后台能看到每台实例是「正常 / 降级 / 宕机」。本地边缘客户端则直接连项目服务器上传文档，不走平台转发。

三、它能替你做哪些事（三档授权）

AI 不是「什么都能干」，也不是「干什么都要问你」。它把事情分成三档，取决于这件事的风险高低：

第一档 · AI 完全自主做

无需你确认

  • 把一个大目标拆解成一条条可执行的任务
  • 写代码、写文案的初稿，跑任务循环
  • 做总结、写日报、整理知识库
  • 在项目内部检索资料、调用模型、跑分析

这些是纯「内部生产」动作，不对外、不花钱、不改系统，AI 直接干。

第二档 · 需要你点头才做

人在回路

  • 对外发布内容、发营销邮件
  • 花钱、调用第三方付费接口
  • 删除、覆盖、装软件等敏感动作
  • 人工处理节点里 L2（一键确认）/ L3（强制人工审核） 的环节

这些有对外影响或资金风险，AI 会停下来，把节点推到「人工处理节点」页等你批。

第三档 · 永远不替你做

红线

  • 方向判断：这生意该不该做、往哪转型
  • 预算给多少：你愿意投多少钱，AI 不替你拍板
  • 是否雇人 / 增员确认：扩编要你人工确认
  • 对外承诺：对客户、对合作方的任何承诺

这些是「老板」的职责，系统只负责执行，不替你当老板。

三档和三通道是一回事的两个说法

系统里还常用「红 / 黄 / 绿三通道」来标记一件事的风险：红 = 强制人工，黄 = 敏感需确认，绿 = 例行通知。你只要记住：越靠近「对外、花钱」的动作，越会落到需要你点头的那一档；越靠近「内部生产」的动作，AI 越自主。真正决定「这个动作归哪档」的是权限模型（第 14 章）与自主级别 L0–L3（第 04 章）。

一句话记住三档

内部的它自己干，对外的它先问你，当老板的事它绝不碰。这套「分级授权」机制在系统里叫渐进式信任——AI 表现越好、你越信任它，它获批的自主权限就越大（详见第 04 章和第 14 章）。

四、它做不到什么（边界要讲透）

这一节很重要，请认真读。知道它「不做」什么，比知道它「做」什么更能帮你避免失望和误判。

它能做的

  • 在项目内部拆任务、写初稿、跑循环、出报告
  • 按你的指令对外发内容、发邮件（但要你批准）
  • 把账目记进账本，算 token 成本，触发预警

它做不到的（别指望它）

  • 不会替你做战略决策：它给建议，方向你来定
  • 不会自己去银行收款：账本要你记，或对接支付
  • 生成的内容发布前要审批，不是一键发出去
  • 不能一键导入任意第三方系统（比如整个 WordPress 站点），只能按支持的连接器逐个接
  • 对无法用文字验证的交付（如线下施工），只能管任务、不能替你施工
进阶：为什么不能「一键导入整个网站 / 任意系统」

系统接入外部系统走的是「连接器（MCP）」，每个连接器都要单独配置，而且写操作必须人工审核——这是为了安全，不可能也不应该有一个「读懂任意第三方系统」的万能接口。所以像「把整个 WordPress 站点一键搬进来」这种事，当前版本没有入口。你需要按第 06、07 章的方式，把关键资料导成文档或文本后让 AI 整理，或逐个接入系统支持的连接器。

关于「有成本」这件事

它不是免费的。AI 每调用一次模型、每生成一张图、每跑一台云服务器，都在花钱（token 计费 + 云服务器费 + 媒体生成费）。但系统有一套「80% 预警 → 超限熔断」的保险，让你不会在不知情的情况下把钱烧光。具体见本章第八节。

五、三种人怎么上手

这本书的读者主要有三种。对号入座，看你第一周该做什么。

OPC 一人公司 CEO

没有团队、预算有限，想有一个「像真公司一样会成长」的 AI 班子。

第一周该做：

  1. 注册账号，创建第一家公司（第 02 章）
  2. 建一个最小的项目，运行模式留在「半自动」（第 03 章）
  3. 下第一个任务，盯着它跑完看验收结论（第 09 章）
  4. 把本地已有的资料导入知识库（第 07 章）
  5. 看一版经营日报，理解钱花在哪（第 13 章）

企业里的管理团队

已有线下业务，老板 + 运营 + 产品一起，想用 AI 接管流程、内容与客户跟进。

第一周该做：

  1. 注册并建公司，把团队成员邀请进来（第 02 章）
  2. 建项目时先导入老资料，别从零开始（第 07 章）
  3. 把运行模式设为「人工审核」，先看清 AI 每一步（第 04 章）
  4. 给关键角色配好智能体与技能（第 08 章）
  5. 约定好谁盯哪些经营指标（第 13 章）

手上已有项目要上线

有现成代码、文档、聊天记录，想导入而不是从零开始。

第一周该做：

  1. 用「项目导入」把既有资料整体导进来（第 03、07 章）
  2. 确认 AI 生成的「执行策略」后再启动（第 03 章）
  3. 要加复杂软件功能，走「软件工程向导」（第 10 章）
  4. 跑通一次「连接器」接外部系统（第 06 章）
  5. 发布前对照红线检查清单（第 19 章）

六、一次完整闭环长什么样

为了让你对「整个过程」有个整体感，这里走一遍最典型的闭环。每一步右边注明了它在哪个页面看。

  1. 有想法

    你想清楚「要做什么生意」，一句话能说清目标客户。这一步在你自己脑子里，不在系统里。

    你 → 第 01 章（本章）

  2. 建公司

    登录后建公司，填名称、行业、描述。公司是组织容器。

    公司管理 › 创建公司

  3. 建项目（向导）

    在项目管理里新建项目，走「基本信息 → 预算设定 → 确认提交」三步。这一步会决定项目的行业、类型、运行模式。

    项目管理 › 新建项目

  4. 确认执行策略

    AI 基于你给的信息，生成一份「项目执行策略」。你确认后，自动运营才允许启动。

    AI 问答 › 引导建项

  5. AI 拆解任务

    AI 把项目目标拆成一条条任务，排进时间片队列。

    自动运营 › 任务管理

  6. 轮次推进

    AI 按「轮次」轮流推进每个任务的一个时间片，一轮一轮往前拱。

    自动运营 › 运行轮次

  7. 独立验收

    任务干完，由另一个独立验收 Agent 给出「通过 / 返工 / 驳回」，不是你判，也不是干活的 AI 自己判。

    自动运营 › 验收记录

  8. 成果上线

    通过验收的产出（代码、文案、页面）被部署或交付。

    项目详情 › 服务器实例

  9. 获客 / 内容

    营销引擎开始产出并发布内容（发布前要你批准），连接器对接邮箱等外部系统。

    自动运营 › 经营日报

  10. 经营日报与复盘

    每天生成经营日报，看收入、成本、任务完成率、预算消耗率。

    自动运营 › 经营驾驶舱

  11. 增员或收缩

    组织进化引擎根据数据建议「增员 / 扩容」，你人工确认后才落地。

    组织与运营 › 组织进化
这 11 步不是一次性走完

它是一个循环。跑完一轮，你会根据日报和复盘注入新信息，AI 再重排任务，继续下一轮。这正是「自动运营」的含义——不是一次跑完就停，而是持续地、一轮一轮地经营下去。

七、开工前你要准备什么

开始之前，把下面这些想清楚、备齐，能让你少返工。照着勾：

  • 一句话说清要做什么生意（做什么、卖给谁、为什么选你）
  • 公司名称（后面能改，但先想一个）
  • 行业类型（软件 / 电商 / 内容 / 制造 / 通用，选哪个会影响 AI 默认行为）
  • 一个能收邮件的邮箱（注册、接通知都用它）
  • 愿意先投入的月度预算（起步期典型量级见第八节，先有个数）
  • 要用的域名、已有账号等资产（比如已有的独立站域名、邮箱账号）
  • 本地待导入的资料目录（旧文档、聊天记录、会议纪要，导入方法见第 07 章）
「这些信息填错了能改吗？」

这是全书反复回答的问题。简单说：公司名称、行业、项目名称、描述、预算大多能改；但「行业类型」和「项目类型」会影响 AI 一开始的拆解思路和默认行为，建议第一次就认真选。逐项的「改后影响」在第 02、03 章讲得很细。

八、成本到底怎么算

钱花在三条线上，分开看就不慌：

1. Token 计费

AI 每调用一次模型就按 token 计费。默认单价（可在项目「运行配置 → 定价」里改）：

  • 输入 1 元 / 百万 token
  • 输出 2 元 / 百万 token
  • 缓存读 0.02 元 / 百万 token

2. 云服务器费用

每个项目背后有一台独立的项目服务器，这台服务器的租用费。规格、地域、厂商不同价格不同，按「服务器」额度单独核算。

3. 媒体生成费用

生成视频、图像、歌曲时按「档位单价 × 用量」折算，计入项目账本。未定价的档位会显示 [待定价]，不折算、不谎报金额。

阶段 典型月成本（估算） 这个量级在干什么
起步期 约 $10–30 一个人跑一个项目，少量 token + 一台小规格服务器
成长期 约 $50–150 多个任务并行、内容营销上量、开始生成媒体
规模化期 约 $200–800 多个项目、更大并发、更多外部连接器调用
成熟期 约 $500–2000+ 多业务线并行、组织自动扩编、媒体与模型高频使用
上面的数字是估算值，不是承诺

这张表来自产品文档里的阶段性估算，用来帮你建立「量级」的概念，不是实际账单。你的实际花费取决于任务量、模型调用频率、媒体生成量、服务器规格，差别会很大。真正的账单以平台「公司账本」和项目「计费明细」为准。

让你安心的三道保险：80% 预警 → 超限熔断 → 补充后恢复

系统不会让你在不知情的情况下把钱烧光：

  1. 80% 预警：预算用到 80%，系统发通知，并自动降级运行（放慢、收缩），不是直接停。
  2. 超限熔断：预算耗尽，暂停循环，AI 不再继续烧钱。
  3. 补充后恢复：你充值或调高预算后，到「自动运营控制台」点 恢复 或 启动 继续。

另外，计费里有一小部分「按文本长度估算的兜底计费」（上游没返回用量时产生），它不是精确账单，别拿它当发票核销。详见第 04 章。
