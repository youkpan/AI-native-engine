二、账号与公司（Q1–Q10）

Q1. 我注册了，但一直没收到验证邮件，是不是注册失败了？

不是。当前注册流程不需要邮箱验证——你在注册页填完「用户名 / 邮箱 / 密码 / 确认密码」点注册，系统直接提示「注册成功，请登录」并跳回登录页。所以压根没有「等验证邮件」这一步。

如果注册没成功，真正的原因通常是这两种：邮箱已被注册（提示「用户已存在」，那就直接去登录）；或者字段没通过校验（用户名 1–64 位、密码 6–64 位、两次密码要一致、邮箱格式要合法）。

邮箱不是随便填的

邮箱就是你以后的登录账号，也是系统识别「你是谁」的唯一凭据。用户名只是显示名，可以重复、可以改；邮箱一旦注册就唯一。请填你长期在用的真实邮箱，别用临时邮箱。

相关：见第 02 章「从注册到登录」。

Q2. 建公司时行业选错了，会不会影响 AI 干活？

结论：不影响，而且随时能改。公司这一层的「行业类型」目前只用于展示和统计（我的公司列表里的「行业」列、超管按行业搜索），不会注入到 AI 的执行逻辑里，不影响模板推荐、也不影响 AI 策略。

想改就去改：

公司管理 › 公司设置 › 行业类型 › 保存修改

注意这里已经变成自由文本框，可以输入任意文字，不必局限在建公司时的 14 个下拉选项里。

别和项目里的「行业」搞混

真正可能影响 AI 的，是项目里那个另建的「行业」字段（自由文本，建项目时自己填）。公司行业和项目行业是两回事，填错公司行业不用慌。

相关：见第 02 章「这些信息对后续有什么影响」、第 03 章字段影响表。

Q3. 公司名称能改吗？改了会不会出问题？

能改，代价极低。路径：

公司管理 › 公司设置 › 公司名称 › 保存修改
保存成功会提示「保存成功」，系统内即时生效。

公司名称会出现在「我的公司」列表、顶栏公司切换器、面包屑、公司账本等处，也可能成为对外内容署名的一部分。改名本身没有历史成本，但如果你已经在对外材料（名片、邮件签名、宣传页）里署了旧名，那些站外的地方要你自己同步改。

口诀：名称是招牌，不是指令

公司名称只是标识，不会改变 AI 的行为。所以起名时想的是「客户看了认不认」，不用琢磨「怎么写才能让 AI 更聪明」。

相关：见第 02 章、Q10（多公司）。

Q4. 我最多能建几家公司？

系统层面对公司数量没有硬性上限，你想建几家都行。但这不是「多多益善」——建议按业务主体来划：不同业务主体、需要隔离风险和账的两摊生意，才值得各建一家公司。

判断标准就三条：是不是不同业务主体（跨境电商 vs 咨询业务）；要不要分开核算（财务或战略上要分开算）；要不要隔离风险（一条线出问题不牵连另一条）。满足任一，就分开建。

早期别拆一堆空壳公司

公司是组织容器，项目才是生意容器——同一家公司下可以挂多个项目。一上来就建好几家公司，注意力全分散了，反而不如先把一条业务线跑通。真出现第二个业务主体再开也不迟。

相关：见第 02 章「多公司的用法」、Q10。

Q5. 怎么邀请同事加入公司？

路径：

公司管理 › 成员邀请 › 生成邀请
弹窗里可以填「邮箱」（留空则不限邮箱，谁拿到码都能用）和「角色」（管理员 / 普通成员 / AI Agent），点「生成」，成功提示「邀请生成成功」。

然后把邀请码或链接发给对方，对方注册/登录后通过「接受邀请」加入公司。列表里能看到「邀请码 / 邮箱 / 角色 / 状态 / 过期时间」，状态分待接受 / 已接受 / 已过期。

这里选不了「超级管理员」

邀请弹窗的角色只有管理员 / 普通成员 / AI Agent 三种。超级管理员不能通过邀请发放，只能由公司所有者在「成员管理 → 编辑成员」里授予。另外，只有所有者或管理员才能管理邀请，其他人看到的是一条「仅公司所有者/管理员可管理邀请」的提示。

相关：见第 02 章「成员邀请」、第 14 章（团队与治理）。

Q6. 邀请码过期了怎么办？

重新生成一个就行。邀请码的有效期是 7 天，超过就变成「已过期」状态，对方再点会失败。

做法：

公司管理 › 成员邀请 › 生成邀请
生成一条新的，把新码发出去。列表里旧的那条会显示「已过期」，可以直接忽略，不影响新码使用。

过期不是故障

7 天有效期是刻意的安全设计——邀请码相当于一张短期门禁卡，长期有效会变成风险。所以别把邀请码贴在群里长期挂着，也别为了「永久有效」反复折腾，直接重新生成即可。

相关：见第 02 章、Q5。

Q7. 怎么把某个权限单独给同事，而不是让他当管理员？

用权限矩阵逐项开。

公司管理 › 成员管理 › 编辑 › 权限
里面有 14 项权限开关：通用 11 项（读 / 写 / 运行任务 / 花钱 / 外发邮件 / 装插件 / 装软件 / 加 MCP / 优化提示词 / 运行命令行 / 调权重）+ 管理 3 项（暂停项目 / 暂停任务 / 用户管理，仅人类可选）。

默认分配是：超级管理员和管理员拿满 14 项，普通成员和 AI Agent 只有 11 项通用权限。

层级门控：你不能改平级或上级

点「编辑」或「移除」时，如果对方层级不比你低，按钮会被禁用并提示「无权管理该成员：需公司所有者，或角色层级高于对方」。另外，界面上 AI Agent 拿不到那 3 项管理权限，选了会提示「AI Agent 不可授予管理权限」。部分可用要如实说：当前这层限制做在前端，后端强制拦截仍在排期中，别把它当成一道服务端已生效的防线。

相关：见第 02 章「成员与权限速查」、第 14 章。

Q8. 我能把公司转让给别人吗？转让后还能收回吗？

能转让，但不能收回。

公司管理 › 公司设置 › 转让与解散 › 选择公司成员 › 确认转让
确认弹窗原文是「确定要转让公司所有权吗？此操作不可撤销。」

转让后，对方成为所有者（最高权限），你不再是最高权限。所有者才能解散公司、再次转让、授予超级管理员，公司的项目和计费主体也挂在所有者名下。

这是不可撤销操作

转出去就收不回来了，系统没有「撤销转让」的按钮。点之前务必确认对方是可信的团队成员。千万不要把它当测试点着玩。

相关：见第 02 章「公司设置」、Q9。

Q9. 解散公司会发生什么？数据还能找回来吗？

解散后无法恢复。界面说明原文是「解散后公司将无法恢复，所有数据将被软删除。仅所有者可操作。」按钮是红色的「解散公司」，需要二次确认。

注意「软删除」这个词——它指的是数据被标记为删除、从你的正常视图里消失，但对普通用户来说效果就是没了，系统没有给你一个「回收站」去恢复。所以别把「软删除」理解成「随时能撤回」。

先停一停再决定

想停掉一条业务线，正确做法是暂停或停止项目（可逆），而不是解散公司（不可逆）。只有当你确定这个公司主体彻底不要了，才用解散。而且这一步只有所有者能做。

相关：见第 02 章、Q8、Q19（项目能不能删）。

Q10. 我一个人能同时管几家公司？怎么切换？

可以同时拥有/加入多家公司，没有数量限制。切换用顶栏的公司切换器：placeholder 是「选择公司」，第一项固定是「全部公司」（等于不指定公司），下面是每一家你加入的公司。

选中某一家，它就变成「当前公司」，之后建项目、看知识库、进账本都会落在它下面。选「全部公司」相当于清空当前公司，各处的数据会变成跨公司汇总或不指定。切换公司时系统会顺手清掉残留的项目上下文，避免串台。

口诀：切公司 = 换桌面

看到「新建项目」按钮变灰、知识库提示「请先在顶部选择公司」，八成就是当前没选公司。先看顶栏，再操作。

相关：见第 02 章「多公司的用法」、Q4。

三、项目与预算（Q11–Q20）

Q11. 建项目必须先建公司吗？能不能只建项目？

必须先有公司。项目不是独立存在的，它一定要挂在某家公司下面——公司是「组织容器」（放人、放钱、放共用知识），项目是「生意容器」（一条业务线，独立服务器、独立预算、独立账本）。

不选公司会出现两个拦截：项目管理页顶部黄色提示「请先选择或创建一个公司」，同时「新建项目」按钮变灰；就算你绕过它打开向导，点到最后一步「提交创建」时也会弹「请先选择公司」，不让提交。

口诀：公司 → 项目 → 任务

这是三层容器，迷路时先问自己「我现在在哪一层」。建项目前的第一个动作，永远是回头看顶栏公司切换器选对了没有。

相关：见第 03 章「建项目前必须知道的一件事」、Q10。

Q12. 项目类型和行业会影响 AI 干活吗？选错要不要紧？

不影响执行逻辑，选一个最接近的就行，拿不准就选「通用业务」。「项目类型」有五个选项（软件开发 / 电商运营 / 内容创作 / 智能制造 / 通用业务），「行业」是自由文本。两者当前都不参与自动运营的执行逻辑——不会因为选了「软件开发」就让 AI 自动去写代码。

它们的实际用途只有三处：项目列表上的分类标签；提示词模板按类型和行业做筛选；走「引导建项」时作为项目档案的种子信息喂给 AI。所以它是「分类口径」，不是「开关」。

真正影响 AI 的是描述和目标

向导里描述和目标才是真正喂给 AI 的强影响字段：AI 据此生成执行策略、拆初始任务、判断优先级。类型行业随便填，描述目标要花心思。

相关：见第 03 章字段影响总表、Q13。

Q13. 项目描述和目标写错了 / 写少了，还能改吗？

能改，但要知道改完有一个「不会自动生效」的坑。

项目详情页 › 编辑
在这里改描述、目标、名称、类型、行业、运行模式都可以。

关键区别在于：名称 / 类型 / 行业改了只是换个标签，影响很小；描述和目标改了，AI 不会自动重读。它们当初是在「引导建项」时被写进项目上下文、用来生成策略的，你改了字段本身，不等于 AI 已经重新理解。

想让它按新描述重来，要再推一把

两个办法：①给任务补充信息（在任务「编辑」里改任务级提示词模板，把新要求追加进去——注意任务「描述」创建后不可修改，它是独立验收的对照依据）；②重新走一遍「引导建项」，让它按新的描述和目标重新拆任务。只改字段不推这一把，AI 可能还按老理解干。

相关：见第 03 章、第 09 章「中途想补充信息怎么办」、Q48。

Q14. 预算到底填多少合适？我第一次建项目完全没概念。

没有标准答案，但有一条硬建议：先少后多。第一次把 AI 运行预算设成一个「烧穿了也不心疼」的数（比如起步期先设个几百元），跑顺了、看懂了钱花在哪，再逐步调高。宁可先熔断一次、补预算，也别一上来设「不限制」。

向导第二步的默认值是：总预算 1000、Token 月度额度 500、图片 100、视频 0、服务器 500（单位：元）。按组织阶段的量级参考是：起步期约 $10–30/月、成长期约 $50–150/月、规模化期约 $200–800/月、成熟期约 $500–2000+/月。

这是量级参考，不是账单

实际花费取决于任务量、模型调用频率、媒体生成量、服务器规格，差别很大。真正的账单以公司账本和项目计费明细为准。另外有三道保险是强制开启、关不掉的：资源治理、预算熔断、渐进式信任——你能调的是给多少钱，不是要不要这道闸。

相关：见第 04 章「预算装在三个口袋里」、Q15、Q16。

Q15. 预算里填 0 是什么意思？是没钱还是无限？

0 表示不限制，不是「没钱」。向导预算设定页顶部那行说明原文就是：「预算单位为人民币（元），0 表示不限制」。也就是说，某项额度填 0，就等于这条预算线不会触发熔断。

五个额度项分别是：总预算（覆盖所有支出）、Token 月度额度（AI 运行预算）、图片额度、视频额度、服务器额度。视频默认就是 0——意思是「不限制视频生成」，如果你不打算做视频，这个 0 其实等于没设防。

新手建议别用 0

0 虽然省事，但等于把这道闸门敞开。正确姿势是给每个你真正会用到的额度都填一个具体数字，用一个「烧穿也不心疼」的小数先跑起来。看到某条额度是 0 时，心里要清楚它是「无限」而不是「关闭」。

相关：见第 04 章、Q14、Q16。

Q16. 预算花超了会怎样？会不会突然就停了？

不会「突然」停，它有预警缓冲。整条链是四步：预警 → 熔断 → 补预算 → 恢复。

AI 运行预算用到预警线（默认 80%）时，系统发通知提醒并自动降级运行（切低成本模型、放慢节奏）先稳住；真的耗尽（AI 运行预算或总预算任一条超限）才熔断——暂停循环，界面显示「已熔断」、控制台「熔断：是」。此时你补预算，再去控制台点「恢复」或「启动」，系统复核两条预算线确实解除后清掉熔断标记继续跑。

熔断后不补钱，点「恢复」是没用的

如果预算仍然超限，点恢复会被拒绝，提示「预算已耗尽，请补充预算后继续」。顺序永远是先补预算，再点恢复。另外，两条熔断线（AI 运行预算线、总预算线）是分开的，哪条先到哪条先停。

相关：见第 04 章「预算的一生」、Q76。

Q17. 项目跑着跑着钱不够了，怎么加预算？

两个入口，按你缺的是哪种钱来选。缺项目预算（额度），去：

项目详情页 › 预算明细 › 调整预算

缺平台账户余额（真钱），去一级菜单「公司账本」点「充值」。另外，资源治理页也有「设置预算」（日 / 周 / 月 / 总额度、预警阈值、熔断阈值），控制台还能调整预算科目。

加完钱别忘了点「恢复」

预算补上不等于项目自动重启——如果之前已经熔断暂停，还要到自动运营控制台点「恢复」或「启动」。只加钱不点恢复，项目还是停着的。别把「解除熔断（临时）」当日常操作，它只是这一次先过去，不改规则。

相关：见第 04 章、第 06 章「资源治理」、Q76。

Q18. 项目能暂停多久？放一个月不管会不会坏？

暂停本身没有时限，停多久都行，服务器也不会因为你停着就自动清掉。但「放很久再回来」有一个你要知道的机制：系统按「断了多久」区别对待恢复方式。

豁免期（默认 2 天）内恢复，不做 AI 评估，直接干净续接。超过豁免期，系统会先做环境漂移检查（代码有没有改、依赖有没有变、凭据有没有失效、数据库结构有没有动、知识库有没有更新），再按中断时长分级（小于 7 天 / 7–30 天 / 超过 30 天），给出三种结论之一：直接续接、调整后续接、重新规划。

断得越久越要「重新对齐」

像出差两周回来，客户需求、代码、API Key 都可能变了。所以长期停摆后恢复，别指望它一定「接着上次的原样干」——它可能会重排任务。这些评估结论和最终决定都会留痕，方便回看。

相关：见第 09 章「中断恢复」、第 04 章。

Q19. 项目能删掉吗？不想要了怎么彻底结束？

当前项目详情页头部的按钮是：返回 / 启动 / 暂停 / 恢复 / 停止 / 标记完成 / 编辑——里面没有「删除项目」。想让项目不再跑，用「停止」（硬停循环，服务重启也不会自动拉起）；想正式收尾，用「终止项目」。

「终止项目」会要求你填写终止原因，然后把项目置为终止态（不再有新轮次），并自动生成一份结项报告（目标达成率、任务完成率、验收返工率、Token 花费、收入、ROI、知识沉淀、经验总结）。

终止不可逆，等价于「正式结项」

只是想让项目歇一歇，请用暂停（可恢复）或停止（需重新启动），不要用终止。项目删除入口当前界面上没有，若后续版本开放，以实际界面为准。

相关：见第 04 章「终止项目与结项」、第 09 章、Q9。

Q20. 一个公司下面能建几个项目？

数量上没有限制，想建几个建几个。但要记住一条成本事实：每个项目对应一台独立的项目服务器（单实例单项目物理隔离）。好处是项目之间数据隔离、互不影响，一个跑崩了不牵连另一个；代价是每个项目都要一台服务器，是要花钱的。

所以「一个公司能建几个项目」的真实约束不是系统限制，而是你的服务器成本和注意力。同一家公司下挂多条业务线是正常用法（公司是组织容器，项目是生意容器）。

新手建议：一次只跑一个项目

第一个项目没跑顺之前，别急着开第二个。多开一个项目 = 多一台服务器 + 多一份预算 + 多一摊要盯的账。等第一条业务线跑通、你知道该看哪些指标了，再复制到第二条。

相关：见第 03 章「服务器实例是怎么来的」、第 13 章（经营指标）。

四、运行模式与自主级别（Q21–Q30）

Q21. 全自动和半自动到底差在哪？听起来差不多。

差别只在「关键决策要不要你点头」。半自动下 AI 照样自动干活，但碰到目标变更、大额支出、对外动作这类关键节点，会停下来等你确认后继续；全自动下这些也不等你，只在关键节点通知你一声。

三种模式的官方解释原文：全自动「AI 自动拆解任务、调度轮次、评审验收，全程自动执行，仅在关键节点通知你」；半自动「AI 自动执行，但在关键决策节点（目标变更、大额支出、对外动作等）由人工确认后继续」；人工审核「AI 产出方案后必须人工审核通过才执行，节奏较慢但最可控」。

半自动不是「AI 少干活」

很多人误以为半自动=AI 干一半。不是。半自动是速度一样、关卡更多。第一周建议就用半自动，你能看懂 AI 的行为逻辑，再决定要不要放开。

相关：见第 04 章「三种运行模式」、Q23。

Q22. 建项目时选了「手动」，进项目后看到「人工审核」，是两回事吗？

指的是同一种模式，只是两个界面的叫法不一样。新建项目向导里这一项的选项是全自动 / 半自动 / 手动；进项目后在自动运营控制台「调整运行模式」里，同一档叫人工审核。别以为项目里冒出了第四种模式。

记住一句话就行：创建时叫「手动」，进项目后叫「人工审核」。两处可以随时互相切换，切换不影响项目已有数据。

选了它，AI 不会自己动

只有全自动 / 半自动会启用自动运营循环。选了人工审核，系统不自动跑循环，任务靠你手动触发、AI 产出方案后等你审核。所以「想让它自己动起来」，就别选人工审核。

相关：见第 04 章、第 03 章、Q91。

Q23. 什么时候该从全自动切回人工审核？

四种情况该切回去：①它开始做你不确定的事（比如要对外发邮件、动生产数据）；②业务进入高合规期（结算、对外承诺、合同相关）；③你刚改了方向或目标，想看清它怎么理解；④你暂时不想它花钱。

切法：

自动运营控制台 › 运行模式卡片 › 修改 › 人工审核
切换时界面会提示原文：「切换后将暂停自动运营循环，仅保留人工审核驱动的执行，可在之后重新启动或调整」。

切完循环就停了

这不是报错，是设计行为。想让它重新自己跑，得再切回全自动 / 半自动并点「启动」。如果你的目的是「临时叫停一下」，其实用「暂停」更轻——暂停不改变模式，恢复后接着原来的进度干。

相关：见第 04 章、第 09 章「运营控制台」、Q18。

Q24. L0–L3 是什么？我该关心吗？

L0–L3 是自主级别，管的是「某一件具体的事，要你多重的确认」。它和运行模式不是一层东西：运行模式管整个项目的节奏，自主级别管单个人工处理节点的松紧。

四个级别的行为：L0 全自主执行，不创建节点、不通知；L1 通知不等待，AI 继续推进；L2（默认） 一键确认，AI 暂停等你点一下；L3 强制人工审核，必须审核通过（可多人 / 审批流）才继续。你在「人工处理节点」页每张卡片上都能看到「自主级别 L{n}」。

三通道和自主级别会叠加

除了级别，还有按风险分颜色的三通道：绿=例行（按级别处理）、黄=敏感（生成权限租赁，超上限需你授权）、红=强制（命中禁止清单，强制 L3，AI 不得代行）。所以「会不会停下来问你」是级别 + 通道共同决定的。

相关：见第 04 章「AI 什么时候停下来等你」、第 14 章。

Q25. 默认是哪个级别？我需要调吗？

默认是 L2（一键确认）——AI 停下来，等你点一下才继续。控制台的「自主级别」卡片显示的就是这个当前值。对绝大多数新手来说，默认值就是最合适的，不用动。

什么时候才需要调？只有两种情况：你非常确定某类例行动作完全不用打扰你（可考虑 L1 或 L0，但要想清楚）；或者某件事你要求正式审批流（L3）。调级别是在新建人工处理节点时选的，不是全局一个开关。

调级别 = 调「打扰频率」

级别越高（L0/L1），AI 越自由、你越省心，但也越容易在你没看见时做错事；级别越低（L3），最可控但节奏最慢。新手阶段，把注意力放在提示词和任务描述上，回报比调级别高得多。

相关：见第 04 章、Q24、第 08 章「运行配置」。

Q26. 怎么让 AI 别自己发邮件给客户？

三重防护，建议都做：①模式留在半自动或人工审核（对外动作会停下来等你）；②确认它的「外发邮件」权限状态（权限矩阵里的 send_email，以及黄通道对敏感写操作的拦截）；③别把权限模式切成 auto-run（角色运行配置里 auto-run 表示自动执行不等人，默认是 approve 审批模式）。

另外记住一条设计事实：对外动作属于触发人工节点的四类动作之一（另外三类是花钱、敏感改动、改方向）。所以只要模式不是全自动、或对方动作走了黄通道，AI 就发不出去，得等你点头。

auto-run 是高危开关

不要为了图省事把权限模式切到 auto-run。让 AI 未经确认就自动发邮件、自动改生产数据，风险远大于你省下的那几次点击。项目级默认就是审批模式，保持它。

相关：见第 08 章「运行配置（RunConfig）」、第 04 章「三通道：按风险分颜色」、Q23、Q27。

Q27. 有一次必须让 AI 做件敏感的事，怎么临时给它放权？

用权限租赁——给它一张「有期限、有金额上限」的临时通行证，而不是长期放开。

自动运营控制台 › 权限租赁 › 新建授权

新建字段有：Agent（被授权 Agent ID）、授权动作（如 send_email(to=customer@x.com)）、任务 ID、授权范围、成本上限、过期时间。列表里能看到「Agent / 授权动作 / 授权范围 / 成本上限 / 授权人 / 状态 / 过期时间」，操作列有「续期 / 吊销」。

授权要写到具体动作，别写「全部」

截图里的示例是把动作写得很具体（发给哪个邮箱）。你写得越具体，这张通行证能覆盖的范围就越小，风险越低。另外，每次授权都会留痕（授权人、过期时间都在列表里），事后可查。

相关：见第 04 章「三个旋钮」、第 14 章、Q28。

Q28. 权限租赁什么时候过期？会不会一直有效？

不会一直有效——它按期 + 按额双重回收。你在新建授权时填的「过期时间」到点就失效；「成本上限」用满也会自动收回。列表状态有三种：生效中 / 已吊销 / 已过期，你可以随时手动「吊销」或「续期」。

如果你没设过期时间（或以实际界面为准），就等于是长期放行——所以切记填一个明确的过期时间，哪怕只给一天。

权限租赁 vs 自主级别，别搞混

一句话区分：自主级别是长期人设（这个 AI 平时要不要等你），权限租赁是一次性通行证（这一次放它做一件敏感事）。还有一个「渐进式信任」是按表现给权限的评分机制。三者叠加才构成 AI 的自由度。

相关：见第 04 章、第 06 章「渐进式信任」、Q27。

Q29. 能不能让 AI 只做不花钱的事，一分钱都不许花？

做不到「绝对不花钱」，因为 AI 每干一次活都要调模型，调模型就产生 token 费用——这是它的「燃料」。但你可以把支出压到很低、并且设死上限：把 AI 运行预算设成一个很小的数（比如几十元）；优先用「Agent 智能体」引擎做轻量短活；关掉或不用媒体生成（图片 / 视频最费钱）；把任务描述写清楚，减少返工轮次。

真正的兜底是预算熔断：花到线就暂停循环，不会无上限烧。这也是三道强制开启、关不掉的安全底线之一。

「免费跑 AI」不存在，只有「便宜地跑」

如果预算设成 0（不限制），反而等于把闸门敞开——那就不是「不花钱」，而是「不设防」。想控成本，设一个具体的小数字，而不是填 0。

相关：见第 04 章、第 09 章「计费明细」、Q75（怎么省钱）。

Q30. 出大事了，怎么一键停掉所有 AI？

用紧急停止（KillSwitch）。路径：

项目内 › 组织与运营 › 审计治理 › 紧急停止（KillSwitch）

确认原文是「紧急停止所有自动运营任务？此操作不可逆」。它的效果等价于「停止」：硬停循环、状态置为已停止，服务重启也不会自动拉起。

红色按钮，想清楚再点

①它是不可逆的，点了之后要重新走「启动」流程才能恢复；②日常临时叫停请用「暂停」（可恢复、不丢上下文），KillSwitch 只留给「AI 正在做明显危险的事」这种极端情况；③停掉之后不要马上重启，先去看日志和验收记录，搞清楚它刚才在干什么。

相关：见第 09 章「紧急停止」、第 06 章、Q91、Q100。

五、智能体与组织（Q31–Q40）

Q31. 我建了一个项目，AI 团队会自动配好吗？还是要我自己一个个建 Agent？

不需要你一个个手建。项目创建后，系统会按你选的项目类型和行业，生成一套默认的智能体组织：一个管理者 Agent 带若干员工 Agent，各自挂好岗位档案和初始技能。你要做的是「审一遍、再调」，而不是「从空开始搭」。

做检查的路径：

项目内 › 组织与运营 › 智能体组织

看到组织架构后，重点看三件事：①有没有哪个岗位明显缺人（比如做电商却没有运营岗）；②每个 Agent 的职责描述是否贴合你的业务；③技能栏是不是空的——技能库没有内置种子，空是正常的，需要后天装配或从具体经验里沉淀。

口诀：先审后调，不要推倒重来

默认组织是可用的起点，不是必须替换的模板。大多数人只需要补一两个岗位、改几段职责描述，就能开工。

相关：见第 08 章「管理者 Agent 与员工 Agent」、Q32、Q36。

Q32. 管理者 Agent 和员工 Agent 到底差在哪？

一句话：管理者只管协调，不下场干活。管理者 Agent 负责拆任务、排时间片、盯进度、做复盘、在需要时把任务指派给合适的员工；员工 Agent 才是真正执行具体活的角色。

这个分工带来一个很实用的好处——你改组织结构，不会影响单个员工的专业能力。比如你想让某个员工专注写代码，就把他从杂事里摘出来，管理者的协调逻辑不用动。

别把活派给管理者

如果你发现「管理者 Agent 自己在写文案」，通常不是设计问题，而是员工 Agent 缺技能或任务没拆细，管理者只能顶上去。这时候该去补员工的能力，而不是让管理者继续下场。

相关：见第 08 章、Q31、Q34。

Q33. 技能（Skill）是什么？技能库里有现成的吗？

技能就是「一个 Agent 会做的一件具体事」——比如写产品文案、做数据清洗、调某个接口。技能挂到 Agent 身上，Agent 才知道自己有哪些手段可用。

技能库没有内置的现成技能种子，打开时是空的，这是正常的。技能主要来自两个途径：①你在项目里给 Agent 手动装配；②组织进化引擎从实际执行经验里沉淀出可复用的技能，建议你装配。

口诀：技能是长出来的，不是发下来的

先让项目跑起来，用着用着，好用的做法会被沉淀成技能。一开始就追求「技能库满满当当」，反而是本末倒置。

相关：见第 08 章「技能库与技能装配」、Q34、Q36。

Q34. 把技能「提升为组织级」是什么意思？为什么还要审批？

技能默认只在某个项目、某个 Agent 范围内用。把它「提升为组织级」，就是让它变成整个公司可复用的公共技能，别的项目、别的 Agent 也能挂上。

因为影响面从「一个项目」扩大到「整个公司」，系统不让你一键生效，而是生成一条申请，进入一个人工确认节点，原文提示是「需人工审批确认后生效」。你确认之后，其他项目才能引用它。

提升前先问一句：这东西别人能用吗

把一次性、强依赖本项目上下文的技能提上去，只会污染公共技能库。只有当它是「通用做法」时，才值得提升。

相关：见第 08 章「技能库与技能装配」、Q36。

Q35. 什么是「运行配置（RunConfig）」？改了会出什么事？

运行配置是一个 Agent 的「工作参数包」：用哪段提示词、能用哪些技能、输出成什么格式、用哪个执行引擎、CLI 传什么参数。改它，等于改这个 Agent 的工作方式。

路径：

项目内 › 组织与运营 › 智能体组织 › 选择某个 Agent › 运行配置
auto-run 是高风险开关

运行配置里若开启自动运行（auto-run），Agent 会在无人确认的情况下自行执行。调试期请保持关闭，让每次执行都过你一眼；确认稳定后再考虑打开。

相关：见第 08 章「运行配置（RunConfig）」、Q37。

Q36. 组织进化引擎是什么？它给的建议会自动执行吗？

组织进化引擎是一个「组织体检 + 开药方」的模块。它盯着项目实际运行数据，发现「某个岗位人手不够」「这项技能该固化了」「该进入下一个阶段了」，就生成一条建议。它只出建议，不自动执行，主动权在你手上。

路径：

项目内 › 组织与运营 › 组织进化 › 待处理建议（N 条）

建议主要有几类：加岗位、扩编制、装配技能、阶段升级。每条都可以采纳、暂缓或拒绝。暂缓默认保留 7 天，过期就失效，需要它会重新出现。

口诀：AI 提建议，人拍板

别把「建议多」当成「系统要我改」的压力。建议是观察结果，采纳与否取决于你对业务的判断。

相关：见第 08 章「组织进化引擎」、Q37、Q38。

Q37. 「一键扩编」点了会发生什么？能撤销吗？

一键扩编是把一条「扩容建议」变成实际动作：系统会走一串自动步骤——建 Agent、挂岗位档案、装配技能、接通连接器、登记上岗，确认原文是「确认采纳建议「X」？系统将自动完成扩编/装配并上岗。」

能撤销。这类由建议触发的操作会留下一个回滚点，如果你想退回扩编前的状态，可以从回滚点恢复。

扩编前先想清楚「谁来管」

人多了，协调成本也上去了。如果一个管理者已经带不过来，再多招员工只会更乱。扩编的同时，看看要不要调时间片权重或再分一层管理。

相关：见第 08 章、Q36、Q38。

Q38. 项目的「阶段」是什么意思？谁来切换？

项目阶段描述组织当前处在哪个发展档位，一般有四档：起步期、成长期、规模化期、成熟期。阶段不同，组织该配多少人、该有哪些技能、该盯哪些指标都不一样。

切换有两种方式：①组织进化引擎根据运行数据建议「该升级了」，你确认后执行；②你手动切换。切换会留下回退点，如果切上去发现不合适，可以退回上一个阶段。

口诀：阶段匹配规模，不匹配心情

别因为「想显得更专业」就跳到规模化期，那会让系统按大团队的方式协调几个人，反而拖慢节奏。阶段跟着真实工作量走。

相关：见第 08 章「阶段切换」、Q36。

Q39. 我想给某个成员加权限，能加到「管理」类吗？

能，但只能加给人。权限一共 14 项，其中 11 项是通用权限，另外 3 项是管理权限：暂停项目、暂停任务、成员管理。这三项是「刹车」和「人事」级别的权限，风险最高。

路径：

公司管理 › 成员与权限 › 选择成员 › 权限设置
AI Agent 不给管理权限（目前是前端拦截）

原则是硬红线：管理权限只能落在人身上，AI Agent 无论多「能干」，都不给它暂停项目、暂停任务、管成员的权力，防止 AI 误操作或失控时你连刹车都踩不到。要如实说明的是：部分可用当前这层限制做在前端（界面会拦，并提示「AI Agent 不可授予管理权限」），后端强制拦截还在排期，暂不要把它当成服务端已生效的安全边界。

相关：见第 02 章「成员与权限速查」、Q40。

Q40. 邀请团队成员，对方一直没进来，邀请会过期吗？

会。邀请有效期是 7 天，过期后那条邀请就失效了，对方再点链接进不来。这时候需要你重新发一次邀请。

路径：

公司管理 › 成员与权限 › 邀请成员
对方没收到，多半不是过期的锅

先确认对方是不是用了你发过去的那个邮箱登录——邀请是绑定邮箱的。如果邮箱对、时间没超 7 天，再让管理员检查成员列表里是不是已经存在同邮箱的账号。

相关：见第 02 章「成员邀请」、Q39。

六、任务与自动运营（Q41–Q50）

Q41. 怎么新建一个任务？最少的必填项是什么？

路径：

项目内 › 任务 › 新建任务

最少要填的是标题和描述。描述就是给 AI 的指令，写得越具体，AI 跑偏的概率越低。另外两个常被忽略的字段：①时限（默认 7200，单位秒，超时会按兜底逻辑处理）；②验收标准——注意系统没有单独的「done_when」输入框，验收标准要写进描述里，用「完成后应满足……」这类句子表达。

口诀：描述里写验收，没有第二个框

很多人找不到「验收标准」输入框就以为系统不支持，其实它就在描述里。把「做成什么样算完成」直接写进指令，验收 Agent 才有的对照。

相关：见第 09 章「新建任务时每个字段怎么填」、Q42、Q51。

Q42. 任务建好了，为什么它一动不动？

先看三件事，按顺序排除。

第一，项目循环有没有启动。任务不会自己跑，必须项目处于运行态，auto-ops 才会调度它。路径：项目内 › 组织与运营 › 运营控制台，看「启动/停止」当前是什么状态。

第二，是不是人工审核模式。只有全自动和半自动会跑自动运营循环；人工审核模式下，任务要等人批准才动，这是设计如此，不是故障。

第三，是不是没有可用时间片。时间片就 10 个格子，被别的任务占满时，新任务只能排队。

别急着反复点「启动」

重复启动不会让它跑得更快，反而可能把状态搅乱。先确认上面三点，再去动它。

相关：见第 09 章、第 11 章、Q43、Q21。

Q43. 「时间片」是什么？为什么我的总是满的？

你可以把时间片想成AI 的「工位」。默认 10 个格子，每个任务占用一个（或按权重占用不等份），同一时刻能并行推进的任务数量受它限制。满格意味着：想开新任务，得先等某个在跑的任务结束。

路径：

项目内 › 组织与运营 › 运营控制台 › 时间片

系统支持自动扩容，任务积压时会自动加格子，不必你手动改。

时间片多不等于快

并行任务越多，对模型额度和预算的消耗越集中，也越容易撞上预算熔断。如果总是满格，先想想是不是任务拆得太碎、太多，而不是把格子加到无限。

相关：见第 09 章「时间片」、Q44。

Q44. 「轮次」是什么意思？一个任务要跑多少轮才算完？

轮次是「AI 推进一个任务的一小步」。系统按时间片轮流调度任务，每轮到某个任务，它往前做一点：干活（task）、复盘（review）或待命（free）。一个任务通常要跑很多轮才收口。

有个关键阈值：单个任务跑满 20 轮（或所有任务都完成）时，会触发一次复盘/评审，重新审视方向和优先级，必要时重排任务。所以轮次不是简单的「计数」，它到点会带来一次结构调整。

口诀：轮次到 20，必有复盘

如果你发现任务跑了很久还在原地打转，别一直等——第 20 轮的复盘就是系统给的检查点，去复盘记录里看它怎么判断的。

相关：见第 09 章「轮次」、Q43、Q50。

Q45. 任务能不能删掉？列表越堆越多。

要分状态看。已经进入执行的任务（待执行 / 运行中 / 已完成 / 失败）没有删除按钮——任务记录是运营历史和审计的一部分，删掉会让「这个任务当时为什么失败」永远说不清，系统对它们只提供状态流转。

但「规划中」的任务可以直接删除：它还没提交执行，在列表操作列点删除、二次确认后即移除。已执行的任务想「收尾」，就把它标记为完成或终止，让它退出调度——不再占用时间片，但仍留在列表里可查。（后端同样只允许删「规划中」任务，删已执行的会返回明确错误。）

口诀：规划中可删，执行后只收尾

还没提交的规划草稿，删干净不留痕；已经跑过的记录，留着有据可查——那正是经营数据的一部分。

相关：见第 09 章「任务：给工厂安排机床」、Q48。

Q46. 任务用「循环执行」还是「Agent 引擎」？选错会怎样？

两个引擎定位不同。循环执行适合复杂、编码类、长时任务，是默认也更稳的选择；Agent 引擎在进程内跑 LLM+ToolCall，适合信息整合、接口调用这类轻活。

如果给一个软件交付类任务选了 Agent 引擎，界面会弹告警，原文意思很明确：Agent 引擎可能无法完成软件交付，仅适合简单项目，建议使用循环执行。

软件类任务，别赌 Agent 引擎

看到那条告警就说明你选错了工具。选引擎的优先级是「任务级 > 角色级 > 项目默认」，所以就算项目默认设了 Agent 引擎，也可以在单个任务上改回来。

相关：见第 09 章「引擎怎么选」、Q81。

Q47. 任务失败了会怎样？会一直重试吗？

不会无限重试，系统有一套三级兜底：

第 1–2 次失败会降级重试（换更稳的策略/模型再试）；第 3 次失败升级为人工处理，在待办里等你介入；如果人工处理后仍超过上限，就告警并暂停项目循环，避免一直空烧预算。

口诀：两次自己扛，三次找人帮

所以看到任务变成「待人工处理」，不是系统坏了，是它在按规矩喊你。你的介入本身就是流程的一环，不是异常。

相关：见第 09 章「连续失败的三级兜底」、Q91、Q98。

Q48. AI 做了一半卡住了，我能往里塞点新信息吗？

能，这正是发挥你价值的地方。做法是给任务补充任务级提示词，让任务带着更新后的上下文继续推进；必要时可以先暂停任务、补充完再恢复。要注意：自动运营任务的「描述」创建后不可修改（它是独立验收的对照依据），所以补充信息别去改描述，走任务级提示词模板。

路径：

项目内 › 自动运营 › 任务管理 › 选择任务 › 编辑 › 提示词模板
补充内容要讲清「和之前有什么不同」

新要求最好写成一段追加说明：「补充：之前的方向作废，改为……，原因是……」，保留来龙去脉，AI 才不会把之前的进度当成没发生过。

相关：见第 09 章、第 11 章「通知与你的介入点」、Q49。

Q49. 项目在跑，我怎么一眼看出它现在到底在干什么？

去运营控制台。一块屏幕上分几组信息：状态卡（运行态、预算运行态）、快捷入口（十几个常用跳转）、以及正在执行任务的实时进度。预算运行态会用标签直接告诉你现在是不是正常、降级、还是已熔断。

路径：

项目内 › 组织与运营 › 运营控制台
口诀：先看标签，再看任务

先扫一眼预算运行态标签——如果是「熔断」或「已终止」，那任务不动的原因就不在任务本身，先解决预算。

相关：见第 09 章「自动运营控制台」、Q92、Q76。

Q50. 我听人说「接力推进」「free 维护」，可界面上找不到这些词？

因为这些是内部机制的说法，界面上不会直接显示成文字。你真正能看到的，是任务如何被轮次调度、复盘如何重排、以及待命状态如何不消耗模型额度。

对应关系是这样的：所谓「接力推进」，你看到的现象是任务完成一段后自动交到下一个环节、不需要你手动接力；所谓「free 维护」，你看到的现象是项目在空闲时也保持待命，但空闲等待不消耗 LLM 调用，不会偷偷烧钱。

口诀：看现象，不记黑话

你不需要记住内部术语，只要抓住三条可观察事实：任务会自动往下走、复盘会重排、空闲不烧钱。

相关：见第 09 章「时间片与轮次」、第 11 章、Q44。

七、验收与返工（Q51–Q60）

Q51. 「三权分立」到底是什么？为什么非要把一件事拆给三方？

三权分立指的是把「做、验、批」拆成三个独立角色：执行的干活、验收的独立核对产出、批准的做最终放行。关键是「独立」——验收方不是干活的那个 Agent。

为什么值得这么麻烦？因为 AI 有个很隐蔽的毛病叫「自审自批」：它对自己做的东西天然宽容，会给自己打高分。让同一个 Agent 既干又验，等于让考生自己判卷，错的地方永远发现不了。拆开之后，验收 Agent 手里只有你定的标准，没有「我做过」的包袱。

口诀：干活的不判卷

这套机制的价值不在形式，而在「有没有一个只认标准、不认人情的角色」。

相关：见第 09 章、第 11 章、Q52、Q54。

Q52. 验收结论有哪几种？「返工」和「驳回」差在哪？

验收结论有三种：通过（pass）、返工（redo）、驳回（reject）。

区别在「问题出在哪一层」：返工的意思是「方向对，但活没干到位」，任务回到执行环继续改，标准不变；驳回更重，通常意味着这件事本身不成立——标准有问题、前提错了、或者根本不该做，需要你重新审视任务定义，而不是让它再改一遍。

驳回不是「再多试几次」

看到驳回，先别急着恢复任务让它重跑。驳回来的是「这件事的前提」，多半要你先改任务、改标准，或者干脆取消。把驳回当返工处理，只会反复撞墙。

相关：见第 09 章「验收：三权分立」、Q55、Q56。

Q53. 验收标准写在哪？我怎么知道 AI 拿什么对照打分？

写在你任务的描述里。系统没有单独的「done_when」输入框——这一点容易踩坑，很多人以为找不到就是没有这个功能。实际上，验收 Agent 对照的就是描述里你写下的完成条件。

写得好的标准长这样：「完成后应满足：①输出一份不超过 800 字的英文产品介绍；②包含 3 个卖点；③语气面向 B 端采购负责人。」——三条都是可核对的。写得差的标准是「做好一点」「写得专业些」，这种话 AI 只能靠猜。

口诀：能数得出来的，才叫标准

判断标准写得好不好，就问自己一句：这句话能不能被人拿尺子量？能量，AI 就能对照；量不了，验收就是走过场。

相关：见第 09 章、Q41、Q51。

Q54. 让同一个 AI 自己验收自己的产出，不行吗？

不行，这正好是系统要避免的事。就算技术上做得到，结果也没有意义——同一个模型的判断偏好跟它执行时是一致的，它会觉得「我这么做是有道理的」，于是把没做到的地方也判成通过。

独立验收 Agent 换的是「立场」：它没有执行过程的记忆，只有你的标准和最终产出。它的任务不是「理解你当初为什么这么干」，而是「对着标准逐条核」。

省掉验收，省下的是假象

有的用户为了提速，手动跳过验收直接标记完成。这样做，自动化跑得越快，积累的隐患越多。验收是系统里最不该省的一环。

相关：见第 09 章、Q51、Q57。

Q55. 任务被判「返工」了，我该做什么？

先看验收记录里写清楚「哪条标准没过」。绝大多数返工，问题都出在标准或指令不清楚，而不是 AI 能力不够。

你要做的是把模糊处补具体：在任务描述里追加一条说明，指出具体差在哪、正确应该是什么样，然后让任务继续。不要只说「重做一遍」，那不叫修复，只是再赌一次。

口诀：返工改指令，不是催进度

返工次数多，往往不是 AI 笨，是你在用一句模糊的话期待一个精确的结果。把话说明白，一次就够。

相关：见第 09 章、Q52、Q59。

Q56. 任务被「驳回」了，是不是等于前面白做了？

不白做，但确实要停下来想一想。驳回代表验收方认为「这件事的前提有问题」：可能是任务目标和项目方向不一致，也可能是标准本身就是错的。前面执行产生的内容还在，只是不能直接用了。

正确动作是回到任务定义层：这个任务要不要继续？目标该改成什么？如果确实不该做，就把它终止，把精力挪到更该做的事上。

驳回是信号，不是失败

一个任务被驳回，说明你的验收机制在工作——它拦下了一件方向不对的事。这比「一路绿灯跑到最后发现跑错了」要好得多。

相关：见第 09 章、Q52、Q60。

Q57. 「验收强度」是什么？能调吗？调了有什么用？

验收强度指的是验收方查得多严。风险高的任务，验收会对照更多维度、更细的标准；风险低的任务，验收相对宽松。这就是所谓「按风险分级」。

调它的意义在于平衡速度和质量：把每个小任务都按最严标准验收，会拖慢节奏；反过来，把关键任务当小事放过，风险就压不住了。合理做法是让风险等级决定强度，而不是凭感觉。

口诀：大事严查，小事快过

与其纠结某个任务该多严，不如先想清楚它的风险等级。定了等级，强度自然有答案。

相关：见第 09 章「验收：三权分立」、Q51。

Q58. 人工处理节点提示要在 SLA 内处理，超时会怎样？

SLA 就是「你需要在多长时间内响应」的约定。系统里的人工处理节点带SLA、升级链和超时降级三重机制：快到时限时提醒你，超时后按预设路径升级给更高权限的人，如果还是没人处理，系统会按降级策略继续（比如先跳过、或按默认处理推进），而不是无限期卡死。

要注意的是，超时降级不等于「问题解决了」，只是系统在「等你」和「卡死」之间选了前者。

降级是兜底，不是免责

如果某个节点的待办一直在超时降级，说明这条流程的责任人配错了，或者 SLA 设得太短。去看一眼「待办」，把该处理的人找出来。

相关：见第 11 章「通知与你的介入点」、Q47。

Q59. 验收记录在哪看？我想知道某个任务到底为什么没过。

在任务详情里。进到具体任务，能看到它的流转历史、执行记录和验收结论。验收结论通常会写清是「通过 / 返工 / 驳回」以及判定依据。

路径：

项目内 › 任务 › 选择任务 › 详情 / 验收记录
口诀：没过，就去读结论，别猜

大多数人卡住是因为只看「任务失败了」这四个字，就去乱改指令。先读结论，再动手，改的才是有用的地方。

相关：见第 09 章、Q55、Q56。

Q60. 我可以直接替 AI 说「通过」吗？会不会破坏流程？

可以，但要想清楚这是「行使决策权」还是「图省事跳过」。你作为负责人有权放行，这在流程里是允许的；但如果明明是没做完的活，你为了让项目往前跑而强行点通过，被跳过的那部分不会消失，只会在后面某个环节冒出来，而且更难查。

强行通过 = 把问题往后推

人工强行通过时，最好在备注里写清「为什么这次可以例外」。留个记录，将来回溯就不会一头雾水。最忌讳的是把「跳过验收」当成提速的常规手段——那不是提速，是欠债。

相关：见第 09 章、Q51、Q54。

八、知识库与资料（Q61–Q70）

Q61. 我传了个文件，它一直卡在「解析中」，怎么办？

先别急着重传。文档从上传到可用会经历几个状态：待处理 → 解析中 → 已解析 → 分块中 → 向量化中 → 就绪，任何一步失败都会变成「失败」。卡在中间态通常是还没走完，不等于坏了。

另有一个状态叫「需人工确认」：解析走了降级路径（文档乱码偏多、结构特殊等）时，系统不会直接标「就绪」，而是等你人工确认内容可用后才正式入库，原因写在文档旁边。看到它不是失败，是系统把把关权交给你。

如果长时间不动，按这个顺序看：①文件是不是特别大或页数很多（会慢）；②是不是格式在白名单外的边缘情况；③刷新页面看状态有没有变化。

失败才需要重传，慢不需要

反复上传同一个文件，会产生多条重复记录，反而让知识库变乱。先确认它确实是「失败」，再考虑重新导入。

相关：见第 07 章「文档的一生」、Q62。

Q62. 为什么我的文件传不上去？格式和大小有什么限制？

知识库上传有明确的白名单：pdf、txt、md、markdown、docx、xlsx。不在这个名单里的（比如 csv、pptx、各种图片）不接受直接上传，会当场被拒。docx / xlsx 还会校验文件结构（ZIP 魔数），改后缀伪装的会被识破。单个文件上限是 50MB。

格式不在白名单时，有个常用绕法：先把内容转成 pdf 或 txt 再传。pptx 可以导出成 pdf，图片可以用文字化的方式重新整理。

csv 有个例外，别搞混

「现有项目导入」那条路径是允许 csv 的，但它和知识库上传是两回事，导入的资料不进知识库。别把两处的格式要求当成同一套。

相关：见第 07 章「支持哪些格式」、Q65。

Q63. 「公司级」和「项目级」知识库有什么区别？我该往哪传？

分层的意义是「谁能用」。公司级知识整个公司共享，适合放公司制度、品牌口径、公共产品资料；项目级知识只在这个项目里用，适合放项目专属资料。中间还有「共享」层，用来把某部分内容定向开放给指定范围。

检索时不是各占一半：系统会优先项目级（约 70%），再补公司级共享（约 30%）。所以同一份资料放哪，会直接影响 AI 答题时的偏好。

口诀：通用放公司，专属放项目

拿不准时问一句：这份资料，别的项目用得上吗？用得上放公司级，只跟这个项目有关就放项目级。

相关：见第 07 章「公司级 vs 项目级」、Q64。

Q64. RAG 搜索答非所问，怎么排查？

按「资料有没有 → 找没找到 → 答得好不好」三步查。

第一步，资料在不在：去知识库看目标文档状态是不是「就绪」。还在解析中，AI 自然检索不到。第二步，分层对不对：资料放在公司级还是项目级，会影响它是否进入检索范围，放错层就等于没放。第三步，问题问得清不清楚：问题太笼统，检索命中的片段就会发散。

口诀：先看状态，再看分层，最后改问法

顺序不能乱。很多人一上来就改问法，其实资料压根还在「向量化中」。先确认「库里真有它」，再谈别的。

相关：见第 07 章「RAG 检索页签」、Q61、Q63。

Q65. 我有个已有的项目，资料想一次性导进来，怎么做？

用「现有项目导入」这条路径。它一次最多选 10 个文件，比知识库上传宽松，允许 csv。

但有个关键区别要记住：通过「现有项目导入」进来的资料，不进知识库。它的用途是把项目信息喂给创建向导，帮助系统理解你在做什么，而不是建一个可检索的资料库。如果你要的是「以后能问它」，请走知识库上传那条路。

一次 10 个，是限制也是节奏

文件多就分几批导。别指望一次把几百个文件灌进去——先导最能说明项目定位的那几份，剩下的后面在知识库里慢慢补。

相关：见第 07 章「已有项目整体导入」、Q62。

Q66. 会议录音能导进去吗？我看到有「会议导入」。

能导入会议内容，但不支持音视频文件。也就是说，把一场会录成 mp3/mp4 直接丢进来，系统处理不了。你需要先把内容变成文字（比如会议纪要、逐字稿），再走会议导入。

导入后，系统会帮你把会议内容整理成结构化的知识沉淀，进入相应的知识层。

口诀：先转文字，再谈导入

音视频不是系统的处理对象，文字才是。手头有录音，先用工具转成文本，再进来。

相关：见第 07 章「会议记录导入」、Q63。

Q67. 「待确认知识」是什么？为什么我在侧边栏找不到入口？

待确认知识是一批「系统提出来、但需要你拍板才算数」的知识条目——通常是 AI 从资料或对话里提炼出的结论，怕它理解偏了，先放在这里让你确认。

它确实没有侧边栏入口，这是一个真实的设计特点，不是你找不到。要访问它，得直接走路径：

项目 /<项目ID>/kb/review
不确认，它就不会进知识库

把待确认清单当「收件箱」定期清一次。堆着不管，等于这些知识一直处于「半成品」状态，检索时用不上。

相关：见第 07 章「待确认知识」、Q63。

Q68. 本地电脑上的文档，怎么批量扫进系统？

用本地边缘客户端。它装在你自己电脑上，负责扫描本地文档并上传到服务器，相当于给系统开了一扇连到你本机资料的门。这样你多年积累的本地文档，不用手动一个个传。

它的定位是「扫描上传 + 接收指令」，是把本地资料接进项目的桥。

先想清楚要扫哪个目录

本地电脑上的资料很宝贵，扫描范围要你主动规划，不要一上来就整盘扫。挑真正跟项目相关的目录，既能提高信噪比，也避免上传一堆无关文件。

相关：见第 07 章、Q69。

Q69. 边缘客户端显示「Disconnected」，怎么排查？

「Disconnected」（已断开）表示客户端和服务器之间的连接断了。这个状态是英文的，因为边缘客户端界面本身就是全英文。

按四步排查：①确认客户端进程还在运行，没有被关掉或崩掉；②确认本机网络正常，能访问外网；③确认服务器地址/端口配置没有改过；④如果它一直在「Connecting / Reconnecting / Disconnected」之间跳，多半是网络不稳或服务器侧暂时不可达，等一会儿再看。

口诀：先看进程，再看网络，最后看配置

顺序排查能省很多时间。多数「Disconnected」都是本机进程或网络的小问题，不是系统故障。

相关：见第 07 章「边缘客户端」、Q68。

Q70. 外面的人（客户）能直接问我的知识库吗？

可以，用「客户页面」就能对外开一个有限权限的问答页。路径：进入项目 › 左侧「研究与获客」› 客户页面 › 新建分享。生成的链接形如 /s/{token}，访客不用注册、不用登录，打开一个标题为「AI 智能问答」的页面就能问，而 AI 只回答你勾进「知识库白名单」的库。

三个关键点：一，白名单要显式勾选——当前界面的原文是「留空 = 不开放任何知识库」（不是"全部开放"，旧文案写反过，这一版已改对），留空时访客只得到无资料的通用回答；二，链接在创建成功那一刻只完整展示一次，弹窗原文「请立即复制访问链接，token 仅本次展示，关闭后不可再查看」，弄丢了就用列表里的「重置链接」生成新的（旧链接立即失效）；三，配上「每分钟限流」和「每日上限」防止被人刷 token，给客户看的内容只勾对外库，别把含成本价的库勾进去。访客的聊天记录只留在他自己的浏览器里，刷新即清；你能回溯的是「访问日志」（问题 / IP / 状态 / 输出 Token / 成本 / 时间）。

别把「公司级共享」当成「对外公开」

「公司级」和「共享」都是公司内部的概念，不等于互联网公开。任何对外发布的内容，都要经过你自己的把关。

相关：见第 07 章、Q63。

九、账本与花费（Q71–Q80）

Q71. 平台账本和项目账本有什么区别？我要管两个吗？

要，但角色不同。这是双线账本设计：

平台账本记真实交易——你的公司账户余额、充值、实际消费。它管的是「你有没有钱」；余额不足会触发熔断。项目账本做虚拟核算——每个项目花掉多少、还剩多少，管的是「这个项目的预算够不够」，预算耗尽就暂停该项目的循环。

口诀：公司看钱，项目看预算

一个对钱负责，一个对项目负责。项目账本让你看清「哪个项目在烧钱」，平台账本让你看清「公司还撑不撑得住」。

相关：见第 04 章「预算装在三个口袋里」、第 05 章、Q72、Q78。

Q72. Token 计费是怎么算的？为什么我看到的是「估算」？

按调用量算：系统读取会话日志里的 usage 统计，然后按单价折算。参考单价是输入 1 元/百万 token、输出 2 元/百万 token、缓存读取 0.02 元/百万 token。输出比输入贵，是因为模型「生成」比「读取」成本高。

之所以会出现「估算」字样，是因为计费明细里包含估算或未精确计量的部分——比如某些调用拿不到精确的 usage 数据，系统会按规则折算。所以它适合用来「看趋势、控预算」，不适合拿来当逐条精确的账单。

它是仪表盘，不是发票

计费明细的定位是成本控制工具，不是财务凭证。别指望它精确到分毫，也别拿它对账。

相关：见第 04 章「钱到底怎么算」、第 09 章「计费明细」、Q74。

Q73. 预算预警线到底是 80% 还是 90%？哪个准？

现在以后端统一配置的那一条预警线为准，默认 80%。这一版把运营控制台「AI 预算消耗」卡片上的「预警」标签阈值也改成由同一条线驱动，和「计费明细」页口径一致——所以不再是"80% 降级、90% 亮标签"两套数字，而是同一条线、同一个时刻。

也就是说：花到预警线（默认八成）时，系统会发通知、开始降级处理，控制台的「预警」标签也在这一刻亮起。具体百分比可在预算设置里调整，但别把预警线设到 95% 左右——那样等于没有缓冲。

口诀：一条线，亮了就补

不用纠结 80 还是 90，只要记住「预警标签一亮，就是该充值的信号」这个动作就够了。

相关：见第 04 章「预算的一生」、第 09 章「自动运营控制台」、Q76。

Q74. 公司账本的「AI 算力费」和项目计费明细对不上，是 bug 吗？

这一版比过去好，但仍不能保证逐条对齐。新打通的是：项目侧的 token 消耗会按批上报到平台真实账本（记为 AI 算力费），平台按上报单号幂等去重、不会重复扣费，上报成功才记账、失败会退避重试不丢单。所以只要部署时配好了上报地址，公司账本的「AI 算力费」里现在是真实包含了 token 消耗的。

那为什么还会有对不上的时候？两个原因：一，如果上报地址没配置，这条链路不会启用，此时平台账本不含 AI 算力费（平台账本页有说明）；二，项目计费明细本身含"按文本长度估算的兜底计费"，两边口径本就不同。依然不要拿两处数字做精确对账——对不齐不代表你算错了。

各看各的用途，别强行拉平

项目账本看「这个项目花了多少」的趋势，平台账本看「公司余额够不够」。跨账本精确核对，现在做不到，也别把它当故障去排查。

相关：见第 04 章、第 05 章「公司账本」、Q71。

Q75. 怎么才能省点钱？有没有实操的降本方法？

有，而且多数降本来自「少做无用功」，不是「用更便宜的模型」。几个最见效的做法：

①把任务描述写清楚，减少返工——返工是最贵的浪费，一次跑对抵十次乱跑；②别把时间片堆满，并行任务越多，额度消耗越集中，越容易撞熔断；③按任务难度选引擎，轻活别用重引擎；④及时收尾没用完的任务，让它们退出调度，不占时间片也不空转；⑤预算设具体数字而非 0，0 等于不设防。

口诀：写清才是真省钱

降本的第一杠杆永远是指令质量。省下的每一轮返工，都是真金白银。

相关：见第 09 章「计费明细」、Q41、Q79。

Q76. 预算熔断了，我该怎么办？能临时解除吗？

熔断的意思是「花到线，循环暂停」，这是保护机制正常起作用，不是故障。标准处理流程是：补充预算 → 循环恢复。

如果你只是想让它临时再跑一会儿，可以在资源治理里「解除熔断（临时）」。但临时解除是应急手段，不是长期方案——不补预算，它很快会再次熔断。

路径：

项目内 › 组织与运营 / 资源治理 › 项目预算 / 解除熔断（临时）
临时解除前先问：钱从哪来

临时解除只是把暂停往后推。想清楚这次多花的钱值不值，再点。反复临时解除、从不补预算，等于把保护机制架空。

相关：见第 06 章「资源治理」、第 09 章、Q77。

Q77. 充值怎么充？有金额限制吗？

路径：

公司管理 › 公司账本 › 充值

金额范围是 0.01 到 1000000，单笔充值不能超过 1000000 元。充值成功后，公司账本余额会相应增加。

另外，公司账本可以设置预警阈值。当余额低于这个阈值时，系统会提示你及时充值，避免实例因为余额不足而熔断，提示大意是「余额已低于预警阈值，请及时充值避免实例熔断」。

口诀：阈值就是提前量的提醒器

把预警阈值设得比「刚好够」高一些，你就有了反应时间。等余额见底再充，中间这段空窗期项目是停着的。

相关：见第 05 章「公司账本」、Q76、Q78。

Q78. 项目预算和公司余额，到底哪个先兜不住？

看哪条线更近。系统有两条独立的熔断线：项目总预算线和 AI 运行预算线。任一条被击穿，对应范围就会暂停。同时，公司余额不足也会从平台侧触发熔断。

可能出现两种情形：项目预算还有，但公司余额先见底——那整个平台侧就先卡住了；也可能公司余额充足，但某个项目的预算先用完——那只有这个项目暂停，别的项目照跑。

别只盯一个数

项目里看到「预算还剩不少」不等于高枕无忧，公司账户也得有钱。两边都要留意。而且因为上报链路尚未完全打通，别指望两边的数字严丝合缝地对上。

相关：见第 04 章「预算装在三个口袋里」、Q71、Q74。

Q79. 预算设成 0 是什么意思？是不花钱还是不限？

在项目预算里，0 表示「不限制」，不是「不花钱」。这一点非常容易误解，后果也不小。

填空的时候要留神：如果你想要「这个项目最多只能花 500 元」，就明确写 500，而不是留 0。填 0 等于告诉系统「随便花」，反而是放开了闸门。

想省钱，就别填 0

「0 = 不限制」是最贵的那个选项。想控成本，永远给一个具体的、你能接受的小数字。这是新手最容易犯、代价也最大的一个错。

相关：见第 03 章「预算设定」、第 04 章、Q75。

Q80. 计费明细能当发票用吗？财务能拿它入账吗？

不能。计费明细是成本控制工具，不是财务凭证。它包含估算和未精确计量的部分，数字粒度上就不适合作为正式的财务依据。

它的正确用途是：看趋势、设阈值、判断要不要补预算、评估哪个项目配合优化。财务入账需要的是另一个体系的凭证，不是这里的明细。

用途错位比数字不准更麻烦

拿明细去跟财务「对账」，你会发现怎么也对不平，然后花大量时间去查一个本来就不存在对应关系的东西。先摆正它的定位。

相关：见第 09 章「计费明细」、Q72、Q74。

十、软件功能与开发（Q81–Q90）

Q81. 「新建软件工程」和「通用任务」有什么区别？我要做个网站该选哪个？

任务分三类：通用任务、新建软件工程、软件修改。要做一个网站，选新建软件工程。

区别在于流程深度：通用任务适合一次性的、目标明确的活（写份文档、做个分析）；新建软件工程会带你走一套七步向导，把需求、技术方案、目录结构这些前置项问清楚，再进入开发。软件修改则是针对已有工程的增量改动。

口诀：要做「东西」用工程，要做「一件事」用通用

产物需要长期维护、要反复迭代的，走工程线；一次交付就结束的，走通用任务。选错了流程，后面会绕远路。

相关：见第 10 章「三种任务类型」、Q83、Q89。

Q82. 软件工程向导走到一半退出了，进度会丢吗？

不会丢。向导会保存你已经填过的内容，你回到列表里能继续。它本质上是一条「草稿到立项」的流程，中间状态是被保留的。

路径：

项目内 › 任务 › 软件工程列表 › 选择未完成的工程 › 继续规划
口诀：没走完，就点「继续规划」

别重新发起一遍——那会生成第二条记录，你的工程列表就多了一份重复的草稿。找到原来那条继续就好。

相关：见第 10 章「软件工程向导」、Q83。

Q83. 软件工程显示「规划中」，任务为什么不开始执行？

因为「规划中」就是不执行的状态。软件工程向导没走完、还在收集信息的阶段，系统不会启动开发任务——它连「要做什么」都还没定，自然不能开工。

你要做的是回到这个工程，把向导剩下的步骤走完，或者点「继续规划」，让状态往下推进。状态一旦进入可执行阶段，任务才会真正被调度。

「规划中」不是卡住

看到它不动就以为系统坏了，然后反复新建工程，只会堆出一堆半成品草稿。先确认它是不是还在规划阶段，这多半就是原因。

相关：见第 10 章、Q82、Q84。

Q84. 「软件修改」弹窗要我选「源软件工程」，这是什么？

这是必填项，指的是你要改的是哪一个已经存在的软件工程。软件修改是在已有工程上做增量改动，所以系统必须先知道「改的是哪一栋楼」，才能定位代码和工作区。

如果下拉里找不到你想改的工程，通常说明那个工程还没建、或者不在这个项目里。那就不是走「软件修改」，而是要先创建对应的软件工程。

选错源工程 = 改错地方

多个工程名字相近时尤其容易选错。确认清楚再提交，改动落到别的工程上，排查起来非常费劲。

相关：见第 10 章「软件修改弹窗」、Q89。

Q85. 提示「任务提示词草稿为空，请先与 AI 对话生成」，怎么办？

这条提示的意思是：你还没让 AI 帮你把需求整理成任务提示词，草稿栏是空的，不能直接提交。

正确做法是先在上面跟 AI 对话，把「你想改成什么样」说清楚，然后点生成草稿，系统会把对话整理成一份结构化的任务提示词，填进草稿栏。生成之后你还能手动微调，再提交。

口诀：先聊清楚，再生成

草稿不是让你手写的，是「对话的结果」。跳过对话直接提交，系统就没有依据。先去聊，聊明白再生成。

相关：见第 10 章、Q86。

Q86. 我点了几次「生成草稿」，会不会把之前改好的覆盖掉？

会。再次生成会覆盖当前的草稿内容。所以如果你已经手动改过草稿、补充了细节，再点一次生成，这些手改的内容就没了。

稳妥的做法是：先把手动修改保存或复制出来，再决定要不要重新生成；如果只是想补充一点内容，就在现有草稿上直接编辑，而不是重新生成。

「再来一次」= 清空重写

把它当成「重置」按钮，而不是「优化」按钮。手改过的内容要留，就先备份。

相关：见第 10 章、Q85。

Q87. 做完的软件怎么部署上线？为什么我点了没反应？

部署和备份都受功能开关控制。自动构建部署对应的是 deploy 这个开关，自动备份对应的是 backup。如果这两个开关没打开，即使代码开发完了，你也看不到部署真正执行。

先检查功能开关的状态（一般在项目设置或运营相关配置里），确认 deploy 是开启的，再发起部署。

点了没反应，先查开关

这一类「功能明明做了却没动静」的问题，八成是功能开关没开。这是设计如此，不是 bug——有些高风险动作默认关闭，需要你主动开启。

相关：见第 10 章、Q90。

Q88. 自动备份在哪开？备份了能恢复到某个时间点吗？

自动备份由 backup 功能开关控制，开启后系统会按策略自动备份，不需要你手动发起。这类开关通常和 deploy 一起，在项目的功能开关配置里。

备份的价值在于「出事时有退路」。至于恢复到具体某个时间点，取决于备份策略的记录情况——建议你在开启后先确认一次备份确实产生了，而不是等真出事了才发现一直是关着的。

口诀：备份要验，不能只信「已开启」

开关打开不等于备份成功。上线前花两分钟看一眼最近一次备份记录，比事后追悔有用得多。

相关：见第 10 章、Q87。

Q89. 我想改一个已经上线的功能，走「软件修改」还是「通用任务」？

走软件修改。因为目标是一个已经存在的软件工程，改动要落到既有的代码和结构上，而不是凭空做一件新事。

判断口诀很简单：产物有没有「源代码/工程」这个实体。有，就走软件工程线（新建或修改）；没有，只是一次性的产出（一份报告、一段文案），才走通用任务。

别用通用任务去改线上功能

通用任务不知道你的工程结构，改出来的东西可能根本没接进现有系统。改已有工程，必须让系统知道「改哪一栋楼」。

相关：见第 10 章、Q81、Q84。

Q90. 「功能开关」是什么？为什么有的功能我这边用不了？

功能开关就是一组「高危能力的总闸」。有些动作影响面大——自动构建部署、自动备份——默认不放开，需要你主动开启才生效。这不是权限歧视，而是安全设计：默认安全，明确开启。

典型的两个开关是 deploy（自动构建部署）和 backup（自动备份）。

还有一类开关是强制开启、关不掉的安全底线：资源治理、预算熔断、渐进式信任。这三项不属于「可选功能」，任何项目都受它们约束。

口诀：能关的是便利，关不掉的是底线

找不到某个功能，先想它是不是个开关；想关掉某个保护，先想它是不是那三条底线之一——是的话，它本来就不给你关。

相关：见第 10 章、第 04 章、Q87。

十一、出错与排障（Q91–Q100）

Q91. 项目突然不动了，我从哪开始查？

按「由外到内、由大到小」的顺序，四步走：

第一步，看运营控制台的状态标签。预算运行态是不是「熔断」或「已终止」？如果是，问题在钱不在任务，先去解决预算。第二步，看项目循环状态。有没有处于「兜底暂停」？这种状态重启服务也不会自己恢复，必须手动处理。第三步，看有没有待人工处理的节点。你在等系统，系统也在等你。第四步，看具体任务记录。任务是不是在「规划中」、或反复失败。

口诀：先标签，再循环，后任务

顺序对了，绝大多数「不动了」都能在两步内定位。反过来先从任务细节下手，容易越查越乱。

相关：见第 11 章「排查树」、Q92、Q93。

Q92. 控制台显示「降级」「熔断」「已终止」，分别是什么意思？

这是预算运行态的三种状态，严重程度递增：

降级：花到预警线（约 80%）后，系统主动降低运行强度，还在跑，但已经在省着用。熔断：击穿阈值，循环暂停，等你去处理——补预算或临时解除。已终止：循环被更彻底地停掉了（例如执行了停止操作），比熔断更「死」，需要重新启动流程。

它们不是「故障」，是「刹车」

看到这几个词别慌，也别急着想法子关掉。它们是保护机制在告诉你：「再烧下去会失控，我先停一下」。你要做的是解决触发它的原因。

相关：见第 04 章「预算的一生」、第 09 章、Q76、Q91。

Q93. 「兜底暂停」是什么？为什么我重启了服务它还是停着？

兜底暂停是系统在出问题时主动把循环停下来避险的结果，由一个安全机制触发（比如连续失败超过上限）。它的关键特点是：这是一个会被持久保存的状态。

所以重启服务不会让它恢复——因为「暂停」这个决定被记下来了，重启只是重新加载了这个状态。你必须手动恢复它，并且在恢复前搞清楚是什么触发了暂停。

口诀：兜底暂停，只认手动

重启不解决它，这才是设计意图——如果重启就能绕过保护，那保护就没意义了。去找触发原因，处理完再恢复。

相关：见第 09 章「兜底保护暂停」、Q91、Q98。

Q94. 我看到「待人工处理」，但不知道要处理什么，怎么办？

「待人工处理」是任务失败到一定程度后升级给你的，所以它一定带着上下文。不要凭感觉猜，直接去看它的来龙去脉：找到那条待办或那个任务，读它的执行记录和失败原因，通常会写清楚「卡在哪一步」「试过什么」。

处理完之后，按流程让它继续——要么补充信息后恢复任务，要么调整任务定义后重跑。

不看记录就点「继续」，等于让它再撞一次

系统把问题交给你，是因为它自己解决不了。你不给新信息，它只会用同样的方式再失败一次，浪费一轮预算。

相关：见第 09 章「连续失败的三级兜底」、第 11 章、Q47、Q98。

Q95. 我看到一条英文报错/上游错误，看不懂，怎么定位？

先说一个好消息：上游服务的错误信息会优先原样透传给你看，不会被系统吞掉或改写成含糊的话。尤其是 502 / 503 / 504 这类网关类错误，现在不再退化成干巴巴的「请求错误 (502)」，而是优先显示后端给出的 message；后端没给时，也会补一句中文解释和下一步动作。所以你能看到英文原文，反而说明信息是全的，别怕它。

再提醒一个容易踩的点：如果报错发生在写操作（保存、提交、部署、发布等）上、提示超时或网络异常，文案会告诉你「可能已在服务端生效，请先刷新确认再重试」——这时别急着再点一次，先刷新看看到底成没成，避免重复提交。

定位方法：抓关键词 + 看时间点。把报错里的关键短语（模型名、错误类型、状态码）记下来，对照出错时间，去看那一刻系统在做什么任务。多数「上游错误」来自模型服务或第三方接口，属于外部侧的临时问题。

口诀：原文别丢，时间要对

把报错原文和时间点一起记录，是给后续排查留下的最有价值的两条线索。别只截图「出错了」三个字。

相关：见第 11 章、Q96、Q100。

Q96. 任务一直在「重试」，是不是死循环了？

不一定是死循环。系统的重试是有上限的：一般前 1–2 次是降级重试，第 3 次就会升级为人工处理，超过上限则告警并暂停循环。所以它不会永远转下去。

如果你觉得它「一直在试」，先确认两点：①是不是多个不同任务在各自重试，看起来像同一个在循环；②是不是每次重试之间还夹着复盘或调度，只是节奏慢。

重试上限的存在，就是为了兜住这种情况

如果确实看到远超 3 次的反复失败，那更值得关注的不是「为什么在试」，而是「为什么每次都失败」——去看失败原因，那才是根。

相关：见第 09 章「连续失败的三级兜底」、Q47、Q98。

Q97. 我改了 HMAC Secret 之后，项目服务器连不上了？

这是预期行为，不是 bug。HMAC Secret 是平台和项目服务器之间通信的共享密钥。你在平台侧重新生成后，旧密钥立即失效——如果项目服务器还在用旧密钥，双方就对不上，通信自然断了。

正确做法是：重新生成之后，把新密钥同步到项目服务器侧，让两边用同一把钥匙。改密钥是一次「换锁」，两把锁必须同时换。

换密钥 = 两端同时换，否则一定断

只在一边重新生成、另一边不管，等于把门锁换了却不给屋里人新钥匙。除非你确定能立刻同步到两端，否则不要随手重新生成密钥。

相关：见第 03 章「HMAC Secret」、Q91。

Q98. 某个任务反复失败，系统提示暂停项目循环，我该从哪下手？

这是三级兜底走到最后一步的结果——「试过降级、也找人帮过，还是不行」，于是系统把整个项目的循环停下来，防止它继续空烧。你的任务不是立刻恢复，而是先解决那个反复失败的任务。

下手顺序：①打开那个任务，读它的失败原因和验收结论；②判断是「指令问题」还是「能力/外部问题」——指令模糊就改指令，外部依赖挂了就等或绕；③如果这个任务本身不该做，就把它终止；④确认原因消除后，再恢复项目循环。

口诀：先治任务，再启循环

直接恢复循环，系统会立刻再试一次，然后再次暂停——你会陷入「恢复/暂停」的循环里。先根治，再重启。

相关：见第 09 章「连续失败的三级兜底」、第 11 章、Q47、Q93。

Q99. 我把项目暂停了，怎么恢复？找不到恢复按钮。

恢复入口在运营控制台的启动/停止控制区。控制台上有一组操作按钮，用于启动、暂停、停止循环，恢复就在这一组里。

路径：

项目内 › 组织与运营 › 运营控制台 › 启动 / 暂停 / 停止
先分清是「暂停」还是「兜底暂停/终止」

普通「暂停」手动恢复即可。如果是「兜底暂停」，按下恢复也不一定马上动——得先消除触发它的原因。如果是「已终止」，则需要重新走启动流程。

相关：见第 09 章「自动运营控制台」、Q92、Q93。

Q100. 排查了一圈还是搞不定，最后该做什么？

做三件事，按顺序。

第一，把「你看到的现象」和「你已经试过的动作」记下来。现象包括：状态标签是什么、报错原文、出问题的时间点。试过的动作包括：改了哪里、有没有重启、结果如何。这两部分构成一份能被人接手的描述。

第二，回到本章的急症索引，重新对一遍症状。很多「排查了一圈」，其实是漏看了某个状态的真正含义，比如把「熔断」当成任务故障。
