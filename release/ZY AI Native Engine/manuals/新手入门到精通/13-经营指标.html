到这一章，你已经把项目跑起来了：公司建好了、项目创建了、运行模式和预算配好了（第 04 章）、AI 员工上岗了（第 08 章）、自动运营循环转起来了（第 09 章）、甚至已经让 AI 开始写软件（第 10 章）。现在你从"建设者"变成了"经营者"——你不再是往系统里填信息的人，而是每天打开电脑看结果、做决策的人。

很多新手 CEO 到这里会犯同一个错：要么不看，要么全看。不看的人，等项目烧完预算被暂停了才发现；全看的人，被三十几张卡片、十几个数字淹没，看完也不知道该干什么。这一章要帮你建立一种"经营者视角"：你不需要看全部，但你必须知道全部在哪儿。

一句话记住本章的核心

一人公司的 CEO 不需要盯 30 个指标，只需要盯 5 个；但你得知道另外 25 个在哪个页面、出问题时该翻哪一页。指标不是用来"看"的，是用来"发现问题"的——看到异常，知道下一步查什么、做什么，比记住数字本身重要一百倍。

一、先分清四种"数字"

界面上数字很多，但本质只有四类：钱、活、果、险。很多人一开始就搞混，是因为把"平台余额"和"项目预算"当成一回事（这是两条完全不同的账，第十一节会专门讲），或者把"任务数"当成"成果"。先分类，再谈解读。

钱 —— 花了多少、还剩多少

包括：平台余额（真金白银）、项目预算余额、AI 运行花费。

在哪看：公司账本看平台余额；项目详情 → 预算明细看项目预算；计费明细看 AI 花了多少 token 钱。

多久看一次：平台余额每周；项目预算和 AI 花费每天——这是最容易突然出事的一类。

活 —— 干了多少活、干得顺不顺

包括：任务数（各状态）、运行轮次、验收返工率。

在哪看：任务管理看任务状态；运行轮次看轮次与花费；验收记录看返工。

多久看一次：每周。任务状态不用天天盯，"积压"了才需要处理。

果 —— 换来了什么

包括：交付物、线索、客户、收入。

在哪看：项目账本看收入；阿米巴核算 → 岗位级核算看「线索 / 成交」；营销与客户页面看获客动作。

多久看一次：每周（起步期可以每两周）。这是项目的"命根子"，但因为变化慢，不用天天看。

险 —— 有什么在报警

包括：预算预警、熔断、待审批节点、连续失败。

在哪看：经营驾驶舱看活跃预警；人工处理节点看待处理；自动运营控制台看熔断 / 降级。

多久看一次：每天。"险"是最需要及时响应的一类，因为它会滚雪球。

为什么先分类这么重要

因为不同类别的"正常值"节奏不一样。钱和险是快变量——今天不处理，明天可能就熔断了；活和果是慢变量——你今天不看，明天还在那儿。新手最容易犯的错，是天天盯"活"（任务完成到几了）却忘了看"钱"（快花超了）。把注意力按类别和频率分配，是经营者的第一课。

展开：为什么"钱"要分成三个地方记？（提前剧透，第十一节有详版）

新手最常问的一个问题是："我账上的钱和项目里的钱，为什么对不上？"——因为它们本来就是三本不同的账：

  • 平台余额：你在平台公司账本里的真实资金。它像"手机话费余额"，是平台给你这个账号提供的服务额度。它见底了，实例可能熔断。
  • 项目预算：你给某个项目划的额度（在项目账本里设）。它像"给孩子的零花钱上限"，是这个项目自己能支配的范围。它超了，项目会被暂停。
  • AI 运行花费：这个项目实际消耗掉的 token / 算力钱（在计费明细看）。它是"已经花掉的"，不是"还剩多少"。

所以看到"钱"的数字，先问自己一句：我现在看的是"还剩多少"（余额/预算），还是"已经花了多少"（花费）？方向搞反了，判断就全错了。

展开：你的注意力该怎么分配？一个简单的"五分钟循环"

如果你嫌"每天 / 每周 / 每月"记不住，就记一个循环：先进项目、看红色、再读信。

  • 先进项目：打开项目详情，看状态是不是"运行中"，有没有异常提示。
  • 看红色：哪里有红色标签（活跃预警、熔断、告警），先处理红色。红色处理完了，再看黄的。
  • 再读信：打开经营日报，读一遍，把里面提到的风险点记下来，作为明天的"红色"。

这三步熟练了，五分钟就能完成每日体检。剩下的每周、每月动作，等你有空再补。

第一屏：待你处理的节点

进入项目 › 自动运营 › 人工节点

界面标题是「人工处理节点」，筛选里有「待处理 / 处理中 / 已完成 / 已驳回 / 已升级」。为什么放第一位？因为这类节点是"卡住 AI 的闸门"——AI 停下来等你点一下，你没点，整个项目就停在那里。更麻烦的是很多节点带 SLA（服务时限，单位秒），超时后会按升级链往上走（先提醒你，再升级到项目负责人，最后到平台超管）。

  • 正常值：待处理 0–2 个。偶尔有几个是正常的，因为 AI 遇到敏感动作（对外发邮件、大额支出）本来就会找你确认。
  • 看到一片红/一堆待处理：说明你几天没管了。先按 SLA 最紧迫的排——卡片上会显示通道（red 红 / yellow 黄 / green 绿）和自主级别（L0–L3）。红通道强制人工，优先级最高。
  • 怎么处理：节点卡片上有「确认完成」「通知催促」「升级处理」「移动审批」四个按钮；手机端也能审批（从通知链接打开）。
常见坑：把「待处理」当待办清单慢慢做

人工节点不是"你有空再处理"，而是"AI 现在正等你"。一个 L2（一键确认）节点挂三天，意味着 AI 也停摆了三天。养成习惯：每天开工第一件事，就是把待处理节点清空或明确升级。

第二屏：预算消耗速率

这里要同时看两处，因为它们是两个不同的预算：

看哪里指标名（原文）它管什么
经营驾驶舱「预算消耗率」项目预算（你在账本页设的总额度）消耗了多少
自动运营控制台「AI 预算消耗」（本轮预算 / 已用）AI 运行预算（token / 算力）消耗了多少，达到预警线（默认 80%，可在项目运行配置里改）就显示「预警」标签
  • 正常值：都低于 80%。系统默认在达到 80%（预警线，后端字段 warn_line_pct，项目可调）时触发预算预警（通知你并让运行降级），超限则熔断（暂停循环）。控制台和「计费明细」页用的是同一条预警线，两处口径一致，不会一个 80% 一个 90%。
  • 看到的速率比"绝对值"更重要：今天 60% 不可怕，可怕的是昨天才 30%、今天 60%——说明烧钱速度翻倍了，明天就可能熔断。这时候先别加预算，先去「计费明细」查是哪个任务/哪一天突然涨的（第十节教方法）。
  • 看到「熔断：是」：AI 已经停了。这不是故障，是保险。补预算或调整后，去控制台点「恢复」即可继续（页面引导指向「恢复」，不会让你去点已禁用的「启动」）。
兜底暂停是"持久状态"，不会自己恢复

这句提示在两个页面上措辞不同，看到哪个都别慌。两者是同一件事，横幅里都会带上「原因」与「暂停时间」，并强调「兜底暂停为持久状态（跨重启保留）」。区别只在后半句的处置指引：

  • 自动运营控制台横幅标题「项目已因兜底保护暂停」，后半句是「需人工在运行配置 / 任务面板处理后，点击「恢复」继续。」
  • 项目详情页横幅标题「自动运营已因兜底保护暂停」，后半句是「需人工处理后在自动运营控制台点击「恢复」或「启动」继续。」

换句话说，你不管它，它就永远停着——跨重启也不会自愈。

第三屏：昨日经营日报

进入项目 › 自动运营 › 经营日报

页面标题「经营日报」，右上角两个按钮：「生成日报」「刷新」。日报是"昨天 AI 干了什么"的自动总结，正常应该是每天自动生成一份。你打开列表点开最新一条，读一遍正文即可，三分钟。

  • 看什么：昨天完成了什么、花了多少、有没有风险提示、今天建议做什么。
  • 列表怎么读：每行显示「标题 / 类型 / 生成时间 / 内容摘要 / 状态」。点一行会弹出完整正文。
  • 如果列表是空的：说明还没生成过（空态原文「暂无经营日报，点击「生成日报」创建」）。点一下「生成日报」即可补一份。
日报不是"报表"，是"信"

把它当成一位值夜班的同事给你留的交接条：他昨天做了什么、遇到什么、今天打算做什么。你不必核对每个数字，但要认真读风险提示那一段——那通常就是今天你该处理的第一屏。

三、经营驾驶舱怎么读

进入项目 › 自动运营 › 经营驾驶舱

驾驶舱是你作为 CEO 的"主仪表盘"。页面标题「经营驾驶舱」，顶部四个按钮：「返回控制台」「刷新」「运行预警评估」。下面是六张指标卡，再下面是预警列表。

六张指标卡，逐个说清楚

六张卡分别是「总收入 / 总成本 / 净收入 / 任务完成率 / 预算消耗率 / 活跃预警」。我们逐个讲它是什么、怎么算的（用大白话）、什么算健康、异常时先做什么。

指标人话解释怎么算出来的异常时先做什么
总收入 项目账本里记的"收入"类流水合计 项目账本里所有 type=收入 的流水求和 如果一直是 0：去项目账本确认是不是没记收入；起步期还没收入是正常的
总成本 AI 花的钱 + 第三方服务费 + 采购成本 token 计费 + 第三方服务支出 + 采购成本 成本突然涨：去「计费明细」查哪一天、哪个角色涨的
净收入 总收入 − 总成本 两者相减，负数会标红 长期为负且收窄不了：考虑收缩任务或调整方向（不是"撑住"）

"健康值"没有统一标准，跟自己的基线比

你可能想让我告诉你"完成率要高于多少才正常"。说实话，没有权威阈值——不同项目、不同阶段的合理区间完全不同。正确做法是：把今天和上周的自己比、和上个月的自己比。完成率从 40% 涨到 60% 是好消息；从 80% 掉到 50% 才是要查的信号。绝对数字不如趋势可靠。

预警列表：预警不是报错，是"该看一眼"

驾驶舱下方是「预警列表」，列有「指标 / 级别 / 消息 / 详情 / 状态 / 时间 / 操作」。两点关键：

  • 级别：warn 显示为「警告」（黄色），critical 显示为「严重」（红色）。
  • 状态：active 显示「活跃」，resolved 显示「已解决」。活跃的行右侧有「解决」按钮，点一下标记为已解决。列表为空时的空态是「暂无预警」。

点顶部「运行预警评估」，系统会当场把所有预警规则跑一遍，弹出一张「本次评估结果」表，列「指标 / 级别 / 是否触发 / 消息 / 详情」。评估完还会提示"共 N 条规则，M 条触发"。这不是重新算账，是主动体检一次。

展开：系统到底会评估哪些预警规则？（进阶）

预警规则覆盖六个方向，界面上以「指标」列的中文名呈现，背后对应的判定方向是：

  • 预算消耗率（budget_rate）：预算用得比预期快。
  • 任务积压（task_backlog）：待执行任务堆得太多，AI 忙不过来。
  • Token 异常（token_anomaly）：某一天花费突然激增（例如单日超出近 7 日均值的数倍）。
  • 角色 SLA（role_sla）：某个岗位的响应/处理变慢。
  • 收入下滑（revenue_drop）：收入指标走低。
  • 漏斗卡住（funnel_stuck）：获客环节卡住不动。

同一项目、同一指标、同一级别，24 小时内不会重复堆叠活跃预警（会自动去重），所以你看到的条数就是"真正待办的事"。你不用背这些英文，界面显示的是中文；这里列出来只是让你知道"系统到底在替我盯什么"。

预警会"复现"，不代表你点错了

你点了「解决」，把一条预警标记为已解决，过几天它可能又出现——这很正常。因为预警是按当前指标快照评估的：只要指标还没回到正常，它就会再次触发。所以"解决预警"的正确含义不是"把警告关掉"，而是"我已经处理了它指向的那件事"。如果你只是点掉按钮却没动根因，它必然还会回来。

别忘了看一眼「统计周期」

指标卡下面还有一张「统计周期」小卡，显示「周期 / 开始日期 / 结束日期」。这张卡很容易被忽略，但它决定了上面六个数字算的是哪一段时间。默认周期是「每日」（daily），也就是统计"今天/最近一天"的情况。如果你把今天的收入和昨天比，发现大涨大跌，先回去看统计周期是不是同一个——不同周期的数字不能直接对比。

这也是一个常见的"假警报"来源：你早上打开驾驶舱看到总收入很低，以为出问题了，其实只是因为今天才刚开始，当日统计自然低。判断收入类指标，强烈建议用"按周 / 按月"的视角去看趋势，而不是盯着当日数字。

展开：为什么预警"看得到却处理不完"？（理解预警的生命周期）

一条预警在系统里的生命周期大致是：被评估触发 → 进入"活跃" → 你处理并标记"已解决" → 如果根因还在，下次评估再次触发。理解了这条链路，你就明白两件事：

  • "活跃"条数不会自动下降：它不会像待办事项那样被你划掉就消失。只有指标回正常，新的评估才不再触发它。
  • 重复触发是"提醒"不是"故障"：它反复出现，恰恰说明那个问题还没解决。这时候的正确反应是"我上次是不是只点了按钮没做事？"

所以一个健康的驾驶舱，不是"预警永远为 0"，而是"预警出现后很快被处理、且不再复现"。复现率比数量更能说明你的经营质量。

展开：驾驶舱的数字为什么有时"看着不对"？（几个正常现象）

刚上手时，你可能会觉得几个数字"怪怪的"。以下都属正常，不是 bug：

  • 总收入是 0：如果你还没在项目账本里记过任何收入流水，它自然是 0。起步期没收入很正常，别慌。
  • 成本不为 0 但收入为 0：AI 一直在干活就要花钱，这很正常。但长期只出不进要警惕。
  • 净收入为负且标红：界面会在净收入小于 0 时标红，这是提醒，不是错误。
  • 任务完成率忽高忽低：新增了很多任务时，分母变大，完成率会先掉下来——这是"任务变多了"，不一定是"效率变差了"。

遇到"数字反常"，先问三个问题：统计周期对不对？是不是新加了任务/预算？是不是我漏记了账？多数"异常"都出在这三处。

别忘了目标：指标是"仪表"，目标是"目的地"

前面讲的都是"仪表读数"，但仪表本身不告诉你该往哪开。项目里另有一块「目标管理」，用一棵目标树把方向钉住：愿景 → 目标 → 关键结果（KR）→ 任务。你可以在那里「新建目标」，为每个目标配几个 KR（关键结果），再把任务挂到 KR 下面。

这套结构和指标的关系是：指标告诉你"现在怎么样"，目标告诉你"要去哪里"。只看指标不看目标，你会陷入"数据很健康，但方向跑偏了"的陷阱——比如任务完成率很高、成本控制很好，可你压根没在做最该做的那件事。

展开：目标里的"权衡权重"是什么？

每个目标（以及它的 KR）可以配一组权衡权重，四个维度：成本（cost）/ 质量（quality）/ 风险（risk）/ 速度（speed）。它们会归一化成加起来等于 1 的比例。

这有什么用？举个直观的例子：同样一个"上线独立站"的目标，如果你把权重调成"速度优先"，系统在给方案排序时就更愿意接受"先上线、后完善"；如果你调成"质量优先"，它就倾向于多做测试与验收。换句话说，权衡权重是你把"经营偏好"翻译给 AI 的方式，省得每次都要在任务描述里重复强调。

当 KR 的加权达成率低于设定阈值时，系统会触发 review（重排）或找你确认。你不用手算达成率，界面会显示，你只要在"该不该调整"的时刻做出判断即可。

起步期：目标不用多，一个就够

组织四阶段里，起步期的核心是"跑通最小闭环"。这时候你其实只需要一个目标（比如"第 30 天前拿到第一个付费用户"）和 2–3 个 KR。目标定得太多，等于没有目标。等进入成长期、有了分工，再把目标树铺开。

  • 客户响应时间 P95（秒）：P95 是统计学说法——把响应时间从小到大排队，第 95 个百分位的那个值。说人话：95% 的客户咨询都能在这个秒数内得到响应，剩下 5% 是较慢的。它比"平均值"更能反映极端情况，因为平均值会被快的拉低，掩盖"少数客户等很久"。
  • 人类参与率（%）：人工节点介入的比例。这个指标特别值得讲，见下面专门一段。
  • 知识库增长量：近 30 天新增的知识条目数。它是"飞轮转不转"的直接证据——只要 AI 在干活，就该持续有东西沉淀进知识库。
别找"标准阈值"，找"自己的基线"

这四个指标没有、也不该有统一的健康阈值。项目类型不同、阶段不同，合理值差别极大。正确用法是：先记录你现在是多少，然后看它是在变好还是变坏。质量评分从 6.5 涨到 7.5 是好信号；响应时间 P95 从 30 秒劣化到 90 秒才是要查的信号。系统给你的不是"及格线"，是一面镜子。

为什么"人类参与率"最值得盯

这一个指标，能同时告诉你两件相反的事：

✅ 它太高时

说明 AI 不被信任、什么都要人来拍板。这时候要么是自主级别设得太保守（默认是 L2），要么是 AI 表现确实差、频繁触发人工节点。先看人工节点的"原因"分布，再考虑适当放宽低风险节点的自主级别。

❌ 它太低时

也别急着高兴。太低可能意味着关键的风险节点没被拦住——比如本该人工审核的对外动作，被 AI 自主执行了。适度的"人类参与"不是效率的敌人，而是安全的保险。

一句话：人类参与率是个"双向指标"，太高说明不信任，太低说明风险失控。你要的不是把它压到最低，而是找到一个"信任与安全"的平衡点。

展开：怎么"建立自己的基线"？三步就够

"与自身基线对比"这句话说起来容易，怎么做？给你一个可执行的三步法：

  1. 记下来：每周复盘时，把这四个数抄到你的复盘表（附录 C）里。一行字，十秒钟的事。
  2. 看方向：对比上周、上上周，是变好还是变坏？单点的数值没有意义，方向才有。
  3. 定个"处理线"：给自己定一条行动线（是你自己定的，不是系统规定的）。比如"质量评分连续两周下滑，我就去优化提示词"。有了处理线，你就不会陷入"看数字看到麻木"。

关键在于：基线是你自己的历史，不是行业标准。别人的项目跟你的项目不一样，别人的"好"对你可能是"差"。跟昨天的自己比，你永远不会被误导。

展开：P95 到底该怎么理解？（一个不用背公式的解释）

你可能会想："P95 听着很专业，我用得上吗？"用得上，但不用背公式。

把一周里所有客户咨询的响应时间，从小到大排成一队。P95 就是站在第 95% 位置的那个人的等待时间。也就是说，95% 的客户在这个时间内得到了响应，剩下 5% 更慢。

为什么不直接用平均？因为平均会被极端值拉偏，也会被大量快响应"稀释"。举个例子：100 个客户里 95 个 5 秒响应、5 个等了 10 分钟，平均值看着还行，但那 5 个客户体验极差。P95 专门用来暴露这些"少数但严重"的慢响应——这正是经营者最该关心的部分。

你只需要记住一句：P95 变大了，说明有一批客户开始等太久了，该查了。

兜底计费与未计量：口径常显，还给出口径入口

「累计花费」卡片上可能有小标签，它们旁边的说明文字——不是悬停才出现的 tooltip，而是直接常显的小字（触屏上也能看到）——非常重要，直接决定你怎么理解这些数字：

① 关于"含估算"标签

「含估算：按文本长度估算的兜底计费（上游未回 usage 时产生），非精确账单，请勿直接用于核销。」

② 关于"未计量"标签

「未计量：这些轮次已实际执行，但没有可用的计量数据（无法读取 usage），仅 0 元留痕，不计入花费。」

出现这两种情况时，卡片区下方还会常显一行精确口径入口：「精确金额以上游回传 usage 的计量记录为准（非估算）：逐轮花费见 运行轮次，任务级归因见 阿米巴核算；项目总账（与 AI 运行预算不是同一条账）见 项目账本。」三个词都是可点的链接，直接跳过去核对，不用自己猜路径。

用大白话解读：第一句是说，有时候上游没把用量数据回传，系统只能按文本长度"估"一个花费，所以这个数字不是精确账单，别拿它去财务核销。第二句是说，有些轮次确实跑了，但拿不到用量数据，于是记 0 元——"我跑了但没收你钱"，这不代表免费，只是没算出来。两句话的共同提醒是：计费明细是"管理账"，不是"发票"。

  1. 按任务看：哪个任务最贵？（阿米巴核算的"任务级核算"表能直接看到每个任务的 Token 成本）

十一、两条账本的关系（最容易混，再说一遍）

整个系统里有两条完全不同的账，很多人第一次看到会以为是重复的。请务必分清：

对比项平台账本（公司账本）项目账本
副标题（原文）「平台账户真实资金流水：充值、AI 算力费、云服务器费等」「项目虚拟核算：收入、支出与预算消耗」
记的是什么真金白银：你充值的钱、平台扣你的钱项目的虚拟核算：收入、支出、预算

一句话口诀

平台账本管"平台是不是还在给你供货"，项目账本管"这个项目自己赚不赚钱"。平台余额不足 = 断供风险（充值解决）；项目预算不足 = 熔断暂停（加预算或砍任务解决）。两者独立，不要把一个的告警当成另一个来处理。

补充一点：项目账本的预算阈值也可以调。在「项目账本 → 项目预算」里能设「预算总额」「预警阈值(%)」「告急阈值(%)」，默认预警 80%、告急 95%。告急时页面上方会出现红色提示「项目预算已用 x%，处于告急状态。」

平台账本里的"AI 算力费"是从哪来的

你在「计费明细」看到的 token 花费，会由项目侧按批上报到平台真实账本，作为一条「AI 算力费」入账——平台账本里那行「AI 算力费」并非另一笔钱，而是同一笔 token 消耗的平台视角。上报有三个关键点：平台按每批的 report_id 幂等去重，同一批不会重复扣费；只有上报成功才记账，失败会退避重试、不丢单；上报水位会落库（token_billing_records.platform_reported_at），进程重启也不会把历史重扫一遍。

但要有心理准备：如果平台的上报地址没配置，这条链路就不启用——此时平台账本不含 AI 算力费。平台账本页对这一点的原文说明是：「AI 算力费由项目侧 token 计费批量上报（未开启该上报时不含此项，可在项目账本查看 AI 运行消耗）」。所以看平台账本时，先确认这个上报有没有开。

十二、每月一次的经营复盘怎么做

前面都是"看"，这里给你一个每月固定动作——30 分钟，五步，最后只做一件事。开着下面这张清单，照着走即可：

  1. 看驾驶舱（5 分钟）：六张卡过一遍，重点看「净收入」「预算消耗率」「活跃预警」。记下本周最异常的一个数。
  2. 看日报（5 分钟）：把本月最后一篇分析报告读一遍，尤其是"优化建议"。
  3. 看阿米巴（5 分钟）：按岗位扫一遍，找出"花得多、产出少"的一个岗位。
  4. 看计费（5 分钟）：看按天分布，找出花费最高的一天，回想那天发生了什么。
  5. 决定一件事（10 分钟）：从上面四条线索里，挑出下个月只做的一件事，写进复盘表（附录 C）。只做一件，是因为同时改五件事你哪件都做不好。
复盘的目的不是"记账"，是"做减法"

一个月下来你会有很多想改的。但经营的本质是做减法：下个月只做最重要的一件事。比如"砍掉最贵的那个低效岗位""把某个任务的验收标准写清楚""给项目预算加 200 元"。一次改一件，下个月复盘时验证它有没有用——这比一口气上十个改进要有效得多。

十三、本章小结与下一步

  • 数字分四种：钱 / 活 / 果 / 险。钱和险是快变量（每天看），活和果是慢变量（每周看）。
  • 每日三屏：待处理节点 · 预算消耗率 · 昨日日报。五分钟，按顺序看。
  • 经营驾驶舱看六个数，预警不是报错是"该看一眼"；「解决」的正确含义是"根因已处理"，不是"关掉警告"。
  • 经营日报有四种类型（日报 / 分析 / 内审 / 红队），注意「草稿」状态等你确认；建议不会自己生效。
  • 指标要分阶段看：起步期盯完成率与花费，成长期盯获客，规模化盯单位经济学，成熟期盯事业部 ROI。别越级看指标。
  • 善用「智能看板」提问、会读「阿米巴核算」、认真看「结项报告」的知识沉淀——这是让经验变成复利的方式。
  • 看到异常，按本章的"信号 → 动作"表处置，不临场发挥；每月做一次 30 分钟复盘，只定一件事。

到这里，你已经具备了"当 CEO 看经营"的完整视角。但一个项目往往不只你一个人——可能有同事、有外部顾问、有 AI 员工。下一步，我们要讲清楚团队、权限与治理：谁能花钱、谁能发邮件、谁需要审批、出了事怎么追责。这些规则如果一开始没理清，后面会变成一团乱麻。

附录 E · 每周经营检查清单（一页纸，可打印）

把这一页打印出来贴在显示器旁。每周固定花 15 分钟，从上往下走一遍，每项打个勾。它是本章所有内容的"压缩执行版"。

每日（5 分钟）

  • 清空「人工处理节点」的待处理项，或明确升级
  • 扫一眼「预算消耗率」和「AI 预算消耗」，是否 < 80%
  • 读一遍最新「经营日报」，记下里面的风险提示

每周（15 分钟）

  • 看「经营驾驶舱」六个数，记下本周最异常的一个
  • 读本周的「分析报告」，逐条过优化建议

  • 看「计费明细」按天分布，找花费最高的一天，回想发生了什么
  • 看「监控指标」四个数，跟自己的基线比方向
  • 确认「公司账本」平台余额仍高于预警阈值

每月（30 分钟）

  • 填一份月度复盘表（附录 C），写下"本月最异常的一个数字"
  • 看「结项报告」（若有）或「目标管理」的达成情况
  • 看一次「内审报告」与「红队演练」结论

  • 定下"下月只做的一件事"，并写清用什么指标验证
清单的意义在于"不用想"

经营最怕的是"凭感觉、看心情"。有了这张清单，你每周的状态是稳定的：该看的都看了，该记的都记了，该做的一件事也定了。哪怕你这周很忙，只做了"每日"那三项，你的项目也不会失控——因为最重要的红线和钱，你已经盯住了。
