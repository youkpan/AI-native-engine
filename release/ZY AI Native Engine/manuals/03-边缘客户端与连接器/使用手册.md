## 一、边缘客户端（本地电脑软件）

### 1.1 功能概述

边缘客户端是运行在用户本机（Windows / macOS）的常驻后台程序，负责：监听本地目录 → 发现文档 → **本地解析清洗** → 上传（原文件 + 清洗文本双通道）到项目服务器，并接收服务器下发的指令执行、回传结果。

V2 已落地链路：`扫描 → 解析 → 清洗 → 双通道上传 → 服务端知识库入库`（本机已完成解析清洗；服务端文本通道经 `/edge/upload` 的 `meta.clean_text` 直入知识库，已落地）。

### 1.2 初始化与配置

1. 生成配置模板：
   ```bash
   edge-client.exe -init
   ```
   生成 `configs/config.toml`。
2. 设置激活码（如有）：
   ```bash
   edge-client.exe -activate <激活码>
   ```
3. 查看版本：
   ```bash
   edge-client.exe -version
   ```
4. 启动：直接运行 `edge-client.exe`（首次启动自动生成 ClientID 并建 SQLite 库；`edge.enable_systray=false` 时降级为后台守护进程）。

**关键配置项**：

| 配置段 | 项 | 说明 |
|:---|:---|:---|
| `server` | `base_url` | 项目服务器 WSS 地址（如 `wss://<服务器>/ws/edge`） |
| `server` | `token` | Bearer Token（激活后由服务器颁发） |
| `scan` | `watch_dirs` | 监听目录列表（`file_process` 白名单） |
| `scan` | `file_types` | 允许的扩展名（默认 `.pdf .docx .xlsx .txt .md .csv`） |
| `scan` | `doc_sources` | 目录别名 → 文档来源映射（如 `{ "work" = "D:/docs/work" }`），上传 meta 携带 |
| `scan` | `max_clean_text_len` | 单文档清洗文本最大字符数（默认 200_000） |
| `scan` | `max_file_size_mb` | 最大文件大小（默认 50 MB，超大文件仅上传清洗文本） |
| `upload` | `max_retries` | 上传重试次数（4xx 不重试） |
| `llm` | `local_base_url` | （可选）本地 LLM OpenAI 兼容端点，配置后 `ai_chat` 本地执行 |
| `llm` | `local_model` / `timeout` | 本地 LLM 模型名 / 超时（默认 60s） |

### 1.3 文档扫描与双通道上传

- 将 `.docx / .pdf / .xlsx / .txt / .md / .csv`（按 `scan.file_types`）文件放入 `scan.watch_dirs` 目录。
- 客户端自动监听（fsnotify，2s 去抖）→ **本地解析** → **清洗** → 登记本地知识库 → 定时上传：

  | 类型 | 解析方式 |
  |:---|:---|
  | docx | Word 段落 + 表格文本（标准库 zip+xml） |
  | xlsx | 单元格扁平化（共享字符串 / 内联串 / 数值） |
  | pdf | 文本提取（纯 Go，失败降级为可打印字符过滤） |
  | txt / md / csv | 直接读取，UTF-8 优先、GBK 回退（Windows 常见） |

- **双通道上传**：multipart 同时携带原始文件 + `meta` JSON（`title / source_type / clean_text / kb_scope / kb_id / doc_source`），服务端有 clean_text 直接走知识库文本入库，否则走原文件解析管线。
- **本地知识库**：`local_kb_meta` 表记录文档元数据与清洗文本缓存（截断 50_000 字符），上传成功回填 `ServerDocID / ChunkCount`。
- **解析失败降级**：解析异常不阻断上传（仍上传原文件，`clean_text` 留空），本地记录错误并重试。
- **去重与续传**：同 hash 文件全局去重不重复上传；上传状态机 `detected → uploading → uploaded / failed`，断网后自动续传；`ServerDocID` 幂等（同 hash 已入库则跳过）。

### 1.4 指令执行（白名单安全）

服务器可下发以下指令，客户端执行后回传结果：

| 指令 | 说明 | 状态 |
|:---|:---|:---|
| `scan_and_upload` | 扫描指定目录并上传 | 已实现 |
| `file_process` | 本地文件处理（仅允许 `watch_dirs` 内路径） | 已实现：`extract_text`（提取清洗文本）/ `convert`（转 Markdown）/ `analyze`（大小/字数/来源统计） |
| `ai_chat` | AI 对话 | 已实现：配置 `llm.local_base_url` 则本地问答；否则回传 `{forwarded:true}` 由服务器接管 |
| `status_report` | 本机状态上报 | 已实现 |
| `rpa` | RPA 脚本执行 | 预留（返回 `not_supported`，接口已占位） |

**执行留痕**：指令经 `edge_commands` 状态机（`queued → running → success / failed / timeout`）执行，结果结构化回传服务器；`CommandID` 复用 `task_id`，终态指令幂等（重复下发返回缓存结果，不重复执行）。

**安全约束**：`file_process` 指向 `watch_dirs` 白名单之外的路径会被拒绝并返回 `permission denied`；本地不执行任意 shell 参数（防命令注入）。

### 1.5 心跳与断线重连

- 客户端通过 WSS 长连接与服务器通信，心跳默认 30s。
- 断线后按指数退避自动重连（1s → 2s → … → 60s 封顶）。
- 断线期间指令由服务器端 `edge_task_commands` 排队（待接线，见 P14-11）；本地侧断网时未上传文件自动续传。

### 1.6 系统托盘

- 常驻系统托盘（`edge.enable_systray=true`），显示连接状态，菜单含「日志 / 退出」两项，均为英文文案（Open Logs / Quit）。托盘状态文案随连接变化：Status: Disconnected / Connected / Connecting... / Reconnecting...。
- **「Open Logs」已接线**：点击直接打开本机日志目录；**「Reconnect」菜单项已移除**——连接层本身已有指数退避自动重连（见 1.5），无需手动重连。托盘图标当前是占位图标。
- `enable_systray=false` 时以守护进程模式运行（无 UI）。

## 二、连接器模块（项目服务器）

### 2.1 功能概述

连接器是平台与外部工具（飞书 / Telegram / 邮件等）的桥梁，遵循 MCP 规范，供 AI Agent 通过 ToolCall 统一调用。

### 2.2 注册连接器

```
POST /api/v1/connectors
{
  "name": "飞书",
  "type": "communication",
  "provider": "feishu",
  "permission": "write_review",
  "config": { "app_id": "...", "app_secret": "...", "verification_token": "...", "encrypt_key": "..." }
}
```

- 敏感字段（`token/key/secret/password/api_key/app_secret` 等）自动 AES-256-GCM 加密，库中为 `enc::` 密文，API 响应不含明文。
- 支持的 provider：`feishu` / `telegram` / `email`（slack / discord / dingtalk / twitter 实例构建待接线，验签函数已就绪）。
- **编辑**：更新的是**同一条连接器**（复用原 `connector_id` 升版本），不再每次生成新 ID，避免列表出现「同名重复连接器」；指定 ID 不存在时返回 **404**，不会静默新建。
- **配置不回显**：`config` 加密存储且永不下发给前端，编辑时必须**重新填写完整配置 JSON**（提交前有二次确认与醒目提示）。
- **重置为默认**：有二次确认。
- ⚠️ 已存在的**重复连接器记录未自动清理**，如需整治建议按 `name + provider` 保留最大版本、其余软删。

### 2.3 启停与执行

| 操作 | 端点 |
|:---|:---|
| 列表 / 详情 | `GET /api/v1/connectors`、`GET /api/v1/connectors/:id` |
| 启停 | `PUT /api/v1/connectors/:id/status` |
| 执行工具 | `POST /api/v1/connectors/execute` |

- **读工具**（`direction=read`）直接执行，审计记录 `status=executed`。
- **写工具**（`direction=write`）按 `permission` 分流：`write_review`（默认）返回 `{status:"pending_review", audit_id}`，需人工审核后执行；`write_auto`（高危，需显式授权）直接执行。
- 权限治理 6 步校验链路（实例状态 / 工具白名单 / Agent 授权 / 数据范围 / 限流 / 成本）已落地为纯函数（接线待 P16）。

### 2.4 人工审核

```
POST /api/v1/connectors/audit/:audit_id/approve   { "reviewer_id": "...", "note": "..." }
POST /api/v1/connectors/audit/:audit_id/reject     { "reviewer_id": "...", "reason": "..." }
GET  /api/v1/connectors/audit?connector_id=&status=&limit=
```

写操作挂审后，人工批准才会真正对外发送；拒绝则不执行。全量调用留痕 `connector_audit_logs`。

### 2.5 Webhook 入站

- **入站契约（已固化为契约测试）**：`/api/v1/webhooks`（复数，订阅组）允许透传到项目服务器；`/api/v1/webhook`**及其子路径**必须拦截，不得转发。
- 各平台验签算法已实现：飞书 `verification_token` 校验 + AES 解密、Telegram `secret_token` 头、Slack HMAC-SHA256、Discord Ed25519、钉钉 timestamp+sign。
- 验签函数已就绪，路由接线与实例构建（slack / discord / dingtalk）待 P16。

## 三、常见问题（FAQ）

1. **文件放入 watch_dirs 后没上传？** 检查 `scan.enabled=true`、文件扩展名在 `scan.file_types` 内、文件大小不超过 `scan.max_file_size_mb`、`server.token` 有效。
2. **file_process 被拒绝？** 目标路径必须位于 `scan.watch_dirs` 白名单内，否则按安全策略拒绝（`permission denied`）。
3. **ai_chat 只回 `forwarded:true`？** 属正常：未配置 `llm.local_base_url` 时由服务器 AI 链路接管；如需本机执行，配置 `llm.local_base_url` 后重启。
4. **上传后 `ServerDocID` 为空？** 服务端回执需包含 `doc_id`（文本通道经 `/edge/upload` 的 `meta.clean_text` 直入，回执同样带 `doc_id`）；仅当服务端未接入知识管线或未携带 `kb_id` 时，文档只落 `stored` 态、`chunk_count` 为 0，本地 `local_kb_meta.uploaded` 仍会置为已上传。
5. **写连接器操作一直 pending？** 属正常「人在回路」机制，需在审计列表 approve 后才实际执行。
6. **密钥泄露如何应急？** 吊销能力（`POST /:id/revoke`）与成本上限、权限漂移内审待接线；当前请先在飞书/邮件侧吊销对应凭据并重建连接器。

## 四、安全提示

- `server.token` 明文存本地 `configs/config.toml`，请确保文件权限 0600 且不入库、不提交到 git。
- 生产环境连接器加密密钥须通过环境变量 `PS_CONNECTOR_ENCRYPT_KEY`（32 字节 base64）显式配置，禁止依赖自动生成文件。
- 传输全程 TLS/HTTPS/WSS，`InsecureSkipVerify` 生产必须为 `false`。
- 本地 `file_process` 仅允许 `watch_dirs` 白名单内路径，服务器指令无法越权读取用户任意目录。
