# 使用手册 — auto-ops 调度与轮次（分卷 04）

> 面向项目负责人 / 运维 / 实施。本手册覆盖已落地能力；「待接线」能力以说明形式标注，不做操作引导。

## 一、功能概述

auto-ops 是项目在「全自动化 / 半自动化」运行模式下的调度与运营机制。它按「时间片 + 轮次制」把项目的多个任务轮流推进，定期让 AI 做 review 重排、free 等待，任务完成后独立验收，全程复用既有任务/角色/预算/人在回路体系。

核心特征：

- **单实例单项目隔离**：每个启用 auto-ops 的项目启动独立 goroutine 循环，互不阻塞。
- **默认全自动**：`run_mode=full_auto/semi_auto` 才启用；`manual_review` 不启用。
- **防死循环防烧钱**：全完成强制 review → review 仍全完成强制 free；连续失败降级→升级→退出；预算熔断；单轮超时强杀。

## 二、运行模式与开关

### 2.1 三种运行模式

| 模式 | 值 | 说明 |
|:---|:---|:---|
| 全自动化 | `full_auto` | 少量人工接入或授权，AI 自主推进 |
| 半自动化 | `semi_auto` | 关键节点人工审核 |
| 人工审核 | `manual_review` | 手动执行，不启用 auto-ops |

> 注意：auto-ops 侧运行模式字段是 `run_mode`（人工审核的规范值为 `manual_review`）；平台侧项目另有 `project.mode` 字段（`full_auto` / `semi_auto` / `manual`）。**这是两个字段**，平台侧枚举尚未并入 `manual_review`，两边合并尚未做。

### 2.2 自主执行级别（L0-L3）

| 级别 | 行为 |
|:---|:---|
| L0 | 全自主执行，不创建人工节点、不通知 |
| L1 | 通知不等待 |
| L2（默认） | 一键确认：AI 暂停等待，任务面板一键确认后继续 |
| L3 | 强制人工审核 |

### 2.3 生命周期 API

```
POST /api/v1/projects/:id/autoops/start     # 启动
POST /api/v1/projects/:id/autoops/stop      # 停止
POST /api/v1/projects/:id/autoops/pause     # 暂停（当前轮完成后暂停）
POST /api/v1/projects/:id/autoops/resume    # 恢复
GET  /api/v1/projects/:id/autoops/config    # 读配置
PUT  /api/v1/projects/:id/autoops/config    # 改配置
```

- `start`：为 `status=running && auto_ops_enabled=true` 的项目启动独立循环。
- `pause`：发暂停信号，当前轮执行完成后进入等待（不杀正在执行的子进程，避免丢上下文）。
- `resume`：从下一轮继续，保留 schedule 与 task_summary。

## 三、任务管理

### 3.1 手动添加任务

```
POST /api/v1/projects/:id/autoops/tasks
{
  "name": "营销内容制作",
  "desc": "生成 3 篇 B2B 邮件营销文案",
  "done_when": "3 篇文案 + 发送计划通过自检",
  "priority": "P1",            // P0-P3
  "time_slice_weight": 3,      // 1-10
  "engine_type": "loop",       // loop / agent
  "time_limit": 7200           // 秒，默认 7200
}
```

- 引擎类型：`loop`（qianshou 子进程，复杂/编码/长时任务，默认）；`agent`（进程内 LLM+ToolCall，信息整合/接口调用/快速任务），界面上显示为「**Agent 智能体（Agent 引擎）**」。
- 引擎优先级：**任务级 > 角色级 > 项目默认**。
- 未指定引擎时，系统按描述关键词启发式预测（编码/开发/构建/长时→loop；查询/汇总/快速→agent；兜底 loop）。

### 3.2 任务列表 / 更新 / 删除

```
GET  /api/v1/projects/:id/autoops/tasks
PUT  /api/v1/projects/:id/autoops/tasks/:tid    # 更新 priority/time_limit/engine_type/prompt_override 等
DELETE /api/v1/projects/:id/autoops/tasks/:tid  # 删除（仅「规划中」任务；写 change_logs 留痕）
```

- **删除限制**：只允许删除「规划中（planning）」任务，并校验任务归属当前项目；非规划中任务返回 **400** 并说明原因（列表操作列带二次确认）。
- 列表状态筛选包含「**规划中**」。
- 编辑弹窗中**时间片权重、角色 ID、描述为只读**（创建后不可修改）；描述旁提示「一次写清什么算做完，创建后不可修改」。
- 编辑时「时限」**留空 = 保持原值**（不再被静默重置）。
- 补充信息的可行路径是**编辑任务描述 / 任务级提示词**（界面没有独立的「注入」按钮）。

### 3.3 提示词继承

任务提示词按「任务级 > 角色级 > 项目级」继承，优先级高的覆盖低的。

## 四、时间片调度与轮次

- 调度默认 **10 个时间片**，任务按 `time_slice_weight` 占用多个时间片。
- 每轮推进一个时间片，任务轮流获得处理时间。
- **接力机制**：每轮结束后保存 `task_summary`（本轮目标/动作/未完成点/下一步），下轮注入 `{{LAST_TASK_INFO}}` 继续。
- **完成闭环**：输出末尾出现 `[Task finished]` → 独立验收（pass 标记完成 / redo 重做 / reject 升级人工）；任务成功后连续失败计数复位。
- **抽样验收（现状未变）**：低风险 P3 任务按比例抽样验收；本批「抽样跳过」目前仅在日志中可区分，无独立落库标记。

## 五、review 轮与 free 等待

- **触发**：距上次 review ≥ `review_every_rounds`（默认 20 轮）；或全部任务完成强制触发；或手动触发 `POST /api/v1/projects/:id/autoops/review`（运行轮次页 / 控制台已有「触发 review」按钮）。
- **行为**：AI 审视全局（git log、进度、预算、收益），产出 `<schedule>` XML 重排任务集与时间片，校验后替换生效。
- **删除未完成任务会逐条告警**：review XML 要求删除未完成任务时逐条提示（不再静默丢弃）。
- **free 等待**：任务集为空或全完成时进入 free 模式，只做常规检查，按固定间隔再 review，防止空转烧钱。

## 六、失败兜底（降级→升级→退出）

任务或 review 连续失败时：

1. 第 1-2 次：**降级重试**（换引擎 → 换角色版本 → 缩小任务范围）。
2. 第 3 次：**升级**（管理者 Agent 复盘 + 创建人工处理节点通知负责人）。
3. 超过上限（默认 3 次）：**告警退出**（通知 + 暂停项目循环，防烧钱）。

review 连续失败同理：`ReviewFailCount ≥ 3` → 告警 + 暂停，需人工介入。

## 七、预算熔断

- AI 运行预算 `ai_budget` 挂项目配置，消耗累计到项目账本。
- 达到预警线 `warn_line_pct`（默认 80%）：预算预警（同轮幂等）。
- 超限：自动暂停 + 通知「预算耗尽，请补充预算后继续」；补充预算后 `resume` 恢复。
- **单轮预算上限 `single_round_max_budget`（默认 100 元）已真正生效**：轮末结算超限即告警并暂停项目，补上了**金额维度**的熔断（时间维度另有单轮超时强杀）。

## 八、中断恢复与续接

任务因人工节点超时、预算熔断、实例重启、Stop 等中断后，可恢复：

```
POST /api/v1/projects/:id/autoops/tasks/:tid/resume
GET  /api/v1/projects/:id/autoops/resume-assessments
```

- **豁免期**（默认 2 天）内：不做 AI 评估，直接 clean 续接。
- 超过豁免期：环境漂移检查（git_diff / deps / api_creds / db_schema / kb）→ 时长分级（<7 天 short、7-30 mid、>30 long/ultra）→ 评估结论（resume / resume_with_adjust / replan）。
- 评估结论与人工决策写入 `resume_assessments` 留痕。

## 九、常见问题（FAQ）

1. **项目一直没跑起来？** 检查 `auto_ops_enabled=true`、`status=running`、`run_mode` 为 `full_auto/semi_auto`（`manual_review` 不启用 auto-ops）。
2. **任务一直不完成？** 输出末尾需出现 `[Task finished]` 标记才会触发验收；未完成时摘要保留「未完成点 + 下一步」保证下轮可续。
3. **review 轮连续失败后项目停了？** 属防烧钱兜底，`ReviewFailCount` 达上限自动暂停，需人工介入后 `resume`。
4. **任务被卡在 pending？** 写操作 / 关键节点按人在回路机制需人工审核（audit approve / 任务面板确认）。
5. **中断后如何恢复？** 直接调 `POST .../tasks/:tid/resume`，豁免期内秒续，长期中断会先做环境漂移评估再续。

## 十、安全提示

- 工作目录严格限定为项目根目录，对外部目录只读。
- 所有 LLM 调用统一经 `llm.Router` 发出，调用 Agent 时使用 opus 模型，token 计入项目 AI 运行预算。
- 连续失败兜底与预算熔断是防烧钱关键路径，请勿在生产环境关闭相关阈值配置。
