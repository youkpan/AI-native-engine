# 使用手册 — 数据架构与 API（分卷 07）

> 面向开发者 / 后端工程师。本手册覆盖 V2 数据层与 auto-ops API 的落地规范、扩展方式与测试方法。

## 一、数据模型总览

项目服务器（project-server）数据库为 PostgreSQL，采用「单实例单项目」物理隔离，全部业务表通过 `project_id` 逻辑挂载，不建物理外键（与既有代码一致）。V2 相关表共 23 张：

| 类别 | 数量 | 表 |
|:---|:---|:---|
| V2 auto-ops 核心 | 18 | auto_ops_tasks / auto_ops_schedules / auto_ops_rounds / auto_ops_progress / auto_ops_meta / task_log_bindings / token_billing_records / role_versions / role_experiences / human_task_nodes / ai_reports / objectives / permission_leases / audit_reports / risk_registry / org_documents / change_logs / resume_assessments |
| P13 经营核算 | 4 | amoeba_daily_stats / amoeba_internal_prices / crm_pipelines / cockpit_alerts |
| P14 连接器治理 | 1 | connector_versions |
| 既有表扩展 | 1 | project_config（V2/V2.2/V2.2.1 追加 13 字段） |

模型定义位置：`project-server/internal/model/auto_ops.go`（18 表 + 枚举常量）、`amoeba.go` / `crm.go` / `cockpit.go`（P13）、`connector_version.go`（P14）、`project_config.go`（扩展）。

**本批增量字段 / 状态**（均由项目启动时的 AutoMigrate **自动补加**，无需手写迁移脚本）：

- `token_billing_records.platform_reported_at`：平台上报水位，进程重启不会重扫历史。
- 知识库文档新增状态 `needs_review`（待人工确认）：解析走降级路径的产物不再直接标「就绪」，原因写入 `error_message`；前端状态映射已补齐（未知值显示「未知状态（原值）」）。

## 二、新增表的正确姿势

1. 在 `project-server/internal/model/` 定义 GORM 模型 + `TableName()` 方法。
2. 在 `project-server/internal/migrate.go` 的 `AutoMigrate(db)` 的 `db.AutoMigrate(...)` 列表**末尾追加** `&model.Xxx{}`。
3. 建库验证：`cd project-server && go run ./cmd/migratecheck/`（本地 PostgreSQL 17，postgres/postgres），输出 `PASS` 即成功；AutoMigrate 幂等，旧库增量加列不丢数据。

**模型编码约定**（对齐 TAD 07 0.2）：

- 主键 `ID uint gorm:"primaryKey"`；业务唯一 ID 字符串 + `uniqueIndex;size:64;not null`。
- 项目隔离 `ProjectID string gorm:"index:idx_xxx;size:64;not null"`。
- JSONB 用 `string` 类型 + `gorm:"type:jsonb;default:'{}'|'[]'"`，并在 `BeforeCreate` hook 兜底非空；本卷 28 处 JSONB 字段已全部标注。
- 追加写表（不可变留痕）**不设 `DeletedAt`**：token_billing_records / audit_reports / risk_registry / change_logs / resume_assessments，代码层只 insert，纠错走追加纠错记录。
- 其余业务表用 `gorm.DeletedAt` 软删。
- 含缩写 `ID` 的字段若需映射到非默认列名，显式写 `gorm:"column:xxx"`（如 `RACIDefault` → `column:raci_default`，避免被 GORM 拆成 `rac_idefault`）。

## 三、auto-ops API 端点

基路径 `/api/v1/projects/:id/autoops`，全部挂在 HMAC `platform` 组（`middleware.HMACAuth`），路径 `:id` 必须与 HMAC 认证的 `project_id` 一致。当前共 **71 个端点**：

| 分类 | 端点 |
|:---|:---|
| 生命周期 | POST /start /stop /pause /resume |
| 配置 | GET/PUT /config |
| 任务 | POST/GET /tasks、PUT /tasks/:tid、**DELETE /tasks/:tid**（仅「规划中」任务，非规划中返回 400）、POST /tasks/:tid/resume |
| 运行 | GET /rounds、POST /review、POST /analyze、GET /report |
| 日志 | GET /logs、GET /logs/:round_id |
| 计费 | GET /billing |
| 人工节点 | GET/POST /human-tasks、POST /human-tasks/:hid/complete|notify|escalate |
| 角色 | GET/POST /roles、GET/PUT /roles/:rid/config、GET /roles/:rid/versions、POST /roles/:rid/optimize|select-version |
| 目标 | GET/POST /objectives |
| 审计 | POST /audit、POST /audit/redteam、GET /audit/reports、GET /risk-registry |
| 日报/治理 | GET /daily-report、POST /killswitch、GET /org-documents、GET /change-log、GET /resume-assessments |

响应封装统一 `{code:0, message:"ok", data:{...}}`（`pkg/response`）。

组织能力端点（`/api/v1/projects/:id/org`，本批只读化）：`GET /capabilities` 为**只读预览（不落库）**；生成并落库能力建议改走 `POST /capabilities`。

## 五、常见坑与排查

- **GORM 缩写拆分**：字段名含 `ID`（如 `RACIDefault`）默认会被拆为 `rac_idefault`，需显式 `column` 标签。
- **JSONB 序列化**：模型层 JSONB 用 `string` + `type:jsonb`；若某处 Go 结构体字段为 `map`/`[]string`，需另加 `gorm:"serializer:json"`（`internal/autoops/types.go` 已处理）。
- **追加写表**：不得加 `DeletedAt`；如需改历史数据，追加纠错记录而非 update/delete。
- **Windows 构建缓存竞态**：`go run ./cmd/migratecheck/` 偶发 `undefined: xxx` 误报，复跑或 `go vet` 即可排除（非真实缺陷）。
